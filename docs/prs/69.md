# Issue 69: Add D4 symmetry property tests

## RED

Issue: #69 — Add D4 symmetry property tests.

Tests added in `tests/symmetry.rs`:

- `transform_extremes`: every transform fixes the empty and full boards and
  preserves the number of set bits.
- `identity_orders`: identity on both sides; `Rot90` and `Rot270` have order
  4; `Rot180`, `FlipH`, `FlipV`, `FlipDiag`, and `FlipAnti` have order 2.
- `compositions`: ten hand-checked pairwise compositions, including
  `FlipDiag then Rot90 = FlipH`, `Rot90 then FlipDiag = FlipV`, and
  `FlipH then FlipAnti = Rot90`.
- `inverses`: every `Sym::ALL` member composed with its inverse on either
  side is the identity.
- `legal_moves_commute`: `transform(legal_moves(me, opp))` equals
  `legal_moves(transform(me), transform(opp))` for all eight transforms, on
  the start position and two hand-built positions. The start fixture also
  asserts four opening moves.
- `transform_orientation` remains as the single-square orientation check.

Expected failure: none. The `Sym` transforms landed in #64; this issue adds
property coverage only, so the tests are expected to pass against the current
`tests/common/mod.rs` implementation.

## Intended behaviour

- The eight transforms form D4: identity order 1, quarter turns order 4, half
  turn order 2, and reflections order 2.
- Composition and inverses match the board geometry, independently of the
  transform's implementation.
- Move generation is equivariant under D4, so transforming a legal-move set
  equals generating moves from the transformed board.
- Only `Sym::ALL` is used to enumerate transforms.
