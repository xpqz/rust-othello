## Step 1 RED: class order without sorting

A pure speed change has no behaviour to add, so no test fails today.
The tests below pin what must not move and pass on the current engine
by design. What is expected to change is the measurement.

Intended change: in `ordered_moves`, when there is no evaluation and
the depth is under 2 (midgame nodes with one ply left, exact nodes
under 5 empties), take the moves straight from the bitboard in four
classes, preferred move, corners, other squares, X/C squares, each in
square order, instead of building a key per move and sorting. The
order is the one the keys give today. Other calls are untouched.

Tests:

- `tests/ordering.rs::class_order` (new). 1,000 playout positions with
  a legal move (every third position visited, fixed seed); for every
  legal preferred move and for none, at depth 0 and at depth 1,
  `ordered_moves(…, None)` must equal an independent sort by
  (class, square). The class masks are written out again in the test.
- Unchanged and binding: the five `ordering_*` tests in
  `tests/search.rs` (two of them call depth 1 with fixed expected
  orders), `evaluation_order`, `evaluation_ties`,
  `evaluation_boundary`, `golden_v2` including its node column,
  `corpus_depths`, `golden_v1`, `window_equivalence`.
- Node identity: `search_bench` must report the same totals after the
  change, 8,614,615 midgame and 7,000,900 exact. `golden_v2` pins the
  tableless depth-8 counts per position.

Results now: `cargo test --test ordering`: 4 passed. Engine fmt and
clippy clean. Nothing else changed since `c8d067c`, where
`./scripts/check.sh` passed.

In GREEN I will show that `class_order` fails when the classes are
taken in a wrong order.

## Step 2 RED: flat pattern offsets

Intended change: `pattern::features` ends by adding each instance's
table offset. It reads the offsets from `instances()`, 46 `Instance`
structs that each own a `Vec`. Replace that read with a flat
`[u32; INSTANCE_COUNT]` built once from the same instances. Output
identical for every board; `instances()` and `Instance` stay as they
are for the trainer and tests.

No new test: the function's whole contract is already pinned, and a
pure speed change adds no behaviour. Binding, passing today by design:

- `tests/pattern.rs::features_wide`: `features` against the
  one-square-at-a-time reference (`reference_features`) on the 23
  corpus boards, the empty and one-colour boards and 100,000 random
  boards; `features_reference` likewise on its fixed boards.
- `golden_v2` with per-position node counts, `corpus_depths`,
  `golden_v1`: any wrong index changes evaluations and so scores.
- Node identity on the benchmark: 8,614,615 and 7,000,900.
