# Issue 114: Tune ProbCut t at equal nodes on the tune set

## Pre-registration (before any match is played)

This is an experiment issue with no engine change and no tests. The RED
checkpoint is this pre-registration review.

- Sweep: `t_centi ∈ {100, 140, 180, 220}`.
- Opponent: `pc:off` (full-width standard engine, depth 64).
- Node budget: **1,965,089 nodes/move**, the measured mean over the first 20
  `bench/openings_tune.txt` positions using the full-width standard engine
  with `SearchLimits::new(64, 1000, 0)` in release on this machine.
- Position set: `bench/openings_tune.txt`, 200 pairs per t, colours swapped.
- Seed: 114 for every match.
- Jobs: 5.
- Journals: `docs/tuning/probcut_tune_<t>.journal`; stdout/stderr:
  `docs/tuning/probcut_tune_<t>.log`.
- Selection: best pair-bootstrap mean point estimate; ties go to the larger,
  more conservative `t`.
- No sweep value, opponent, node budget, pair count, seed or selection rule
  may be added or changed after results are seen.
- `bench/openings_validation.txt` and `openings_final.txt` stay untouched.

Commands (one per t, resumable by re-running identically):

```sh
cargo run --release --manifest-path tools/Cargo.toml -- match \
  --a pc:<t> --b pc:off --openings bench/openings_tune.txt \
  --pairs 200 --seed 114 --nodes 1965089 --jobs 5 \
  --max-load 5 --out docs/tuning/probcut_tune_<t>.journal
```

Approval is required before the sweep starts. Expected compute is several
hours on the performance cores; equal-node results do not depend on load.
