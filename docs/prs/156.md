# Issue 156: Opening book gate at equal game time

Run work, with no test stage. `docs/design/book.md` § Gate runs after
#151, which is now merged. Play uses the 51 s game clock with policy
variant 3 (#163, #167). This file is the pre-registration. No gate game
has been played.

## Pre-registration (binding)

- **Agents:**
  - candidate `pc:80:c51000v3+book`: today's play configuration with the
    book on (`book: true`);
  - baseline `pc:80:c51000v3`: the same configuration with the book off.

  The same engine, clock and policy on both sides, so this is equal
  total game time: each side has 51,000 ms per game. Book moves go
  through `book::play` and are charged like any `choose` call, so the
  book's time saving stays on the candidate's clock.
- **Starts:** the 400 frozen roots in `bench/openings_book.txt` (SHA-256
  `a819bac0…f53f`, as recorded in #158), one pair per root, colours
  swapped, in file order.
- **Pinned binary:**
  - worktree `../othello-book-gate` at `6e532ef` (main after #167);
  - `othello-tools` SHA-256 `0c280682…03a5`, `clock_time` SHA-256
    `5d67aee4…5f68`;
  - built with `cd tools && cargo build --release --bin othello-tools
    --example clock_time` in the worktree's Space2 target.
  - A `--pairs 0` check wrote a header with both agent names, control
    `clock`, `max_load 6.000` and engine `6e532ef`.
- **Command,** one look, through `docs/tuning/book_gate.sh` (pins
  checked before every launch, fixture overrides cleared, `--check`
  passes now):

  ```sh
  othello-tools match --a pc:80:c51000v3+book --b pc:80:c51000v3 \
    --openings bench/openings_book.txt --pairs 400 --seed 156 \
    --jobs 4 --max-load 6 --out docs/tuning/book_gate.journal
  ```

- **Load and void:** load is sampled once per pair and rounded to three
  decimals. A pair above 6.000 is void and replayed, flagged or not. Ten
  void passes stop the run, and the same command resumes it. Void events
  are counted from the log, as observed log events.
- **Timeouts:** return-and-forfeit (#162). A side whose charged time
  exceeds 51,000 ms loses the game and its last move is not played.
  Flags are reported by agent and colour.
- **Checkpoint:** `clock_time docs/tuning/book_gate.journal --a
  pc:80:c51000v3+book --b pc:80:c51000v3 --pairs 400 --seed 156` must
  accept the journal (all pairs complete, none void). The header must
  match: seed 156, control `clock`, `max_load 6.000`, the
  `openings_book.txt` path and hash, and engine `6e532ef`.
- **Rule** (the design's):
  - **enable** the book (`book: true` in `standard()`, a separate commit
    after the results review) only if the informative pair-bootstrap
    lower bound of the candidate's score (10,000 resamples, seed 156) is
    strictly above 0.500;
  - **otherwise** the book stays off. The degeneracy fallback cannot
    enable it.
  - No time condition gates the book. Both sides have the same clock, and
    saving time is part of what the book offers.
- **Reported, not gated:**
  - clock time saved: both mean charged times per game, and the paired
    difference with its interval (`clock_time --seed 156`);
  - flags;
  - void events.
- **Deferred diagnostic:** the design's "book moves per game for each
  side". `Agent::choose` returns only a square, so the journal cannot
  tell a book move from a search move. As with depth-by-stage in #160,
  this is not reported. The time saving is reported instead.
- **Time:** about 800 games × 2 × ≤ 51 s ÷ 4 jobs, roughly 5–6 h on a
  quiet machine.
