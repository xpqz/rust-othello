# Issue 156: Opening book gate at equal game time

Run work, with no test stage. `docs/design/book.md` § Gate runs after
#151, which is now merged. Play uses the 51 s game clock with policy
variant 3 (#163, #167). This file is the pre-registration. No gate game
has been played.

## Pre-registration (binding)

- **Agents:**
  - candidate `pc:80:c51000v3+book`: today's play configuration with the
    book on (`book: true`);
  - baseline `pc:80:c51000v3`: the same configuration with the book off.

  The same engine, clock and policy on both sides, so this is equal
  total game time: each side has 51,000 ms per game. Book moves go
  through `book::play` and are charged like any `choose` call, so the
  book's time saving stays on the candidate's clock.
- **Starts:** the 400 frozen roots in `bench/openings_book.txt` (SHA-256
  `a819bac0…f53f`, as recorded in #158), one pair per root, colours
  swapped, in file order.
- **Pinned binary:**
  - worktree `../othello-book-gate` at `6e532ef` (main after #167);
  - `othello-tools` SHA-256 `0c280682…03a5`, `clock_time` SHA-256
    `5d67aee4…5f68`;
  - built with `cd tools && cargo build --release --bin othello-tools
    --example clock_time` in the worktree's Space2 target.
  - A `--pairs 0` check wrote a header with both agent names, control
    `clock`, `max_load 6.000` and engine `6e532ef`.
- **Command,** one look, through `docs/tuning/book_gate.sh` (pins
  checked before every launch, fixture overrides cleared, `--check`
  passes now):

  ```sh
  othello-tools match --a pc:80:c51000v3+book --b pc:80:c51000v3 \
    --openings bench/openings_book.txt --pairs 400 --seed 156 \
    --jobs 4 --max-load 6 --out docs/tuning/book_gate.journal
  ```

- **Load and void:** load is sampled once per pair and rounded to three
  decimals. A pair above 6.000 is void and replayed, flagged or not. Ten
  void passes stop the run, and the same command resumes it. Void events
  are counted from the log, as observed log events.
- **Timeouts:** return-and-forfeit (#162). A side whose charged time
  exceeds 51,000 ms loses the game and its last move is not played.
  Flags are reported by agent and colour.
- **Checkpoint:** `clock_time docs/tuning/book_gate.journal --a
  pc:80:c51000v3+book --b pc:80:c51000v3 --pairs 400 --seed 156` must
  accept the journal (all pairs complete, none void). The header must
  match: seed 156, control `clock`, `max_load 6.000`, the
  `openings_book.txt` path and hash, and engine `6e532ef`.
- **Rule** (the design's):
  - **enable** the book (`book: true` in `standard()`, a separate commit
    after the results review) only if the informative pair-bootstrap
    lower bound of the candidate's score (10,000 resamples, seed 156) is
    strictly above 0.500;
  - **otherwise** the book stays off. The degeneracy fallback cannot
    enable it.
  - No time condition gates the book. Both sides have the same clock, and
    saving time is part of what the book offers.
- **Reported, not gated:**
  - clock time saved: both mean charged times per game, and the paired
    difference with its interval (`clock_time --seed 156`);
  - flags;
  - void events.
- **Deferred diagnostic:** the design's "book moves per game for each
  side". `Agent::choose` returns only a square, so the journal cannot
  tell a book move from a search move. As with depth-by-stage in #160,
  this is not reported. The time saving is reported instead.
- **Time:** about 800 games × 2 × ≤ 51 s ÷ 4 jobs, roughly 5–6 h on a
  quiet machine.

## Stopped (Nov 21): the load rule cannot work on a daily-use machine

- **Started** at 02:40:40 UTC, as registered. At 07:29 UTC, after
  4.8 h, it had 21 of 400 accepted pairs and 397 void events.
- **Load** sat at about 6.7 against the limit of 6. `appstoreagent` was
  stuck at about 95% CPU, and `launchd`, Firefox and other user
  processes added to it. Stopping `appstoreagent` at 07:23 (the user
  agreed) did not bring the load under 6 quickly enough to matter.
- **User:** "I believe your approach will never complete. Think again.
  Something this load sensitive cannot work on a machine which is a
  daily driver."
- **User decisions:**
  - measurements (gates and tuning) move to a deterministic **node
    clock**, independent of load, under a design amendment;
  - this gate is stopped.
- **The partial journal is never scored.** It is kept as a record in
  `docs/tuning/book_gate_stopped.{journal,log}`, and its score was not
  looked at. The book gate is re-registered under the node clock and
  played from scratch.

## Re-registration: a node-limited "not worse" check (user decision, Nov 21)

The user questioned the cost of a full gate for an expected result ("It
seems like a lot of work for something that seems pretty obviously
true"). Offered a cheap node check, a plain enable, or the full node-clock
gate, they chose **"Cheap node check"**. The node-clock design (#168) is
closed unbuilt, and the budget raises approved for it are not made.

This replaces the clock gate above, which was stopped and is never scored.

- **What it tests:** whether the book's moves are not worse, at a fixed
  search effort. Each move gets the same node budget, so a book move's
  saved effort is not passed on. The book's time saving is therefore
  deliberately not credited, and the check is conservative. Node-limited
  games are deterministic and independent of load: no load rule applies,
  so the run works on a machine in daily use and resumes bit for bit.
- **Agents:**
  - candidate `pc:80+book`, the standard engine with the book on;
  - baseline `pc:80`, the same with the book off.

  Both have `--nodes 10000000` per move. That size was chosen from a
  4-pair timing probe at 4,000,000 nodes per move (24.9 s for 8 games on
  4 jobs, about 20 M nodes/s), so it is roughly a 0.5 s search and the run
  takes about 1.7 h.
- **Starts:** the 400 frozen roots in `bench/openings_book.txt`
  (`a819bac0…f53f`), one pair each, colours swapped.
- **Binary:** the pinned `../othello-book-gate` at `6e532ef`,
  `othello-tools` `0c280682…03a5`, unchanged.
- **Command,** one look:

  ```sh
  env -u OTHELLO_TOOLS_ELAPSED_MS -u OTHELLO_TOOLS_LOAD \
  othello-tools match --a pc:80+book --b pc:80 \
    --openings bench/openings_book.txt --pairs 400 --seed 1561 \
    --nodes 10000000 --jobs 4 --out docs/tuning/book_nodes.journal
  ```

  The seed differs from the stopped clock run's 156, so no game repeats
  its seeds.
- **Rule** (strict comparisons; the degeneracy fallback cannot pass):
  - **Enable** the book (`book: true` in `standard()`, a separate commit
    after the results review) if the informative pair-bootstrap lower
    bound of the candidate's score (10,000 resamples, seed 1561) is above
    **0.475**: not worse.
  - **Report it as better** at this effort if the lower bound is also
    above 0.500.
  - **Otherwise** the book stays off.
  - The result applies to the 400 frozen book roots, and to equal node
    effort per move.
- **Checkpoint:**
  - the report must cover all 400 pairs;
  - the header must show seed 1561, control `nodes`, nodes 10000000, the
    `openings_book.txt` path and hash, and engine `6e532ef`;
  - a resume must leave the accepted records unchanged.

## Node check result (Nov 21)

- **Run:** started at 07:38:44 UTC after the pins were checked (worktree
  `6e532ef` clean, `othello-tools` `0c280682…03a5`, `openings_book.txt`
  `a819bac0…f53f`). It ended at 09:26:46 UTC with exit 0, in one run
  with no interruption. The machine was in use: the launch line logged a one-minute load of
  2.08, and the accepted pairs' samples span 3.700–7.430 (corrected
  after the review; an earlier draft said 6.4). Under node control load
  does not void pairs, and the log has no void events.
- **Checkpoint:**
  - the journal holds 800 records, 400 complete pairs;
  - the header shows agents `pc:80+book` and `pc:80`, 400 pairs, seed
    1561, nodes 10000000, control `nodes`, openings
    `bench/openings_book.txt` (file hash `22d8057c046379b5`) and engine
    `6e532ef`;
  - files: `docs/tuning/book_nodes.{journal,log,summary}`.
- **Score** (`othello-tools report`, 10,000 resamples, seed 1561): W 348,
  D 69, L 383 for the book side. Mean **0.4781**, interval **[0.4575,
  0.4988]** by bootstrap (informative), Elo [−29.60, −0.87].
- **Outcome, by the registered rule:**
  - the lower bound 0.4575 is not above 0.475, so the not-worse
    condition fails. **The book stays off** (`standard()` keeps
    `book: false`);
  - the whole interval lies below 0.500. At the same 10,000,000-node
    cap per move from these 400 frozen roots, the book side scored
    measurably worse than the same engine without it.
- **Scope** (per the review): this is the same per-move node cap, not
  equal realized node use. It says nothing about the book's effect under
  the 51 s game clock, where book moves would also save time, and it
  applies to these 400 roots.
- **Not investigated yet:** why the book loses. Plausible causes, none
  tested:
  - drop-out values biased upward by taking the maximum of noisy
    searches, as noted in #154;
  - depth-19 scoring choices that lead to positions this engine plays
    worse at this effort;
  - a defect not covered by the lookup tests.

  Any follow-up is a separate issue.
