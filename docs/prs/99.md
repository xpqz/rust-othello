# Issue 99: Incremental tuning against the preceding accepted config

## Predeclared protocol (before the 200-pair runs)

- Fixed node budget: 2000 nodes/move. Same openings, seeds, search settings.
- Comparator: frozen Phase 2 evaluator (`phase2`, depth 4 baseline config).
- Candidate: the #96 phase-weighted evaluator.
- Position set: `bench/openings_tune.txt`; 200 pairs, seed 42, colours
  swapped within each pair. Validation uses `openings_validation.txt` only
  after selection.
- Five candidates, declared now: base, no-mobility, no-frontier,
  no-corner-risk, no-disc.
- A candidate is retained only if it beats phase2 with a pair-bootstrap 95%
  interval whose lower bound is above 0.50. An ablation is evidence against a
  feature if the ablated variant has a higher mean than base; otherwise the
  feature remains. Validation must confirm the final base against phase2 with
  the same rule.
- The 10-pair, 2000-node run already used to time the harness is a pilot and
  is excluded from selection.
- Ablations are run by temporarily zeroing one weight vector (or the disc
  weight) and rebuilding tools; the final tree keeps the accepted #96
  configuration. No source variant is committed.

## Commands

```sh
cargo run --release --manifest-path tools/Cargo.toml -- match \
  --a ab:4 --b phase2 --openings bench/openings_tune.txt \
  --pairs 200 --nodes 2000 --seed 42
```

The same command is repeated with one feature zeroed for each ablation, then
with `--openings bench/openings_validation.txt` for the final base.

## Revised direct-ablation protocol (predeclared after review, before these runs)

The earlier indirect phase2 comparisons are superseded for feature decisions.

- Candidate variants: no-mobility, no-frontier, no-corner-risk, no-disc.
- Each plays the #96 base **directly**, 400 pairs / 800 games, seed 43,
  2000 nodes/move, max depth 64, no time limit, ordering on, same tune
  openings in alternating colours.
- Drop a feature if the variant's 95% interval lower bound is above 0.50;
  keep it if the variant's upper bound is below 0.50; otherwise the result is
  inconclusive and the default is the smaller evaluator (drop the feature).
- If both frontier and disc are dropped individually, a combined variant must
  clear the same rule against base before final validation.
- Validation runs only after this decision.
- The reproducible tool is `tools/examples/tune.rs`; full variant-vs-base logs
  are committed under `docs/tuning/`.

## Direct-ablation decision

The revised protocol was applied exactly. Direct variant-vs-base runs on
`openings_tune.txt` (400 pairs, seed 43, 2000 nodes) gave:

| Variant | Mean | 95% interval | Decision |
| --- | ---: | --- | --- |
| no mobility | 0.2669 | [0.2369, 0.2975] | keep (upper < 0.50) |
| no frontier | 0.4206 | [0.3906, 0.4506] | keep (upper < 0.50) |
| no corner risk | 0.4019 | [0.3700, 0.4344] | keep (upper < 0.50) |
| no disc | 0.7731 | [0.7450, 0.8013] | **drop** (lower > 0.50) |

The earlier indirect phase2 ablation table is superseded for these decisions.

Removed the disc term and `disc_weight` from `src/eval.rs`; the finalized
evaluator is positional + mobility + frontier + dynamic corner risk with the
phase blend. Tests, hand-computed values, and the corpus were regenerated for
the reduced evaluator. The old overflow tests were tied to the removed
disc-diff term, so they were removed; bounded-playout and antisymmetry/D4
coverage remain.

Validation (untouched set, 400 pairs, seed 43, 2000 nodes):
**0.8675** [0.8444, 0.8894], Elo [293.78, 362.09] versus phase2. Log:
`docs/tuning/99_tuned_validation.log`; direct logs:
`docs/tuning/99_no-{mobility,frontier,risk,disc}_vs_base.log`.

Budget after the cut: engine 992/999, `eval.rs` 81/86, tools 632/650.

## Round 2 response

- `tools/examples/tune.rs` now asserts at startup, over 1,000 seeded playout
  positions, that `NO_DISC` equals the shipped `othello::eval::evaluate`.
  `BASE` is that copy plus the reviewed #96 disc term.
- Log headers now show the repo-relative opening path by default.
- With the disc term gone, `EVAL_BOUND` and the debug assert/clamp are a safety
  net rather than a reachable boundary; that is why the overflow tests were
  removed, while bounded-playout coverage remains.
