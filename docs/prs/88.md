# Issue 88: Integrate TT into negamax

## RED

Issue: #88 — Integrate the transposition table into negamax.

Tests added in `tests/search.rs`:

- `tt_equivalence`: at depth 3, `search_tt` with a fresh table returns the
  same score as `search_limited` on the start, a pass-adjacent midgame board,
  and a corner-heavy fixture; the returned move is legal.
- `tt_deep_then_shallow`: after a depth-4 search warms a table, a depth-3
  search scores the same as a cold depth-3 search.

Expected failure:

```text
error[E0432]: unresolved import `othello::search::search_tt`
```

The failure is intended.

## Intended behaviour

- `search_tt(board, limits, config, &mut Table)` mirrors `search_limited` but
  carries the table through `Ctx`. `search_limited` keeps the no-table path.
- `negamax` probes after resolving terminal/pass and the depth cutoff. It uses
  the stored move as the ordering hint and consumes only equal-depth heuristic
  cutoffs; deeper entries order only.
- After a completed node, store `{key, value, depth, bound, Heuristic, mv}`
  with `Upper`/`Lower`/`Exact` from the original window. Aborted nodes return
  before storing.
- The root retains its previous-best ordering; interior nodes use the TT move.
- Callers size the table at `64 << 20 / size_of::<Entry>()`, clear it between
  games, and never share it across evaluator configurations.

## Review responses

- Added `tt_warm_nodes`: a second depth-4 search with the same warm table must
  match the score and use fewer than half the nodes, proving probe, store,
  equal-depth cutoff, and ordering are live.
- Added `tt_sample_equivalence`: 30 sparsely sampled playout positions at
  depth 4, each checked cold vs TT for score equality, then deep-5 then warm-4
  with the same table.
- The root is intentionally not stored: root ordering uses the previous
  iteration's best directly, while interior nodes probe/store.
- `negamax` will keep `alpha_orig` and classify with
  `best <= alpha_orig -> Upper`, `best >= beta -> Lower`, else `Exact`.
