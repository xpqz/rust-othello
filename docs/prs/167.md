# Issue 167: Play with the game clock (51 s per game, policy variant 3)

The "If enabled" step of `docs/design/time.md` § Gate, after #163 passed
as not worse within the registered margin (0.5062 [0.4906, 0.5225]
against flat 3 s per move, margin 0.475), with a measured time saving of
about 21% (40.5 s against 51.3 s per game).

## RED

### Scaffolding

- `src/agents.rs` gains:
  - `PLAY_CLOCK_MS = 51_000` and `PLAY_POLICY = 3`;
  - a stub `play_agent()`, which still builds the flat 3 s
    `search_agent`;
  - a stub `GameClock { limit_ms, used }`, where `new` works, but
    `remaining_ms` returns 0 and `charge` and `refund` do nothing.
- **GUI** (`gui/src/main.rs`):
  - an `engine_clock: GameClock` field, started at `PLAY_CLOCK_MS`;
  - `engine_moved(square, spent)`, which charges the clock (a no-op in
    the stub) and plays the move. `step` now calls it;
  - `engine_limits()`, which still returns the flat per-move limits from
    the think-time slider. `start_engine` uses it.

  GUI behaviour is unchanged in RED.

**Expected failures:** 4 (2 engine, 2 GUI). Everything else passes, and
clippy is clean on all four crates.

**Limitation:** the CLI binary's use of `play_agent` is not timed in a
test, because real-time replies under early stopping are not
deterministic. `play_agent_policy` pins the agent the CLI will build,
and GREEN makes `play_game` call `play_agent()` and charge a
`GameClock`.

### GREEN plan

- **`GameClock`:** saturating `Duration` arithmetic; `remaining_ms` is
  `limit − used` rounded down.
- **`play_agent`:** `clock_agent(standard(), SearchLimits::new(64, 3000,
  0), ClockPolicy::variant(PLAY_POLICY))`.
- **CLI `play_game`:** keeps a `GameClock` for the engine. Before each
  engine move it calls `clock(remaining_ms)`, then charges the move's
  elapsed time.
- **GUI:**
  - the think-time slider becomes an engine game clock, in seconds per
    game (default 51), which takes effect at the next new game;
  - `engine_limits` uses `allot_with` under variant 3 from the remaining
    time, and a lone legal move is played without search;
  - each history entry records the engine time spent on its move, so
    undo refunds exactly the moves it takes back;
  - `new_game` resets the clock.

## RED review response

### Definitions (my calls)

- **What the play clock charges:** the worker's own search time, from
  just before `book::play` to its return, measured inside the worker and
  sent with the result. The time from launch to the UI noticing the
  result is not charged, so slow polling never spends the engine's
  budget. The CLI charges its `choose` call, timed the same way.
- **Overrun in interactive play:** no forfeit; that is the match
  harness's rule. When the clock is spent, the engine is told 0 ms and
  keeps playing on the allocator's 1 ms minimum, and the clock stays at
  0. The CLI pins this in `play_turn_overrun`.

### CLI: the actual turn path

- **New `othello::cli::engine_turn(agent, clock, board, elapsed)`.**
  - `play_game` already calls it, with a `GameClock` and real time.
    It is a stub for now: it calls `choose`, with no clock update and no
    charge.
  - The tests drive it with scripted durations:

  | Test | Checks |
  |---|---|
  | `play_turn_clock` | a recording agent receives 51,000 before its first move and 48,500 before the next, after a 2.5 s charge; the clock ends at 46,000 |
  | `play_turn_pass` | a board where the engine must pass: no call, no clock update, no charge |
  | `play_turn_overrun` | an overspent clock: the agent is told 0, still plays a legal move, and the clock stays at 0 |
  | `play_turn_forced` | a lone midgame move, with a variant-3 `clock_agent` and a panicking evaluator: the turn returns the move without searching, and the 7 ms call is charged |

- The subprocess `play_opponent_is_search` stays as a legal-reply smoke
  test.

### GUI: through the result handler

- **New `engine_result(found, spent)`,** which `step` now calls.
  `engine_moved` charges `spent`, and `start_engine` will take the
  lone-move shortcut.

  | Test | Checks |
  |---|---|
  | `engine_clock_default` | a fresh clock and fresh variant-3 limits |
  | `engine_clock_next` | after a 2.5 s engine result, the next allocation is `allot_with(board, 48,500, …)`, so the allocator cannot always see 51,000 |
  | `engine_clock_undo` | after charged results of 2.5 s and 4 s (6.5 s in all), undo refunds only the last exchange, leaving 48,500 rather than 51,000 or 44,500; a new game resets to 51,000 |
  | `engine_lone_move` | engine to move with one legal move: `start_engine` plays it with no worker (`thinking` stays `None`) and no charge |

### Results

- 4 CLI failures (`play_turn_*`), 2 engine failures
  (`play_agent_policy`, `game_clock_charges`) and 4 GUI failures, all
  from the stubs. Everything else passes, and clippy is clean.
- Engine at 1,475 of 1,500 with the stubs.
