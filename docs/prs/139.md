## Step 1 RED: no reply count in midgame ordering below depth 4

Intended change: in `negamax`, a midgame node below the
evaluation-order depth (remaining depth 1 to 3) asks `ordered_moves`
for the class order: table move, corners, other squares, X/C squares,
each by square. Today depths 2 and 3 also play every move and count
the opponent's replies. Depth 4 and above (evaluation order), exact
search (reply count from 5 empties up) and the root are unchanged.
`ordered_moves` itself does not change; `negamax` passes it depth 0
for these nodes.

Why: the reply count at depths 2 and 3 is 46% of all `runs` calls on
the benchmark. Dropping it searches more nodes (+13.6% on the
benchmark) in less time (about 1.17 there, 1.19 to 1.22 on 64 held-out
positions at depths 9, 10 and 11). Scratch figures, in SKIS #139; not
gate results.

Tests:

- `tests/ordering.rs::midgame_class_order` (new). `search` on one
  fixed 40-empties corpus position with the standard configuration at
  depths 3, 4 and 5 must return move, score and node count
  (26, 583, 462), (20, −309, 2,987), (21, 352, 8,113). The moves and
  scores are today's (and `DEPTH_SCORES`' for that board); the node
  counts are what the scratch copy with the change gives. **Fails
  today**: the engine uses 381, 2,008 and 5,832 nodes. This is the
  wiring test: a count that only the class order at depths 2 and 3
  produces. It is tableless and uses the direct root, so nothing but
  the order decides it.
- Unchanged and binding: `corpus_depths`, `golden_v1`,
  `window_equivalence`, `window_bounds`, `tt_*`, `evaluation_boundary`,
  `class_order`, `class_edges`, and the `ordering_*` tests of
  `ordered_moves` (including `ordering_replies`, which pins the reply
  count that the root and exact search still use).
- Expected in GREEN: `golden_v2`'s node column changes for the
  midgame rows and is re-recorded, moves and scores shown unchanged.
  `fewer_nodes` and `fewer_table_nodes` are reduction guards against
  fixed baselines and this step raises node counts; scratch says they
  still pass, and I will report their totals. If one fails I bring it
  to review; no baseline moves.

Expected failure now: `midgame_class_order` only
("left: (26, 583, 381)"). `cargo test --test ordering`: 5 passed,
1 failed. Engine fmt and clippy clean.

Before: measured alongside the after-runs, alternating binaries,
