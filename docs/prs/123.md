# Issue 123: Label rule and labelling job, with pilot

## RED

Tests first; no `othello_trainer::label` module is present.

New `trainer/tests/label.rs` covers:

- `label_bands`: all three bands in one game. A 30-empty position uses the
  WTHOR theoretical score; a 20-empty position uses the first anchor at 14
  empties; the anchor and a 10-empty position use their own exact values.
  It also checks which boards the solver is asked to solve.
- `pass_sign`: the same board before and after a forced pass (side to move
  flips, pieces do not). The anchor value is converted through black's point
  of view, and the two labels are opposite.
- `final_result`: a game with no position at 14 or fewer empties uses its
  final result, with no solver calls.
- `disc_units`: solver centidiscs 4200 and -1300 become +42 and -13 discs.
- `journal_resume`: four copies of the known 59-move, four-pass game are
  labelled by the `label` command with `--jobs 1`. A second run is SIGKILLed
  after its first journal line, then resumed with the same command; the
  sorted journal records must equal an uninterrupted run.

Expected failure:

```text
error[E0432]: unresolved import `othello_trainer::label`
 --> tests/label.rs:8:5
```

### Intended design

`src/label.rs`:

- `Labelled { board: Board, black: bool, label: i32 }`.
- `labels(p3, game, replay, solve) -> Result<Vec<Labelled>, String>`, with
  `solve: &mut dyn FnMut(Board) -> Result<i32, String>` returning centidiscs.
- The anchor is the first replay position with 14 or fewer empties. If there
  is none, band 2 uses the final result.
- Bands: `empties >= p3` uses `2 * theoretical - 64`; `15..p3-1` uses the
  anchor value; `<= 14` solves the position. Every value is converted to the
  player to move; centidiscs divide by 100.
- `Replay.positions` already carries black-to-move and excludes terminal and
  pass-required positions, so a forced pass is just the colour flip in the
  position stream.

The `label` command:

- `label [dir] [journal] [--jobs N] [--games N]`, defaulting to
  `data/wthor`, `data/labels.journal`, one job and all games.
- One unit is one game. It uses `othello_tools::journal::Journal`, keyed by
  `file:index`, and skips keys already present. Positions at 14 or fewer
  empties use `search::solve` with the full window and no node limit.
- `--games` limits the pilot to 1,000 games. The full run is not started in
  this issue.

### Pilot and evidence

The pilot will run 1,000 games with the real solver and write
`docs/tuning/pattern_label_pilot.log` with commit, date, elapsed time, games
and positions solved. The projected full-run wall clock will be computed from
that measured rate and replace the design's estimate in the notes.

Trainer production is 250/450 before this issue. The labelling rule, command
and journal wiring should stay well inside the remaining budget; the exact
count is GREEN evidence.

## RED review round 1 responses

Verdict was **request changes**; all seven points are addressed.

1. `pass_sign` is renamed `colour_flip`, which is what it tests: an anchor
   value converted to the other colour. `pass_chain` is added. It replays the
   known 59-move game with `wthor::replay`, labels it with the real solver,
   and takes exact values from black's side for positions with at most 10
   empties. The value must not fall after a black move and must not rise
   after a white move, and the last value is +48. The four passes fall
   between replay positions 54→55, 55→56, 56→57 and 57→58 (empties 6→5,
   5→4, 4→3, 3→2), all inside the ≤10 range.
2. `label_bands` now has a white-to-move position at 30 empties and expects
   -10.
3. `label_bands` now includes exactly 24, 23, 15 and 14 empties: theoretical,
   anchor, anchor and own value. It also sets the 23-empty position to white
   to keep both colours in the anchor band.
4. The journal payload is defined as the labels in replay position order,
   space-separated. `label::encode` and `label::decode` are the shared
   conversion. `journal_roundtrip` reads the line written by the `label`
   command, decodes it, and compares it with `label::labels` using the real
   solver.
5. The journal header records the engine commit, the sorted input file names
   and their hashes, the P3 values and the 14-empty solve threshold. `--jobs`
   and `--games` are not in the header, so a resume with different `--jobs`
   is allowed. `journal_resume` changes an input byte and asserts the same
   command is refused with a header error.
6. Rejected games are skipped without a journal line. `journal_resume` uses
   an archive with two valid games and one illegal game and expects exactly
   two lines.
7. `journal_resume` kills a `--jobs 1` leg and resumes with `--jobs 2`.
   `games_limit` runs `--games 2` over three valid games and asserts two
   lines.

GREEN must report the test runtime, especially `pass_chain` and the journal
tests with the real solver. If it exceeds a minute, the fixture is cut, not
the assertion. The trainer line count is also reported in GREEN.

## RED review round 2 responses

Verdict was **request changes**, on `pass_chain`; the fault was in the
round-1 wording.

- Swapped the inequalities. Black's move must not raise the black-side
  value, so the test now asserts `next <= value` after a black move.
  White's move must not lower it, so it asserts `next >= value` after a
  white move. The two messages are corrected.
- Appended the final result as one more chain link, `(final_black, 48)`, so
  the same inequality covers the last move. The separate
  `assert_eq!(chain.last().unwrap().1, 48)` is gone.

The expected RED failure is still the missing `othello_trainer::label`
module.
