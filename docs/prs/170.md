# Issue 170: Book trace tool

Epic #169. `docs/design/opening-book-v2.md` (revised) § Instrumentation.

## RED

### Scaffolding: `tools/examples/book_trace.rs`

The example carries unit tests, run by `cargo test` through
`[[example]] test = true`. It is outside the tools budget.

- **Types:**
  - `Book` is `Off`, `Embedded` (through `book::play`) or `Asset(bytes)`
    (through `book::lookup`);
  - `Source` is `Book` or `Search`;
  - `Decision { key, legal, source, square, depth, status, nodes }`.
- **`Tracer`:** a search agent with standard config,
  `SearchLimits::new(64, NO_DEADLINE, nodes)`, its own table and a book,
  which logs its decisions. Its `choose` is a stub that always returns
  `None`.
- **Journal lines:** `Decision::line` and `parse` are stubs.
- **Driver (written, around the stubbed core):** `book_trace --roots
  FILE --book off|embedded|PATH --nodes N --out JOURNAL [--pair-range
  A..B]`.
  - For each root, the book side plays black and then white against
    book-off, with fresh tracers per game. That matches the match
    harness's agent per game, so the table lifecycle is the same.
  - Records go to an append-only `Journal`, ids `pair:game`, and resume
    skips completed pairs. The header holds the book name, the asset's
    byte count, nodes, the roots hash and the engine commit.
- **Temporary:** two `#[allow(dead_code)]` markers, labelled as RED
  scaffolding, on `Source` and `Decision::parse`. They are needed only
  until GREEN constructs and uses them, and are removed in GREEN.

### Tests (6, all failing against the stubs)

| Test | Checks |
|---|---|
| `off_matches_agent` | book-off tracers play the same game (score, plies, passes) as `search_agent(book: false)` at 20,000 nodes from `d3 c3`; every decision is a search |
| `embedded_matches_agent` | an embedded-book tracer against book-off plays the same game as `search_agent(book: true)` against `search_agent(book: false)`; the first decision is a book hit at the start key, with depth 0, 0 nodes and `Complete` |
| `asset_matches_embedded` | the embedded bytes through `book::lookup` give the same game and the same decision log as `book::play` |
| `empty_asset_searches` | an empty asset never hits: every decision is a search with nodes > 0 |
| `decisions_and_passes` | a deterministic game (from fixed openings and small node caps) with a pass and a lone move: decisions + passes + 2 opening moves = plies, so passes log nothing; lone moves are logged with `legal` 1, as searches (node mode searches them) |
| `line_roundtrip` | a book and a search decision round-trip through `line` and `parse`; garbage does not parse |

**Results:** tools suite 101 passed, 6 failed (these). Clippy and
rustfmt are clean.

### GREEN plan

- `choose`:
  - returns `None` without logging when there is no legal move;
  - for `Embedded` and `Asset`, answers a `book::lookup` hit (against
    `BOOK` or the bytes) with a `Book` decision: depth 0, 0 nodes,
    `Complete`;
  - otherwise calls `search_tt` with the tracer's table and logs it as a
    `Search` decision with the result's depth, status and nodes.
- `Embedded` must match `book::play`, which answers only when the book
  hits.
- `line` and `parse` use the documented colon format.
- Resume parses every saved decision.
- The scaffolding markers come out.

## RED review response

`tools/examples/book_trace.rs` is restructured. The driver is now
`run(args)`, which the tests call directly, and `main` only reports its
error. There are 11 tests, all failing against the stubs.

- **Chronological traces against production play (major):**
  - New `trace_game(opening, black, white) -> (score, Vec<Event>)`, with
    `Event::Move { black, decision }` or `Event::Pass { black }`, in play
    order. It replaces grouping each side's log.
  - `events_line` persists the events as `b<decision>`, `w<decision>`,
    `b-` and `w-`.
  - `replay_events(opening, text)` parses them and replays from the
    opening, checking every key, legal count, move and forced pass.

  | Test | Checks |
  |---|---|

  | `trace_replays_with_pass` | a deterministic game with a pass followed by the other colour moving again replays from its opening through the persisted text; every decision's key is the board the mover saw, and its legal count is that board's |
  | `replay_rejects_tampering` | a wrong opening and an unforced pass are refused; changing a recorded source does not break the replay |

## RED re-review response

- **Lone-move regression restored (major):** new `lone_move_searched`.
  - It finds a deterministic book-off game, from fixed openings and node
    caps, containing a decision with one legal move.
  - Each such decision must be a `Search` with nodes > 0, since node mode
    searches lone moves.
  - The game's score and (colour, move) sequence must equal the
    production `search_agent` game at the same node cap, that move
    included. `production` now takes the node cap.
- **Resume trusts only finished games (major):**
  - new `finished(opening, events)`, true only when the replayed events
    end at a terminal position;
  - new `final_black(opening, events)`, Black's final score in
    centidiscs.
  - In GREEN, resume checks each saved record: replay, terminal end, and
    a recorded score equal to `final_black`. A pair with any failing game
    is discarded and replayed, and valid pairs are kept.
  - `replay_rejects_tampering` now also requires a legal two-event prefix
    to replay but not count as finished, and the full trace to count as
    finished.
  - New `command_resume_validates`: a complete run's journal is
    rewritten with a fully written but legally truncated `1:0` and a
    `2:1` whose score is off by 200. After resuming, the records equal
    the uninterrupted run's: pairs 1 and 2 replayed, pair 0 kept.
- **RED scaffolding:** `finished` and `final_black` join the labelled
  `#[allow(dead_code)]` markers, all removed in GREEN.
- **Results:** 13 tests, all failing against the stubs. Clippy and
  rustfmt are clean.

## GREEN

### Changes (`tools/examples/book_trace.rs`; no engine, CLI or tools-library lines)

- **`Tracer::choose`:**
  - with no legal move it returns `None` and logs nothing;
  - `Embedded` looks up `BOOK`, which is `book::play`'s asset, and
    `Asset` looks up its bytes, both through `book::lookup`;
  - a hit is logged as `Book` (depth 0, 0 nodes, `Complete`);
  - otherwise it calls `search_tt` with the tracer's table and logs
    `Search` with the result's depth, status and reported nodes;
  - every decision carries `zobrist(board)` and the legal-move count.
- **`trace_game`** applies the opening, then alternates, emitting
  `Event::Pass` for each forced pass and `Event::Move` with the mover's
  logged decision. It ends with Black's terminal score in centidiscs, the
  harness's convention.
- **Journal text:**
  - `Decision::line` and `parse` use the documented colon format;
  - `events_line` writes the event tokens;
  - `replay_events` parses and replays them, refusing out-of-turn
    tokens, unforced passes, and decisions whose key, legal count or move
    do not match the position.
- **Checks:** `finished` and `final_black` replay events to the
  terminal position. `trusted(root, line)` needs a finished replay and a
  recorded score equal to the replayed final score.
- **`load_roots`** reads move sequences of any length, `start` and `#`
  comments, and refuses bad squares and illegal sequences.
- **`digest`** is 64-bit FNV-1a. The header digests the effective asset
  (`BOOK` for `embedded`, the file's bytes for a path, nothing for `off`)
  and the roots text.
- **`run`:**
  - refuses a zero node cap before opening any journal;
  - on open, discards every record of a pair that is not fully trusted,
    and replays such pairs; trusted pairs are skipped.
- All RED scaffolding markers are removed (no `allow(dead_code)` left).

### One approved assertion narrowed

`asset_paths` required every search decision with an empty asset to
report nodes > 0. In GREEN a decision failed it with status `Fallback`,
depth 0 and 0 nodes. At a 20,000-node cap the endgame solve can spend
the whole budget, and the engine then returns its fallback move
without counting the aborted solve's work (`fallback_search` with no
spare nodes). That is the "reported nodes" caveat in the design. The
assertion now requires nodes > 0 except for `Fallback` decisions, and
still requires every decision to be a search. `lone_move_searched`
still requires nodes > 0 for lone moves.
