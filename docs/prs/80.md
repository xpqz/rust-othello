# Issue 80: Define frozen position sets and reproducible logs

## RED / GREEN

Issue: #80 — Define frozen position sets and reproducible logs.

Tests added in `tools/tests/harness.rs`:

- `openings_parse`: comments and blank lines are skipped; a legal 4-ply
  set parses; duplicate sequences are counted; the length distribution is
  recorded; too-short, illegal, and malformed squares are rejected.
- `canonical_d4`: all eight D4 transforms of the start position share one
  canonical key.
- `split_overlap`: the same group key in two splits is rejected; three
  distinct group keys are accepted.
- `frozen_sets`: the three frozen files each hold four 8-ply openings with no
  duplicates and no cross-split group-key overlap.
- `log_line`: a `GameLog` records run/pair/game, agent seeds, canonical key,
  opening squares, agents, depth, and score in order.

## Serialization

- One opening per line, squares as `a1`-style notation separated by spaces.
- Blank lines and lines starting with `#` are ignored.
- Each opening must be 4-8 plies and legal from `Board::START`.
- The group key is the minimal `(me, opp)` over the eight D4 transforms after
  ply 4; all openings with one key must stay in one split.
- `check_splits` rejects a group key appearing in two different splits.
- `stats` reports the opening count, duplicate sequence count, and sorted
  `(plies, count)` distribution.
- `bench/openings_tune.txt`, `bench/openings_validation.txt`, and
  `bench/openings_final.txt` each contain four 8-ply openings with distinct
  group keys.

## Logs

- `GameLog::line()` records `run`, `pair`, `game`, both agent seeds, the
  canonical key, the opening, the agent names, depth, and the black-view
  score.
- `match` loads openings with `--openings` (default:
  `bench/openings_validation.txt`) and pairs each opening with a colour swap.
- The same fixed-depth seed reproduces byte-identical stdout, including all
  ordered log lines.

## Implementation notes

- Added `tools/src/sym.rs` for D4 transforms and canonical keys, and
  `tools/src/positions.rs` for parsing, stats, and split validation.
- `tools/src/main.rs` now uses the frozen openings and prints one log line per
  game after the run configuration.
- Tune/positions subcommands are deferred to the remaining Phase 3 work; the
  files and policy above are in place.

## Round 2

- `match` rejects `--pairs` greater than the number of loaded openings, so no
  opening is reused within a run. The default set is the 512-opening
  validation file.
- The frozen sets are now generated once by `tools/examples/gen_openings.rs`,
  which enumerates 8-ply lines, groups them by canonical D4 key after ply 4,
  and assigns whole groups to splits by key order. Each file has 512 openings
  plus a `#` header describing the generator. The example is not production
  source and is not counted in the tools budget.
- The paired game loop is now a single `[(a, b), (b, a)]` loop that pushes
  each log immediately after its game, so game 0 records its own seeds.
  `log_seeds` checks the two games in a pair carry different seeds, and
  `pairs_limit` checks the reuse guard.
- `run` is the run seed, and the ambiguous `depth` field is gone (`describe`
  already records each side's configuration).
- The compiled-in default opening path is documented as a development default
  and can be replaced with `--openings`.
- Tools are 582 of 600 after the cut (`main.rs` 155, `positions.rs` 120).
- The Phase 3 gate command now reports
  `pairs 200 … mean 0.9375 interval [0.9125, 0.9600] bootstrap`.

Ready for re-review. Future issues keep the RED stop separate.

  and takes an evenly strided subset from each group. Every split has 20
  distinct 4-ply group keys, not one.
