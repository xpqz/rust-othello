# Issue 80: Define frozen position sets and reproducible logs

## RED / GREEN

Issue: #80 — Define frozen position sets and reproducible logs.

Tests added in `tools/tests/harness.rs`:

- `openings_parse`: comments and blank lines are skipped; a legal 4-ply
  set parses; duplicate sequences are counted; the length distribution is
  recorded; too-short, illegal, and malformed squares are rejected.
- `canonical_d4`: all eight D4 transforms of the start position share one
  canonical key.
- `split_overlap`: the same group key in two splits is rejected; three
  distinct group keys are accepted.
- `frozen_sets`: the three frozen files each hold four 8-ply openings with no
  duplicates and no cross-split group-key overlap.
- `log_line`: a `GameLog` records run/pair/game, agent seeds, canonical key,
  opening squares, agents, depth, and score in order.

## Serialization

- One opening per line, squares as `a1`-style notation separated by spaces.
- Blank lines and lines starting with `#` are ignored.
- Each opening must be 4-8 plies and legal from `Board::START`.
- The group key is the minimal `(me, opp)` over the eight D4 transforms after
  ply 4; all openings with one key must stay in one split.
- `check_splits` rejects a group key appearing in two different splits.
- `stats` reports the opening count, duplicate sequence count, and sorted
  `(plies, count)` distribution.
- `bench/openings_tune.txt`, `bench/openings_validation.txt`, and
  `bench/openings_final.txt` each contain four 8-ply openings with distinct
  group keys.

## Logs

- `GameLog::line()` records `run`, `pair`, `game`, both agent seeds, the
  canonical key, the opening, the agent names, depth, and the black-view
  score.
- `match` loads openings with `--openings` (default:
  `bench/openings_validation.txt`) and pairs each opening with a colour swap.
- The same fixed-depth seed reproduces byte-identical stdout, including all
  ordered log lines.
