# Issue 63: Record engine conventions in code and docs

## RED

No test stage: this is documentation-only setup work under the AGENTS.md
exception.

## Implementation

- Added crate-level doc comments in `src/lib.rs` covering:
  - score units and a pointer to `score` for the objective;
  - the start position and black's opening moves;
  - the perft pass and terminal-node conventions;
  - search pass cost, cutoff order, fail-soft, caller-handled roots,
    `SearchStatus`, and the deterministic fallback;
  - the root-only 12-empty solver trigger and 1000 ms default move budget;
  - Zobrist TT keys, full-key storage, strict equal-depth reuse, and domains;
  - tools bootstrap, frozen evaluators, and ply-4 D4 group keys;
  - engine/tools size ceilings and the doc-comment exclusion.
- `docs/PLAN.md` already states the same conventions, so no plan changes were
  required.

## Review responses

- Start wording now says black discs on d5/e4, white discs on d4/e5, black to
  move.
- Added the square mapping: `i` is `a1 + i`, row-major, `a1` = bit 0, `h8` =
  bit 63. The fallback is now explicitly the first legal move by square index
  (lowest index).
- Perft now says a pass consumes one ply and is a node, `perft(b, 0) = 1`, and
  that the terminal-with-`depth > 0` rule is this project's convention, not
  part of Aart Bik's table.
- The size rule now states the guard rule: formatted lines, excluding blank
  and all comment-only lines (`//`, `///`, `//!`, block comments).
- The solver threshold is configurable with a default of 12.
- The 1000 ms default is now its own time-control bullet.
- `src/lib.rs` is the intended single home for cross-cutting conventions.
  When `board.rs` and `search.rs` gain code, each will add a one-line `//!`
  pointer back to the crate docs.
