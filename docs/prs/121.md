### Fixture

The known game is a deterministic engine playout with seed 23. It records 59
moves; replaying it inserts four passes. Black finishes with 8 discs, one
empty square, and `final_score(board) == -48`, matching the WTHOR real score
`2B - 64`. The move bytes are embedded in the test, so the fixture needs no
archive data.

### Intended design

- `trainer/src/lib.rs` exposes `wthor` and `check`; the binary calls them.
- `wthor::read(bytes)` parses the 16-byte header (N1, year, P1/P2/P3, with
  P3 0 meaning 22), checks `16 + 68 * N1`, reads 68-byte records, and decodes
  each move byte `column + 10 * row` to the engine square
  `(row - 1) * 8 + (column - 1)`. Parsing does not validate legality.
- `wthor::replay(game)` starts at `Board::START`, validates each move with
  the engine's `play`, inserts a pass whenever the side to move has no legal
  move, and returns `Replay { positions, final_board, passes }`. Positions
  are the non-terminal positions whose side to move has a legal move.
  `positions` starts with `Board::START`. An illegal move returns
  `Reject::Illegal { ply }`; a game that ends with a legal move still
  available returns `Reject::Incomplete`.
- `check::summarise(db)` reports games read, games replayed to the end,
  rejected counts by reason, real-score agreement (`2B - 64` against the
  engine's terminal score), the P3 values found, and the share whose
  theoretical score equals the real score.
- `check::verify_file(path, expected)` computes SHA-256 and refuses a
  mismatch. The full manifest and the full-archive check log are GREEN work.

## RED review round 1 responses

Verdict was **request changes**; every required point is addressed in the
tests.

1. `move_decoding` now checks asymmetric squares: 18 (h1) -> 7, 81 (a8) ->
   56, and 56 (f5) -> 37, alongside 11 -> 0 and 88 -> 63.
2. `known_game` is documented here as a pass/final-score fixture, not an
   orientation test: it was encoded by the same convention that decodes it.
   Requirement 1 is the orientation test.
3. `invalid_byte` uses both 19 and 99 and expects
   `Reject::Illegal { ply: 0 }`. `summary_counts` includes the 19 case, so
   an invalid byte is a per-game rejection rather than a file error.
4. `header_rejections` refuses P1 = 10 and P2 = 1.
5. `summary_counts` now has six games: one exact, one with real score 9
   against engine 8, one with theoretical 20 against real 8, one illegal
   opening, one incomplete, and one invalid byte. Expected counters:
   read 6, replayed 3, rejected illegal 2, rejected incomplete 1,
   real agreement 2, theoretical equality 1, P3 24 found in one file.
   Both agreement counters are over replayed games; `p3_values` counts
   files, not games.
6. `manifest_entries` checks one good and one bad entry in two-line
   `shasum -a 256` format. `manifest_missing` checks a named file that is
   absent. `manifest_unlisted` requires a `.wtb` file absent from the
   manifest to be refused. `manifest_mismatch` keeps the direct hash test.

The expected RED failure remains the missing `othello_trainer` library.

### GREEN requirements from review

- `docs/tuning/wthor_check.log` must report real-score agreement separately
  for full-board games and games ending with empty squares, and within the
  latter separately for black wins and black losses. A systematic group
  disagreement is a stop condition, not a score to average away.
- Generate `trainer/wthor.sha256` from the 49 files already in
  `data/wthor/` (137,548 games by their headers, P3 = 24).
