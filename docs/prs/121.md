### Fixture

The known game is a deterministic engine playout with seed 23. It records 59
moves; replaying it inserts four passes. Black finishes with 8 discs, one
empty square, and `final_score(board) == -48`, matching the WTHOR real score
`2B - 64`. The move bytes are embedded in the test, so the fixture needs no
archive data.

### Intended design

- `trainer/src/lib.rs` exposes `wthor` and `check`; the binary calls them.
- `wthor::read(bytes)` parses the 16-byte header (N1, year, P1/P2/P3, with
  P3 0 meaning 22), checks `16 + 68 * N1`, reads 68-byte records, and decodes
  each move byte `column + 10 * row` to the engine square
  `(row - 1) * 8 + (column - 1)`. Parsing does not validate legality.
- `wthor::replay(game)` starts at `Board::START`, validates each move with
  the engine's `play`, inserts a pass whenever the side to move has no legal
  move, and returns `Replay { positions, final_board, passes }`. Positions
  are the non-terminal positions whose side to move has a legal move.
  `positions` starts with `Board::START`. An illegal move returns
  `Reject::Illegal { ply }`; a game that ends with a legal move still
  available returns `Reject::Incomplete`.
- `check::summarise(db)` reports games read, games replayed to the end,
  rejected counts by reason, real-score agreement (`2B - 64` against the
  engine's terminal score), the P3 values found, and the share whose
  theoretical score equals the real score.
- `check::verify_file(path, expected)` computes SHA-256 and refuses a
  mismatch. The full manifest and the full-archive check log are GREEN work.

### Fixture correction found in GREEN

The RED fixture used real score 8 from the probe's side-to-move disc count.
The final side to move is white with 8 discs; black has 55 and the one empty
square is awarded to black, so the WTHOR black count is 56. The test now uses
56 for the exact game, 55 for the wrong-real game, and asserts
`!replay.final_black` and 55 black discs. Colour-aware scoring then gives
`+48`, matching `2 * 56 - 64`; the wrong-real and wrong-theoretical counters
still distinguish the two fields. This is a correction of the fixture, not a
weakening of the test.

## GREEN review round 1 response

Verdict was **request changes**, size only. The refactor is in `48ad444`.
Trainer production lines: **250 / 450**, down from 376. The earlier 376
figure in these notes is superseded.

What changed:

1. `Summary` is now a `BTreeMap` of labelled `(agree, total)` pairs plus the
   P3 file counts. `merge` and `Group` are gone; `summarise` takes the summary
   by mutable reference, and the report is one loop.
2. `Database` and `Header` are gone. `read` returns `(p3, records)`. `Game`
   no longer carries tournament, black or white; the header year is not
   stored because nothing uses it.
3. `Replay.positions` is one vector of `(Board, black_to_move)`. The parallel
   vector and `passes` field are gone.
4. `run` lists the `.wtb` files once and passes that list to `verify_files`;
   the manifest check no longer re-reads the directory.
5. `verify_file` is a `then_some` expression; `digest` stays a `map`/`collect`
   because `Sha256::digest`'s output does not implement `LowerHex`, so the
   attempted one-line `format!("{:x}", ...)` does not compile.
6. `check` takes two optional positional arguments, `check [dir] [manifest]`.

220 was not reached cleanly. The remaining 30 lines are the WTHOR header and
record validation (P1, P2, exact length), colour-aware replay with pass
insertion, SHA-256 manifest verification with missing and unlisted checks,
and the CLI report and 99% threshold. Reaching 220 would mean merging error
paths or dropping checks the tests require, so I stopped at 250 rather than
compress the code to the number.

Changed tests, each keeping its behaviour:

- `header_fields`: checks `records.len()` and `p3`; the unused year assertion
  is gone.
- `move_decoding`: destructures `(p3, records)`.
- `known_game`: positions are `(Board, bool)`; the four passes are counted
  from consecutive equal colours; the final colour and 55 black discs are
  asserted as before.
- `illegal_move`, `invalid_byte`, `incomplete_game`, `positions_playable`:
  destructure the `read` tuple and iterate `(Board, bool)` positions.
- `summary_counts`: builds a mutable `Summary`, calls
  `summarise(p3, &records, &mut summary)`, and reads the metrics map.
- `check_synthetic`: calls `check <dir> <manifest>` positionally.

The log was regenerated at `48ad444`. Metric lines are now alphabetical
because the labels live in a `BTreeMap`; the values are unchanged and every
real-score group is still 100.00%.
