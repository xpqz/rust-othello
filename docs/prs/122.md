### Base order and hand-computed indexes

Square order is digit order, first square least significant. The base lists
are row-major from the design's diagrams:

- edge: a1..h1, b2, g2;
- corner 3x3: a1..c1, a2..c2, a3..c3;
- corner 2x5: a1..e1, a2..e2;
- rows 2, 3, 4: a..h on that row;
- diagonals 8..4: a1..h8, b1..h7, c1..h6, d1..h5, e1..h4.

Hand-built board: `me = 0x0209` (a1, d1, b2), `opp =
0x8000_0000_0800_4824` (c1, f1, d2, g2, d4, h8). The identity instances
give:

| Family | Digits | Index |
| --- | --- | ---: |
| Edge + 2X | 1,0,2,1,0,2,0,0,1,2 | 46,459 |
| Corner 2x5 | 1,0,2,1,0,0,1,0,2,0 | 13,897 |
| Diagonal 8 | 1,1,0,2,0,0,0,2 | 4,432 |

### Intended API

In `src/pattern.rs`:

- `FAMILIES: [&'static [u8]; 11]` and `INSTANCE_COUNT = 46`,
  `TABLE_SLOTS = 167_265`, `STAGES = 12`.
- `Instance { squares: &'static [u8], family: usize, offset: u32 }`.
- `instances() -> &'static [Instance]`, built once with `LazyLock`, with the
  eight symmetries applied in `Sym::ALL` order (identity first).
- `features(board: Board) -> [u32; 46]`, parallel to `instances()`, giving
  the family offset plus the base-3 index (0 empty, 1 `me`, 2 `opp`).
- `stage(empties: u32) -> usize`, `60.saturating_sub(empties) / 5`,
  clamped to at most 11.
- `canonical(index: u32) -> u32`, the single shared derivation of the
  family self-symmetry permutation: it finds the family from the offset,
  applies that family's permutation to the local base-3 index, and returns
  the smaller of the index and its image. The test uses it now; the trainer
  will use it later for tied weights. No permutation table is duplicated in
  the test.

The pattern module does not add `pattern::evaluate`, weights, or a search
hook. `search.rs` and `eval.rs` are unchanged.

Engine production lines will be reported in GREEN. The evaluator must end at
or under 230 after issue 5, so this issue's pattern module is expected to be
small; the exact count is GREEN evidence.

## RED review round 1 responses

Verdict was **request changes**; all six points are addressed.

1. `index_convention` now subtracts the instance offset in its helper, so the
   asserted values stay the local indexes in the table above: 46,459,
   13,897 and 4,432.
2. `canonical` is removed from the engine API and `canonical_symmetry` is
   removed from `tests/pattern.rs`. The permutations and their tests move to
   the trainer in issue 124, where the transforms come from
   `othello_tools::sym`.
3. `instances_closed` is added: every instance, under every symmetry, has a
   transformed square set equal to some instance of the same family.
4. `features_reference` is added: for all 46 instances it recomputes
   `offset + sum(digit * 3^position)` directly from `instance.squares` and
   compares it with `features`, on the start position and three dense corpus
   positions (40, 44 and 42 discs, the first three corpus lines with at least
   40 discs). This pins digit order for transformed instances.
5. `index_ranges` runs over the same four boards.
6. `stage_boundaries` adds the other sides: 59 and 56 are stage 0, 51 is
   stage 1, 6 is stage 10, and 4 and 1 are stage 11.

The expected RED failure is still the missing `othello::pattern` module.

## GREEN

Implemented the approved pattern module in `src/pattern.rs`.

- Eleven base lists in the order recorded above, public as `FAMILIES`.
- `Instance { squares, family, offset }` and `instances()` built once with
  `LazyLock`, applying the eight symmetries in `Sym::ALL` order and
  deduplicating by square set. Square lists are leaked once to give the
  static slices the public `Instance` exposes.
- `features(board) -> [u32; 46]` sums family offset plus the base-3 index
  from `instance.squares`, first square least significant.
- `stage(empties) = min(60.saturating_sub(empties) / 5, 11)`.
- `INSTANCE_COUNT = 46`, `TABLE_SLOTS = 167_265`, `STAGES = 12`.
- No `canonical`, no weights, no `pattern::evaluate`. `search.rs` and
  `eval.rs` are unchanged.
