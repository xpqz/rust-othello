# Issue 165: Engine clock policies and early exits

Engine side of `docs/design/time.md` amendment 1 (approved, revision 2).

## RED

### Scaffolding

- `src/search.rs`:
  - `pub struct Early { stable: u8, decided: u16, share: u8 }` with
    `Early::OFF`, and `SearchLimits.early`, which `new` and `depth` set to
    `Early::OFF`;
  - a stub `pub fn stops(elapsed, start_ms, &early, &history)` that
    always says no;
  - `pub struct ClockPolicy` with private fields (weight, reserve, cap,
    early, forced), `pub const CLOCK_POLICIES: [ClockPolicy; 4]` (for now
    four copies of the approved allocator), a stub
    `ClockPolicy::variant(k)` that always gives `None`, and
    `ClockPolicy::forced()`;
  - a stub `allot_with(board, R, threshold, &policy)` that ignores the
    policy.
- `src/agents.rs`: `clock_agent(config, limits, policy)` takes a
  `&'static ClockPolicy`, which it does not use yet.
- **Callers:** `tools/src/agents.rs::search` and `tests/clock.rs` pass
  `&CLOCK_POLICIES[0]`. The tools grammar for `v<k>` is #166. The 10
  `SearchLimits` literals in `tests/search.rs` and the `limits` helper in
  `tests/clock.rs` gain `early: Early::OFF`.

### GREEN plan

- **`stops`:** settled means a stable window of `stable` entries with
  the same best move, or the last |score| (unsigned) at least `decided`.
  The cutoff is `Duration::from_millis(start_ms).checked_mul(min(share,
  100))`, divided by 100; `None` never stops.
- **The iterative loop** keeps the history only when `early` is not
  `OFF`. With exits off it allocates nothing and reads the clock no more
  than now (implementation-review note).
- **Policies:** `CLOCK_POLICIES` as in the design table; `variant`;
  `allot_with` generalizing `allot`, which calls it with variant 0.
- **`SearchAgent`** stores its policy. After the first `clock`, a forced
  policy with one legal move returns it without searching.
