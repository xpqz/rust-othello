# Issue 77: Implement tools harness game loop, openings, and pair scoring

## RED

Issue: #77 — Implement tools harness game loop, openings, and pair scoring.

Tests added in `tools/tests/harness.rs`:

- `games_terminate`: greedy vs greedy from the start terminates with more than
  zero plies and a score inside `[-6400, 6400]`.
- `opening_replay`: the odd-length opening `[c4]` replays to identical
  `GameResult`s with fresh agents; the illegal opening `[a1]` is rejected.
- `identical_pairs_draw`: two identical greedy factories score `0.5` over
  colour-swapped pairs with and without an opening; swapping two different
  factories makes the pair scores sum to `1.0`.
- `invalid_actions_error`: an agent returning `None` when legal moves exist,
  and an agent returning off-board square `64`, both produce `Err`.
- `passes_occur`: across 50 seeded random games, at least one pass occurs and
  all games terminate.

Expected failure:

```text
error[E0432]: unresolved import `othello_tools::harness`
```

The failure is intended: `tools/src/lib.rs` is empty.

## Intended behaviour

- `Factory` is `dyn Fn() -> Box<dyn Agent>`; every game constructs fresh
  agents from the factories.
- `play_game(opening, black, white)` replays an opening of squares, then runs
  to a terminal. The absolute side-to-move bit toggles on every placement and
  pass, including an odd-length opening.
- `play_from(board, black_to_move, black, white)` is the same loop from an
  explicit position. When the side to move has no move but the opponent does,
  the loop passes without calling that side's agent; when neither has a move,
  the game ends.
- Every action is validated before shifting: `None` while legal moves exist
  or an illegal square is an error, in both debug and release.
- `GameResult { score, plies, passes }` reports the terminal centidisc score
  from black's perspective, so `score.signum()` gives the result.
- `pair_score` plays the opening twice with colours swapped and returns the
  mean score for the first factory, with win = 1, draw = 0.5, loss = 0.
- Canonical D4 grouping and tune/validation/final split consistency move to
  #80, which owns `positions.rs` and `sym.rs`.
