# Issue 125: classic and pattern agents; speed and diagnostics

## RED

Tests first; the classic evaluator copy and the two agents are not present.

`tools/tests/baselines.rs` now covers:

- `classic_pins`: `eval_classic` matches the 1.0.0 evaluator on the start
  position and the hand-pinned single-disc values.
- `classic_config_pins`: `classic_config()` uses `eval_classic`, threshold
  14 and ordering.
- `classic_antisymmetry`: the old evaluator's antisymmetry and
  `EVAL_BOUND` test moved here from the engine's `tests/eval.rs`.
- `classic_agent`: `match --a classic:100` describes
  `classic:100 (eval_classic, depth 64, time 100, nodes 0, threshold 14)`.
- `pattern_agent`: `match --a pattern:100` describes
  `pattern:100 (pattern::evaluate, depth 64, time 100, nodes 0, threshold 14)`,
  and `agents::config("pattern", ...)` selects `pattern::evaluate` with
  threshold 14.

`tools/tests/golden.rs` now builds its search configuration from
`classic_config()`, so the frozen v1.0.0 node/move/score fingerprint tests
the copied evaluator, not the engine's live one.

The engine's old `antisymmetry_and_bounds` test is removed from
`tests/eval.rs`; it moves to the classic copy.

Expected failure:

```text
error[E0432]: unresolved imports `othello_tools::baselines::classic_config`,
`othello_tools::baselines::eval_classic`
```

### Intended implementation

- Copy the 1.0.0 evaluator into `tools/src/baselines.rs` as
  `eval_classic`, with `classic_config()` at threshold 14.
- `agents::parse_name` accepts `classic[:time]` and `pattern[:time]`;
  `agents::config` selects `classic_config()` and a pattern config using
  `pattern::evaluate`, both threshold 14. `describe` prints the evaluator
  names used by the tests.
- The engine `SearchConfig::standard()` is untouched.

### Measurements for GREEN

All matches use `bench/openings_tune.txt`, never the gate openings; logs
and journals go under `docs/tuning/` with commit, date and elapsed time.

- Nanoseconds per `evaluate` call, each evaluator, over the bench corpus
  by stage.
- Nodes per second and depth reached at 3 s over the corpus.
- `pattern` against `classic` at equal depth and at equal nodes, 100 pairs
  each.
- Carried from #124: over the corpus and over positions sampled from
  search at 3 s, report how often the raw sum exceeds `EVAL_BOUND` and the
  share of looked-up entries with fewer than 20 training occurrences. If
  either is common, stronger damping (a larger floor with the horizon
  kept) is the first remedy; that is a re-fit, not new code.
- If the pattern search rate is below half the classic rate, improve the
  indexing within the tools/engine budget and measure again before the
  gate issue.

The notes will give a short reading of prediction quality against cost,
whatever the result. Tools production is 1,173 before this issue and has a
1,300-line budget; the classic copy and agents must fit.
