# Issue 159: Route Rust build artefacts to Space2 when mounted

Setup work, with no test stage.

## Change

- **`scripts/cargo-target.sh`** (new) prints
  `/Volumes/Space2/othello/<checkout>/target` when the volume is really
  mounted: its device id differs from `/`, so a stale `/Volumes/Space2`
  directory on the system disk does not count. Otherwise it prints nothing.
  `OTHELLO_CARGO_VOLUME` overrides the mount point. Modelled on ghost's
  `scripts/cargo-target.sh` and nars's `scripts/lib/cargo-target.sh`.
- **One target per checkout:** the root, `gui`, `tools` and `trainer`
  crates of a checkout share that directory, so the engine is compiled once
  for all of them. Separate checkouts get separate directories, so a run
  worktree's binaries are never overwritten by builds elsewhere.
- **Scripts:** the hard-coded `tools/target/...` paths in
  `tools/tests/{edax_depth,edax_phase,edax_resume,probcut_fit,probcut_screen,solve_times,version_match}.sh`
  and `scripts/version_workers.sh` now use
  `${CARGO_TARGET_DIR:-<the old path>}`, so they work routed or not.
- **Outside the repo:** a block appended to `~/.zshenv`, guarded on `$PWD`
  being inside `/Users/stefan/work/crust/othello*`, exports
  `CARGO_TARGET_DIR` from the checkout's own `scripts/cargo-target.sh` when
  it prints a path. Checkouts without the script (the pinned
  `othello-book-ext` and `othello-book-run` worktrees) keep their local
  targets.

## Commands and results

- Routing, each from a fresh `zsh -c`: main checkout and `trainer/` →
  `/Volumes/Space2/othello/othello/target`; `othello-book-ext` → unset;
  nars → its own `/Volumes/Space2/skalpel/target-shared` (unchanged);
  `/tmp` → unset. `OTHELLO_CARGO_VOLUME=/nonexistent` and a same-device
  directory both print nothing.
- `scripts/check.sh` with `CARGO_TARGET_DIR=/Volumes/Space2/othello/othello/target`:
  exit 0, 6 min 20 s (cold build on the volume).
- `tools/tests/probcut_screen.sh` and `tools/tests/version_match.sh`,
  routed: exit 0. The other five tool scripts need Edax or long runs and
  were not re-run; their change is the same substitution.

## Not done

- The existing local `target/` directories (root, `gui`, `tools`,
  `trainer`) were left in place. They can be deleted to free disk space.

## Review response

### Managed routing (major)

- **Fix:** the startup block is now committed as `scripts/zshenv.zsh` and
  installed by appending it verbatim to `~/.zshenv`, replacing the earlier
  block. Its last 20 lines are byte-identical to the committed file
  (`cmp`), and `zsh -n ~/.zshenv` passes.
- **Ownership:** `OTHELLO_CARGO_ROUTED` holds the target the block
  exported. If `CARGO_TARGET_DIR` is unset or equal to it, the block clears
  both and recomputes them from `$PWD` and the mount. Any other value was
  set by the caller and is kept, and the stale marker is dropped. The block
  runs in every zsh, so an inherited routed target is dropped outside
  routed checkouts.
- **Transitions:** probed with `scratch/probe159/probe.sh` (not
  committed). It sources only the committed snippet through an isolated
  `ZDOTDIR`; a temporary sibling checkout `othello-probe159`, holding only
  the helper, stood in for a second routed checkout and was removed
  afterwards. Output (`target | routed marker`):

```text
fresh main:              /Volumes/Space2/othello/othello/target | routed=/Volumes/Space2/othello/othello/target
fresh pinned:            UNSET | routed=UNSET
main -> pinned:          UNSET | routed=UNSET
main -> other routed:    /Volumes/Space2/othello/othello-probe159/target | routed=/Volumes/Space2/othello/othello-probe159/target
main -> outside (/tmp):  UNSET | routed=UNSET
main -> volume absent:   UNSET | routed=UNSET
main -> same-device dir: UNSET | routed=UNSET
explicit custom, main:   /Users/stefan/work/crust/othello/scratch/probe159/custom | routed=UNSET
explicit custom, pinned: /Users/stefan/work/crust/othello/scratch/probe159/custom | routed=UNSET
main -> custom in child: /Users/stefan/work/crust/othello/scratch/probe159/custom | routed=UNSET
```

  "Child" rows start a zsh in the named place from a shell already routed
  in main, with the named variable set by the caller. With the real
  `~/.zshenv`, a child shell started from routed main in nars gets
  `/Volumes/Space2/skalpel/target-shared` and in ghost
  `/Volumes/Space2/ghost/target-shared`, as before. The nars and ghost
  blocks are unchanged.

### Layout and reuse (non-blocking)

- **Layout adjustment:** the issue asked for one target per Cargo project.
  This change deliberately uses one target per checkout,
  `/Volumes/Space2/othello/<checkout>/target`, shared by the root, `gui`,
  `tools` and `trainer` crates. Checkouts stay isolated from each other.
- **Correction:** "the engine is compiled once for all of them" is
  withdrawn. Sharing the directory allows reuse of compiled artefacts only
  where profiles, features and flags match. The trainer's release profile
  and the GUI's dev override differ from the engine and tools profiles.
