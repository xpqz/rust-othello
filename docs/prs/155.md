# Issue 155: Opening book engine lookup behind a switch

Engine side of `docs/design/book.md` § Engine and § Tests › Engine.
The shipped asset is the approved #158 book (7,729 records).

## RED

### Scaffolding, so that the tree compiles

- `src/book.rs` (new): `BOOK` (`include_bytes!("../assets/book.bin")`),
  `RECORD` (11), and stubs `lookup(asset, board) -> Option<(u8, i32)>`
  returning `None`, `book_move(board)` delegating to `lookup(BOOK, …)`, and
  `play(board, limits, config, table) -> SearchResult` calling `search_tt`
  only.
- `SearchConfig::book: bool`, `false` in `standard()`. `search_tt` does not
  read it.
- **API choices:**
  - `play` lives in `book.rs` and is called as `othello::book::play`.
    `search.rs`, `agents.rs` and `cli.rs` already import `board::play`.
  - `lookup` takes the asset as a slice. This is the seam for the
    bad-data tests, since `tests/budget/rules.rs` forbids test code under
    `src/`.
- Every full `SearchConfig` literal gains `book: false`:
  - `phase2_config` and `classic_config` (`tools/src/baselines.rs`);
  - the trainer's scoring `policy()` (`trainer/src/book.rs`), so the
    scoring policy never consults a book;
  - `tools/examples/search_rate.rs` and `trainer/examples/occurrence.rs`;
  - the test helpers in `tests/agents.rs`, `tests/ordering.rs` and
    `tests/search.rs`.

### GREEN plan

- `lookup`:
  - reject a ragged asset, a stuck board or a terminal board;
  - take the canonical board with bit-level transforms, the least
    `(me, opp)` with the same tie rule, remembering the kind;
  - binary-search `zobrist` over the records;
  - check the square is below 64, map it back through the inverse kind
    (kinds 1 and 3 are each other's inverse, the rest self-inverse);
  - return it only if legal, with the value read as i16.
- `play`: on `config.book` and a hit, return the move with
  `SearchResult { depth: 0, nodes: 0, Complete, solved: false }`;
  otherwise `search_tt`.
- **Callers:** `SearchAgent::choose` and GUI `start_engine` call
  `book::play`. CLI play goes through `SearchAgent`. Explicit
  `book: false` goes into the `pc:` configurations and golden's `full()`
  helper.

### Question for the reviewer

The design asks for "a book hit and a book miss through `SearchAgent`, the
CLI play path and the GUI engine call". CLI play and the GUI both build
from `SearchConfig::standard()`, which keeps `book: false` until the gate,
so neither can hit without a new switch, which the design does not have.

This RED therefore tests hit, miss and re-entry through `SearchAgent` and
`play` with `book: true`. It also tests the shipped `book: false` policy:
`standard()` in `play_off`, and the GUI's configuration in
`engine_book_policy`. The CLI's play path is a `standard()`
`SearchAgent`, with no test of its own. Is that acceptable, or should the CLI and GUI get an
explicit book switch now?

## RED review response

### Agent fixtures now tell a book hit from a search

- New helper `distinct(n)` in `tests/book.rs`: the first `n` asymmetric
  manifest records, in canonical orientation, whose depth-3 search
  (`standard()`, fresh table) plays a different move from the stored one.
  It reads only the manifest and `search_tt`, never `lookup`. The first
  two are `00000301352b0100:00001c1e0a142000` (stored 37, search 12) and
  `0000040c3c081008:0000001000140804` (stored 43, search 1).
- `agent_reenters`: a single `book: true` agent must play the stored move
  on board A, the search move on the deep miss, then the stored moves on B
  and on A again. An agent that bypasses the book, or stops consulting it
  after a miss, fails at a hit. Against the stub it now fails at the first
  agent call (`Some(12)` against `Some(37)`), not at a `book_move` expect.
- `agent_book_off`: a `standard()` agent plays the search move on both
  boards, and that move differs from the stored one.

### GUI engine call

- `start_engine` now hands off to a private `think(board, limits, config,
  table, generation) -> Receiver<(u64, SearchResult)>`. It is the same
  worker thread and channel as before and still calls `search_tt` in RED.
  Behaviour is unchanged.
- New `gui/src/main.rs::engine_book_path`, with `book: true` and depth 3:
  - **Hit:** the stored board above, after asserting that the search
    plays something other than 37. The channel must deliver generation 7
    and `(best, score, depth, nodes) = (37, 553, 0, 0)`. Against the stub
    it delivers `(12, 1158, 3, 278)` and fails.
  - **Miss:** the deep board's result equals `search_tt`.
- `engine_book_policy`, the default-off assertion, is kept.
- **CLI:** `play_game` delegates to `search_agent(SearchConfig::standard(),
  …)` (`src/cli.rs:155`), so `agent_reenters` and `agent_book_off` cover
  its only playing path. No CLI flag or GUI control was added.

## GREEN

### Changes

- `src/book.rs`:
  - **`lookup`** refuses a board with no legal move (stuck or terminal)
    and an asset whose length is not a multiple of 11 (`as_chunks`). It
    takes the least `(me, opp)` over the eight bit-level images and
    remembers its symmetry kind. It binary-searches `zobrist` of that
    board over the records. It rejects a stored square of 64 or more, maps
    the square back through the inverse kind (1 and 3 swap, the rest are
    their own inverse), and answers only if that square is legal, with the
    value read as i16.
  - **Images:** `image(bits, kind)` uses `pattern.rs`'s numbering, built
    from a delta-swap `transpose`, `swap_bytes` (ranks) and `reverse_bits`.
  - **`play`:** the lookup runs only when `config.book` is set. A hit
    returns `SearchResult { depth: 0, nodes: 0, Complete, solved: false }`;
    otherwise `play` calls `search_tt`, unchanged.
- **Callers:** `SearchAgent::choose` (`src/agents.rs`) and the GUI's
  `think` worker call `book::play`. CLI play, tools `match`,
  `engine_worker` and `edax_ladder` reach it through `SearchAgent`. With
  `standard()` (`book: false`) all of them play exactly as before.
- **Explicit `book: false`:** the `pc:` configuration
  (`tools/src/agents.rs`) and golden's full-width `full()` helper.
- **Tools budget:** the explicit field took the tools crate to 1,301 of
  1,300. `agents::config` now picks a base configuration per kind and sets
  `ordering` once (`SearchConfig { ordering, ..base }`), instead of
  repeating it in every arm. Behaviour is unchanged (the
  `tools/tests/baselines.rs` agent tests pass).

### Commands and results

- `cargo test --release --test book`: 19 passed.
- `scripts/check.sh`: exit 0. rustfmt and clippy (`-D warnings`) are clean
  on all four crates, and every suite passes: 410 tests passed, 0 failed,
  13 ignored (the existing ignored tests). This includes
  `engine_book_path` and `engine_book_policy` (GUI) and `frozen_off`
  (tools).
- **Budgets:** engine 1,296 of 1,500. Of the 78 lines over the 1,218
  before this issue, `src/book.rs` is 56. Tools 1,292 of 1,300; trainer
  2,465 of 2,500.

### Not changed

- `standard()` keeps `book: false`. Enabling the book is #156's gate,
  after #151.
