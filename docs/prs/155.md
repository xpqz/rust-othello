# Issue 155: Opening book engine lookup behind a switch

Engine side of `docs/design/book.md` § Engine and § Tests › Engine.
The shipped asset is the approved #158 book (7,729 records).

## RED

### Scaffolding, so that the tree compiles

- `src/book.rs` (new): `BOOK` (`include_bytes!("../assets/book.bin")`),
  `RECORD` (11), and stubs `lookup(asset, board) -> Option<(u8, i32)>`
  returning `None`, `book_move(board)` delegating to `lookup(BOOK, …)`, and
  `play(board, limits, config, table) -> SearchResult` calling `search_tt`
  only.
- `SearchConfig::book: bool`, `false` in `standard()`. `search_tt` does not
  read it.
- **API choices:**
  - `play` lives in `book.rs` and is called as `othello::book::play`.
    `search.rs`, `agents.rs` and `cli.rs` already import `board::play`.
  - `lookup` takes the asset as a slice. This is the seam for the
    bad-data tests, since `tests/budget/rules.rs` forbids test code under
    `src/`.
- Every full `SearchConfig` literal gains `book: false`:
  - `phase2_config` and `classic_config` (`tools/src/baselines.rs`);
  - the trainer's scoring `policy()` (`trainer/src/book.rs`), so the
    scoring policy never consults a book;
  - `tools/examples/search_rate.rs` and `trainer/examples/occurrence.rs`;
  - the test helpers in `tests/agents.rs`, `tests/ordering.rs` and
    `tests/search.rs`.

### GREEN plan

- `lookup`:
  - reject a ragged asset, a stuck board or a terminal board;
  - take the canonical board with bit-level transforms, the least
    `(me, opp)` with the same tie rule, remembering the kind;
  - binary-search `zobrist` over the records;
  - check the square is below 64, map it back through the inverse kind
    (kinds 1 and 3 are each other's inverse, the rest self-inverse);
  - return it only if legal, with the value read as i16.
- `play`: on `config.book` and a hit, return the move with
  `SearchResult { depth: 0, nodes: 0, Complete, solved: false }`;
  otherwise `search_tt`.
- **Callers:** `SearchAgent::choose` and GUI `start_engine` call
  `book::play`. CLI play goes through `SearchAgent`. Explicit
  `book: false` goes into the `pc:` configurations and golden's `full()`
  helper.

### Question for the reviewer

The design asks for "a book hit and a book miss through `SearchAgent`, the
CLI play path and the GUI engine call". CLI play and the GUI both build
from `SearchConfig::standard()`, which keeps `book: false` until the gate,
so neither can hit without a new switch, which the design does not have.

This RED therefore tests hit, miss and re-entry through `SearchAgent` and
`play` with `book: true`. It also tests the shipped `book: false` policy:
`standard()` in `play_off`, and the GUI's configuration in
`engine_book_policy`. The CLI's play path is a `standard()`
`SearchAgent`, with no test of its own. Is that acceptable, or should the CLI and GUI get an
explicit book switch now?
