# Issue 86: Implement move ordering with fixed buffers

## RED

Issue: #86 — Implement move ordering with fixed buffers.

Tests added in `tests/search.rs`:

- `ordering_priorities`: `me = c1 | b4 | e4`, `opp = b1 | b3 | f4` has moves
  `a1` (corner), `g4` (normal), and `b2` (X). At depth 1 the order is
  `a1, g4, b2`; with `b2` preferred it moves to the front.
- `ordering_start_ties`: from the start, all four moves are normal; with `f5`
  preferred the order is `f5, d3, c4, e6`, proving preferred-first and
  square-index ties.

Expected failure:

```text
error[E0432]: unresolved import `othello::search::ordered_moves`
```

The failure is intended: ordering does not exist yet.

## Intended behaviour

- `ordered_moves(board, moves, depth, preferred) -> ([u8; 64], usize)` fills a
  fixed stack buffer and sorts it in place; no heap allocation.
- Priority order: preferred (root previous best / future TT move), corners,
  normal squares, then X/C squares. Within a category, fewer opponent replies
  sorts first at depth >= 2; ties break by square index.
- The root passes the previous iteration's best as `preferred`; interior
  nodes pass `None` until the TT/PV move lands in #88.
- Scores are unchanged by ordering; node/time measurements on the corpus are
  #89's acceptance.
