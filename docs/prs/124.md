# Issue 124: Fit, restart, learning report, inspect, asset and pattern::evaluate

## RED (checkpoint 1: fit, restart, report, inspect)

Tests first; no `othello_trainer::fit` module is present.

New `trainer/tests/fit.rs` covers:

- `reference`: a three-entry table and four examples where entry 0 occurs
  twice in one position and entry 1 twice in another. The hand-computed
  least-squares solution is (1.8, 2.8); entry 2 is unseen and must stay
  exactly zero. A fit that counts each position once per entry gives
  (2.5, 4.0) and fails.
- `damping`: three noisy examples for one entry stay within 0.5 discs of
  zero with the production constants; an unseen entry is exactly zero.
- `quantisation`: NaN and out-of-i16 values fail; 1.23 and -4.56 become
  123 and -456 centidiscs; the rounded prediction differs by at most 0.23
  discs over 46 values.
- `tied_asset`: the written asset has identical `i16` values at every
  index and its canonical tied index, and is exactly
  12 × 167,265 × 2 bytes.
- `stage_restart`: a valid stage loads; a mismatched header, a leftover
  `.tmp`, a missing final file, and a damaged body all behave as the design
  requires (the first is reused, the rest are discarded).
- `reproducible`: two fits over the same examples produce identical values
  and learning curves.
- `inspect_output`: a stage with known edge values and counts prints the
  family-relative values and occurrence counts.
- `report_fields`: the rendered report names inputs, constants, stage
  curve and errors, classic-evaluator error, label-quality diagnostic and
  asset hash.
- `planted`: weights are planted only in the two smallest families
  (diagonals 5 and 4, 324 entries), positions are generated for every
  planted configuration with varied other squares, labels come from the
  planted table, and held-out mean absolute error must be below 1.0 disc.

### Intended API

`trainer/src/fit.rs`:

```rust
pub struct Example { pub features: Vec<u32>, pub label: f32 }
pub struct Options { pub step: f32, pub floor: f32, pub patience: usize, pub max_passes: usize }
impl Default for Options { /* production constants */ }
pub struct Fit { pub values: Vec<f32>, pub curve: Vec<(f32, f32)> }
pub fn fit(table: usize, train: &[Example], held: &[Example], options: &Options) -> Fit;
pub fn predict(values: &[f32], features: &[u32]) -> f32;
pub fn quantise(values: &[f32]) -> Result<Vec<i16>, String>;
pub fn canonical(feature: u32) -> u32;
pub fn asset(stages: &[Vec<f32>]) -> Result<Vec<u8>, String>;
pub struct Stage { pub values: Vec<f32>, pub counts: Vec<u32>, pub curve: Vec<(f32, f32)> }
pub fn save_stage(path: &Path, header: &str, stage: &Stage) -> Result<(), String>;
pub fn load_stage(path: &Path, header: &str) -> Result<Option<Stage>, String>;
pub fn inspect(stage: &Stage, family: usize, count: usize) -> String;
pub struct Report { /* inputs, constants, per-stage reports, label quality, asset hash */ }
pub fn report(report: &Report) -> String;
```

The update holds values fixed during a pass. Each example adds its residual
to every selected entry and one to the entry's occurrence count, so
multiplicity is kept. The step is divided by `max(count, floor)`. Fits are
in a fixed example order; the returned values are the best pass by held-out
error.

`canonical` is the trainer-side tied-pair derivation using the engine's
public `pattern` data and `othello_tools::sym`; it is not in the engine.

## RED review round 1 responses

Verdict was **request changes**; every point is addressed. The budget
ruling is 650 as stated; the 450 in the issue text is superseded.

1. `tied_asset` uses centidisc-sized values and asserts every written value
   equals the quantised input at its canonical index. Stage `s` is checked
   separately, so a file that repeats one stage or writes zeros fails.
2. `canonical_pairs`, `canonical_properties` and `canonical_symmetry` are
   added.
   - Edge: index 46,459 has digits 1,0,2,1,0,2,0,0,1,2; the mirror gives
     0,0,2,0,1,2,0,1,2,1, index 35,577. Both map to 35,577.
   - Corner 3x3: transpose maps base positions [0,3,6,1,4,7,2,5,8]. A
     single digit at position 3 (index 59,049 + 27) maps to position 1
     (59,049 + 3).
   - Row 2: reversal maps index 137,781 + 2,187 to 137,781 + 1.
   - Diagonal 8: reversal maps index 157,464 + 2,187 to 157,464 + 1.
   - Corner 2x5: every index in 78,732..137,781 is unchanged.
   - Every index is in its family range, is not larger than its input, and
     is idempotent.
   - The start and three dense bench positions give the same sorted
     `canonical(features)` multiset under all eight `othello_tools::sym`
     transforms; a control asserts the raw multisets differ for at least
     one transform.
3. `damping` uses a rare entry seen three times with label +10 and a common
   entry seen 500 times with label +10, held-out equal to training. The
   test asserts the common value is above 9 and the rare value is at most
   `10 * (1 - (1 - 3 * step / floor) ^ max_passes)`, computed from
   `Options::default()`. The production constants must satisfy it. An
   unseen third entry is exactly zero.
4. `planted` now builds each example from only the instance indexes of
   families 9 and 10, so no other family can absorb the residual. The
   held-out MAE must be below 0.05 discs and below 5% of the mean absolute
   label.
5. `shared` adds the exact system `[0,0,1] -> 5`, `[1] -> 1`, `[0] -> 2`
   with answer `(2, 1)`.
6. `early_stop` uses 50 training examples labelled 10 and 50 held-out
   examples labelled 2. It asserts the returned values are the best pass,
   the curve stops `patience` passes after it, and the run is far shorter
   than `max_passes`.
7. `inspect_output` asserts the relative values +2.57, +0.57 and -2.43 in
   that order, and that `count 0` entries are not listed.
8. `fit_cli.rs` adds the process tests on a 200-game synthetic archive and
   a handwritten journal:
   - an uninterrupted fit writes the asset and report;
   - a fit killed after its first stage file appears is resumed with the
     same command and must produce the same asset bytes and report;
   - the same journal records in reverse order must produce the same asset
     bytes.
9. `split` asserts a game's held-out decision depends only on its move
   bytes and that roughly one game in twenty is held out over 300 games.

Smaller points:

- `quantisation` adds infinity, ±327.67 passing, ±327.68 failing, and an
  error naming entry 0.
- `report_fields` requires the toolchain input and the per-pass curve
  values `1.10` and `0.60`.
- `reproducible` is kept; it is cheap now that the process test exists.

API additions from this review: `Fit.best`, `fit::held_out`, and
`Report.label_quality`. The intended API section above is otherwise
unchanged.

Expected RED failures: `tests/fit.rs` cannot compile without the
`othello_trainer::fit` module; `tests/fit_cli.rs` fails because the `fit`
command does not yet write its asset or report.
