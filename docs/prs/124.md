# Issue 124: Fit, restart, learning report, inspect, asset and pattern::evaluate

## RED (checkpoint 1: fit, restart, report, inspect)

Tests first; no `othello_trainer::fit` module is present.

New `trainer/tests/fit.rs` covers:

- `reference`: a three-entry table and four examples where entry 0 occurs
  twice in one position and entry 1 twice in another. The hand-computed
  least-squares solution is (1.8, 2.8); entry 2 is unseen and must stay
  exactly zero. A fit that counts each position once per entry gives
  (2.5, 4.0) and fails.
- `damping`: three noisy examples for one entry stay within 0.5 discs of
  zero with the production constants; an unseen entry is exactly zero.
- `quantisation`: NaN and out-of-i16 values fail; 1.23 and -4.56 become
  123 and -456 centidiscs; the rounded prediction differs by at most 0.23
  discs over 46 values.
- `tied_asset`: the written asset has identical `i16` values at every
  index and its canonical tied index, and is exactly
  12 × 167,265 × 2 bytes.
- `stage_restart`: a valid stage loads; a mismatched header, a leftover
  `.tmp`, a missing final file, and a damaged body all behave as the design
  requires (the first is reused, the rest are discarded).
- `reproducible`: two fits over the same examples produce identical values
  and learning curves.
- `inspect_output`: a stage with known edge values and counts prints the
  family-relative values and occurrence counts.
- `report_fields`: the rendered report names inputs, constants, stage
  curve and errors, classic-evaluator error, label-quality diagnostic and
  asset hash.
- `planted`: weights are planted only in the two smallest families
  (diagonals 5 and 4, 324 entries), positions are generated for every
  planted configuration with varied other squares, labels come from the
  planted table, and held-out mean absolute error must be below 1.0 disc.

### Intended API

`trainer/src/fit.rs`:

```rust
pub struct Example { pub features: Vec<u32>, pub label: f32 }
pub struct Options { pub step: f32, pub floor: f32, pub patience: usize, pub max_passes: usize }
impl Default for Options { /* production constants */ }
pub struct Fit { pub values: Vec<f32>, pub curve: Vec<(f32, f32)> }
pub fn fit(table: usize, train: &[Example], held: &[Example], options: &Options) -> Fit;
pub fn predict(values: &[f32], features: &[u32]) -> f32;
pub fn quantise(values: &[f32]) -> Result<Vec<i16>, String>;
pub fn canonical(feature: u32) -> u32;
pub fn asset(stages: &[Vec<f32>]) -> Result<Vec<u8>, String>;
pub struct Stage { pub values: Vec<f32>, pub counts: Vec<u32>, pub curve: Vec<(f32, f32)> }
pub fn save_stage(path: &Path, header: &str, stage: &Stage) -> Result<(), String>;
pub fn load_stage(path: &Path, header: &str) -> Result<Option<Stage>, String>;
pub fn inspect(stage: &Stage, family: usize, count: usize) -> String;
pub struct Report { /* inputs, constants, per-stage reports, label quality, asset hash */ }
pub fn report(report: &Report) -> String;
```

The update holds values fixed during a pass. Each example adds its residual
to every selected entry and one to the entry's occurrence count, so
multiplicity is kept. The step is divided by `max(count, floor)`. Fits are
in a fixed example order; the returned values are the best pass by held-out
error.

`canonical` is the trainer-side tied-pair derivation using the engine's
public `pattern` data and `othello_tools::sym`; it is not in the engine.
