# Issue 87: Implement Zobrist hashing and TT depth/domain contract

## RED

Issue: #87 — Implement Zobrist hashing and the TT depth/domain contract.

Tests added in `tests/tt.rs`:

- `zobrist_keys`: the start key is non-zero and deterministic; swapping the
  side-relative colours changes it.
- `bound_cutoffs`: `Exact` always cuts, `Lower` cuts only when
  `value >= beta`, and `Upper` only when `value <= alpha`.
- `strict_depth_and_domain`: a depth-4 heuristic entry does not cut at depth
  3; an endgame entry does not serve heuristic cutoffs and is reusable through
  `endgame_cutoff`.
- `order_hints`: a deeper heuristic entry supplies a move for ordering at a
  shallower depth, not the reverse; endgame entries supply no hint.
- `table_operations`: store/probe work, `clear` empties the table, and a zero
  key is never stored.
- `index_collision`: two keys with the same index always-replace; the full key
  rejects the stale one.

Expected failure:

```text
error[E0432]: unresolved import `othello::tt`
```

The failure is intended: `src/tt.rs` is empty.

## Intended behaviour

- `zobrist(board)` XORs const-fn splitmix64 keys for own and opponent discs.
- `Entry { key, value, depth, flag, domain, mv }` with `Bound`
  `Exact/Lower/Upper`, `Domain` `Heuristic/Endgame`, and `NO_MOVE = 64`.
- `Entry::cutoff(depth, alpha, beta)` is heuristic-only, equal-depth, and
  bound-compatible. `Entry::endgame_cutoff(alpha, beta)` is endgame-only.
  `Entry::move_hint(depth)` returns a heuristic move when `entry.depth >=
  depth` and `mv != NO_MOVE`.
- `Table::new(entries)`, `megabytes(mb)` sizing at 16 bytes per entry,
  always-replace `store`, full-key `probe`, and `clear`.
- A zero Zobrist key is skipped on store and never matches.
- Integration, incomplete-store rules, and TT on/off equivalence are #88/#89.
