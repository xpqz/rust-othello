## RED

### Two collection rules made precise (the design left them implicit)

- **Ply counts placements only.** A pass is not a ply. With ply limit P,
  the positions after 0..P-1 placements are counted.
- **Passes are contracted.** A position whose mover must pass is replaced
  by the passed position (`normalize`), both when counting and for the
  partition's child keys. Nodes are therefore always boards with a legal
  move, or terminal. A book move whose child needs a pass is marked
  `passed`: its value is +v(passed node), the two sign changes cancelling.
  The design's "pass node with one pass move" is this contraction. The
  value helper still handles a pass at the same depth for drop-out
  children.
- Each position counts at most once per game.

### Simplification

The design's second tie rule ("then a book move over a drop-out move") can
never apply: a square is either a book move or a drop-out move, never
both. Ties go to the lower canonical square only.

### API under test (`othello_trainer::book`, new module)

- **Keys and collection:** `Key = (u64, u64)`. `key` (the canonical
  board, `sym::canonical`) and `board` convert both ways.
  `normalize(board) -> (Board, passed)`, and
  `count(games, plies) -> BTreeMap<Key, u32>`.
- **Partition:** `partition(key, nodes) -> Vec<Move>`, in ascending
  square order. `Move { square, child, passed, book }` is `Copy`.
- **Values:**
  - `value(board, depth, search)`: the terminal score, or a pass at the
    same depth, or `search`, which is called only with a legal move.
  - `dropout(key, nodes, depth, search) -> Option<(value, square)>`:
    placements at `depth − 1`, in ascending order.
  - `backup(nodes, drops) -> Result<BTreeMap<Key, Entry>, String>`, where
    `Entry { value, square: Option<u8>, book }` and terminal nodes have
    `square: None`.
- **Pruning:**
  - `reachable(roots: &[(Key, engine_to_move)], entries, removed) ->
    BTreeSet<Key>`.
  - `truncate(roots, entries, counts, mandatory, room_records) ->
    Result<BTreeSet<Key>, String>`. Records are removed in ascending
    (count, zobrist) order, mandatory keys are never removed, and the
    walk is recomputed after each removal.
- **Asset:** `encode(&[(zobrist, square, value)]) -> Result<Vec<u8>, String>`
  writes 11-byte little-endian records sorted by key, clamps the value to
  i16, and rejects duplicate keys and squares of 64 or more.
- **Roots and pilot:**
  - `shuffle(items, seed)`: Fisher–Yates with `Rng::new(seed)`, taking
    `j = next_u64() % (i + 1)` for i from len − 1 down to 1.
  - `roots(games, nodes, plies, n, seed)`: move sequences for movable
    nodes reached at those plies, drawn from the pool sorted by key, each
    taken from the first game that reaches it.
  - `projection(times, nodes, threads, seed) -> (mean_hours,
    upper_hours)`, with the upper bound at the 97.5th percentile of
    10,000 bootstrap resamples.
  - `depth_rule(&[(D, upper)], limit) -> Option<D>`.
- **Policy and header:** `policy()` is a literal `SearchConfig`, not built
  from `..standard()`, so the field `book` added in #155 must be chosen
  explicitly. `Params { min, plies, depth, table }`, and
  `header(params, input)` names every input, including the ProbCut
  `Debug` output, the `eval.bin` hash and the engine commit.
- **Run:** `score(nodes, params, jobs, journal, header)` journals one
  line per node. `build(nodes, journal, roots, mandatory, room_bytes) ->
  (asset, manifest)` reads journal records sorted by key, never in
  append order.
- **CLI:** `othello-trainer book score <dir> <journal> --min N --plies P
  --depth D [--jobs J]`. The `pilot` and `build` subcommands and the
  roots file come in GREEN, alongside these functions.

### Tests (`trainer/tests/book.rs`, 30)

- **Keys and counting:**
  - `key_is_canonical`;
  - `count_once_per_game`;
  - `count_plies_are_placements`;
  - `count_contracts_passes`.
- **Partition:**
  - `partition_counts_unplayed_edges`: the four first moves reach one
    canonical child, so all are book moves though no game played them.
  - `partition_is_complete`: every legal move is listed once, classified
    correctly.
- **Values:**
  - `value_terminal`;
  - `value_terminal_awards_empties`: the reviewer's 10–0 with 54 empty
    gives 6,400;
  - `value_pass_same_depth`: the stand-in search panics on a board with
    no move, and records depths.
  - `dropout_order_and_depth`;
  - `dropout_skips_book_moves`.
- **Backup:**
  - `backup_negamax`;
  - `backup_ties`;
  - `backup_terminal_and_pass`;
  - `backup_needs_dropouts`.
- **Reachability:**
  - `reachable_follows_policy`, both colours;
  - `reachable_removed_key`: one key, removed, stops the walk with the
    engine to move but continues with the opponent to move;
  - `reachable_colour_through_pass`;
  - `reachable_skips_terminal`.
- **Truncation:**
  - `truncate_order_and_roots`: the count order, the zobrist tie-break,
    and a low-count mandatory root that survives;
  - `truncate_keeps_retained_move`;
  - `truncate_mandatory_overflow`.
- **Asset, roots and pilot:**
  - `encode_records`;
  - `shuffle_permutes`;
  - `roots_frozen`: deterministic, distinct, movable, in the node set,
    and an error if too few;
  - `projection_and_rule`.
- **Policy and header:**
  - `policy_explicit`;
  - `header_names_inputs`.
- **Determinism and resume:**
  - `score_deterministic`: 1 worker against 3, and the node order
    reversed, give identical sorted journal lines, asset bytes and
    manifest.
  - `score_resume`: CLI SIGKILL, then a resume with more workers, gives
    identical sorted lines; a changed depth is refused on the header.
