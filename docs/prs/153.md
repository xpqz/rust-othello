## RED

### Two collection rules made precise (the design left them implicit)

- **Ply counts placements only.** A pass is not a ply. With ply limit P,
  the positions after 0..P-1 placements are counted.
- **Passes are contracted.** A position whose mover must pass is replaced
  by the passed position (`normalize`), both when counting and for the
  partition's child keys. Nodes are therefore always boards with a legal
  move, or terminal. A book move whose child needs a pass is marked
  `passed`: its value is +v(passed node), the two sign changes cancelling.
  The design's "pass node with one pass move" is this contraction. The
  value helper still handles a pass at the same depth for drop-out
  children.
- Each position counts at most once per game.

### Simplification

The design's second tie rule ("then a book move over a drop-out move") can
never apply: a square is either a book move or a drop-out move, never
both. Ties go to the lower canonical square only.

### API under test (`othello_trainer::book`, new module)

- **Keys and collection:** `Key = (u64, u64)`. `key` (the canonical
  board, `sym::canonical`) and `board` convert both ways.
  `normalize(board) -> (Board, passed)`, and
  `count(games, plies) -> BTreeMap<Key, u32>`.
- **Partition:** `partition(key, nodes) -> Vec<Move>`, in ascending
  square order. `Move { square, child, passed, book }` is `Copy`.
- **Values:**
  - `value(board, depth, search)`: the terminal score, or a pass at the
    same depth, or `search`, which is called only with a legal move.
  - `dropout(key, nodes, depth, search) -> Option<(value, square)>`:
    placements at `depth − 1`, in ascending order.
  - `backup(nodes, drops) -> Result<BTreeMap<Key, Entry>, String>`, where
    `Entry { value, square: Option<u8>, book }` and terminal nodes have
    `square: None`.
- **Pruning:**
  - `reachable(roots: &[(Key, engine_to_move)], entries, removed) ->
    BTreeSet<Key>`.
  - `truncate(roots, entries, counts, mandatory, room_records) ->
    Result<BTreeSet<Key>, String>`. Records are removed in ascending
    (count, zobrist) order, mandatory keys are never removed, and the
    walk is recomputed after each removal.
- **Asset:** `encode(&[(zobrist, square, value)]) -> Result<Vec<u8>, String>`
  writes 11-byte little-endian records sorted by key, clamps the value to
  i16, and rejects duplicate keys and squares of 64 or more.
- **Roots and pilot:**
  - `shuffle(items, seed)`: Fisher–Yates with `Rng::new(seed)`, taking
    `j = next_u64() % (i + 1)` for i from len − 1 down to 1.
  - `roots(games, nodes, plies, n, seed)`: move sequences for movable
    nodes reached at those plies, drawn from the pool sorted by key, each
    taken from the first game that reaches it.
  - `projection(times, nodes, threads, seed) -> (mean_hours,
    upper_hours)`, with the upper bound at the 97.5th percentile of
    10,000 bootstrap resamples.
  - `depth_rule(&[(D, upper)], limit) -> Option<D>`.
- **Policy and header:** `policy()` is a literal `SearchConfig`, not built
  from `..standard()`, so the field `book` added in #155 must be chosen
  explicitly. `Params { min, plies, depth, table }`, and
  `header(params, input)` names every input, including the ProbCut
  `Debug` output, the `eval.bin` hash and the engine commit.
- **Run:** `score(nodes, params, jobs, journal, header)` journals one
  line per node. `build(nodes, journal, roots, mandatory, room_bytes) ->
  (asset, manifest)` reads journal records sorted by key, never in
  append order.
- **CLI:** `othello-trainer book score <dir> <journal> --min N --plies P
  --depth D [--jobs J]`. The `pilot` and `build` subcommands and the
  roots file come in GREEN, alongside these functions.

## Review response: RED review of `39dd5af`

Amendment 1 approved. Design amendment 2 (`docs/design/book.md`) now
writes into the partition and values sections the rules accepted in the
review: placement-only plies, contracted forced passes (no pass nodes;
+v(child) for a passing book move; the walk's role flips back across a
pass), and the single tie rule. It also records the old-book contract: the
values are offline scores from the recorded evaluator, the build inputs
are kept, and resuming still checks the full journal header.

`trainer/tests/book.rs` now has 36 tests:

1. **A pass in collection.** `count_through_a_pass` uses a real legal game
   with a forced pass and an independent replay oracle (`replay_oracle`).
   - It checks the passed board at k placements, the unpassed board
     absent, and limit k excluding it while k + 1 includes it.
   - The next placement enters only at k + 2.
   - An unfinished prefix counts its final recorded board.
   - `count_terminal_final` counts a terminal final board.
   - `count_plies_are_placements` compares against the oracle's keys.
   - `count_contracts_passes` is renamed `normalize_contracts_passes`.
2. **Drop-out boundaries and asset contents.**
   - `dropout_pass_child` and `dropout_terminal_child` use the refusing
     recorder, against an independent oracle (`stand_in_value`). They
     check the sign, the post-placement depth, the chosen square, the
     exact call list, and that a terminal child makes no call.
   - `artifact_records` includes a terminal node in the input. The
     single record is decoded from the binary and compared with an
     independently computed key, square and value (fresh-table policy
     oracle), and the manifest line must match.
   - `artifact_truncation_keeps_parent`: the truncated build's only
     record is byte-equal to the start's record in the full build, and
     the children are gone from both outputs.
   - `score_deterministic` maps every binary record back to its manifest
     line.
3. **Bootstrap and seeds.**
   - `projection_and_rule` pins mean 0.2222222222222222 and upper bound
     0.4444444444444444. The convention is 10,000 resamples of n draws,
     index `next_u64() % n` from one `Rng::new(seed)`, and the bound
     `sorted[ceil(0.975 R) − 1]`. I reproduced the figures
     independently; neighbouring endpoint conventions give the same
     value.
   - The depth rule is checked with equality at the limit and with the
     highest depth fitting.
   - `shuffle_golden` pins `[0, 2, 9, 4, 3, 8, 1, 5, 6, 7]` for 0..10 with
     seed 150, computed independently.
   - `roots_frozen` compares against an independent Fisher–Yates over
     the oracle-built sorted pool, and checks that each line is the
     first game's prefix.
4. **Resume.**
   - The SIGKILL now lands while units remain: depth rises through
     6, 8, 10, 12 until the kill interrupts real work.
   - A `Drop` guard kills the child on any failure.
   - Completed units are skipped: the `done D scored S` summary is
     checked, and the complete-line prefix of the file is preserved
     byte for byte.
   - A deterministic torn tail is redone.
   - Both resumed journals build the full journal's asset and manifest.
   - A changed header is refused with the journal bytes unchanged.
   - I'll run it in debug and release once GREEN exists.

Contracts these add for GREEN:
- `score` prints a summary line containing `done D scored S`.
- The journal holds one line per node, terminal nodes included.
- Manifest record lines read `{me:016x}:{opp:016x} {square} {value}`,
  with the value clamped to i16, in asset order; header lines start
  with `#`.

Expected failures: unchanged. Only E0432, the missing
`othello_trainer::book`.

  - `key`, `board`, `normalize` and `count`;

  - `pilot` and `read_games`;
  - `write_lines` and `read_roots`.
- **Shared runner.** `score` and `pilot` share `run_units`: a rayon
  pool of `--jobs` threads, one table per thread, cleared before each
  unit, with completed journal IDs skipped.
- **One fix found by the RED tests.** `truncate` makes every mandatory
  key a walk root with the engine to move. Removing a non-mandatory
  record therefore cannot cut a mandatory record off. Without this,
  `truncate_mandatory_overflow` returned an empty book instead of an
  error. In production the mandatory keys (start and gate roots) are walk
  roots already. A mandatory key that is not a movable node is an error.
- **`trainer/src/main.rs`:** `othello-trainer book score|roots|pilot|build
  <dir> <path>`. Options: `--min` (10), `--plies` (30), `--depth`
  (20), `--table` (`MAX_ENTRIES`), `--jobs`, `--count` (400),
  `--seed` (151), `--room` (179,576), `--depths` (18,19,20) and
  `--limit` (36), plus `--roots`, `--asset` and `--manifest` for
  `build`.
  - `score` prints `nodes N done D scored S elapsed`.
  - `build` takes the start position and every root, each with both
    roles, as walk roots and mandatory records.
- **`trainer/tests/book.rs`:** 37 tests, the 36 approved plus
  `roots_file_round_trip` for the roots file that `build` reads.
- **Size.** The trainer is at 1,825 of 2,000 lines. The builder took
  about 675 lines (`book.rs` and the CLI), against my design estimate of
  250–350. rustfmt's expansion of struct literals and the four
  subcommands account for most of it; I removed the duplicated
  pool/journal code between `score` and `pilot`.
