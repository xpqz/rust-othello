# Issue 90: Implement exact endgame solver with domain and solved semantics

## RED

Issue: #90 — Implement the exact endgame solver with domain and solved
semantics.

Tests added in `tests/search.rs`:

- `solve_terminal`: `solve` returns `terminal_score(final_score)` on a
  terminal board.
- `solve_pass`: a no-move root recurses through `pass` and negates.
- `solve_matches_reference`: a corpus endgame with at most 6 empties matches
  an independent exact minimax in the test.
- `solver_root_trigger`: `search_limited` with `endgame_threshold = 12` on
  that board returns `Complete`, depth 0, `solved = true`, and the exact score.
- `solver_endgame_domain`: `search_tt` on the same board leaves an
  `Endgame`, depth-0 entry under the root key.

Expected failure:

```text
error[E0432]: unresolved import `othello::solver::solve`
```

The failure is intended.

## Intended behaviour

- New `src/solver.rs`: `solve(board, alpha, beta, ctx) -> Option<i32>` is
  depth-free, uses `terminal_score`, passes without cost, orders with the
  existing moved ordering, probes/stores endgame entries, and propagates
  `None`.
- `search_limited`/`search_inner` use the solver only at the root when
  `empty_count <= endgame_threshold`; #90 runs the exact solve directly,
  #91 adds the WDL narrow pass. No interior solver calls.
- A completed exact root sets `status = Complete`, `depth = 0`,
  `solved = true`. Heuristic results stay `solved = false`.
- Endgame entries have `domain = Endgame`, `depth = 0`; heuristic entries
  remain `Heuristic`.

## Budget

- Adds a solver module and a small root trigger. The search budget is already
  tight; the GREEN phase will propose a solver allocation/reallocation rather
  than hide lines elsewhere.
