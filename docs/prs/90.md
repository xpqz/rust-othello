# Issue 90: Implement exact endgame solver with domain and solved semantics

## RED

Issue: #90 — Implement the exact endgame solver with domain and solved
semantics.

Tests added in `tests/search.rs`:

- `solve_terminal`: `solve` returns `terminal_score(final_score)` on a
  terminal board.
- `solve_pass`: a no-move root recurses through `pass` and negates.
- `solve_matches_reference`: a corpus endgame with at most 6 empties matches
  an independent exact minimax in the test.
- `solver_root_trigger`: `search_limited` with `endgame_threshold = 12` on
  that board returns `Complete`, depth 0, `solved = true`, and the exact score.
- `solver_endgame_domain`: `search_tt` on the same board leaves an
  `Endgame`, depth-0 entry under the root key.

Expected failure:

```text
error[E0432]: unresolved import `othello::solver::solve`
```

The failure is intended.

## Intended behaviour

- New `src/solver.rs`: `solve(board, alpha, beta, ctx) -> Option<i32>` is
  depth-free, uses `terminal_score`, passes without cost, orders with the
  existing moved ordering, probes/stores endgame entries, and propagates
  `None`.
- `search_limited`/`search_inner` use the solver only at the root when
  `empty_count <= endgame_threshold`; #90 runs the exact solve directly,
  #91 adds the WDL narrow pass. No interior solver calls.
- A completed exact root sets `status = Complete`, `depth = 0`,
  `solved = true`. Heuristic results stay `solved = false`.
- Endgame entries have `domain = Endgame`, `depth = 0`; heuristic entries
  remain `Heuristic`.

## Budget

- Adds a solver module and a small root trigger. The search budget is already
  tight; the GREEN phase will propose a solver allocation/reallocation rather
  than hide lines elsewhere.

## Review responses

- Added a documented seeded sample (seed `0x5A3A11`): 20 positions at 6-8
  empties in `solve_sample`, and 1,000 at 6-10 empties in the `#[ignore]`
  `solve_sample_deep` for `cargo test --release -- --ignored`.
- Added `solver_interior_is_heuristic`: a root above the threshold whose
  search crosses it stays `solved = false`, matches the threshold-0 heuristic
  score, and differs from the exact score (the fixture is selected to ensure a
  difference).
- Added both domain-wall integrations: heuristic garbage entries do not affect
  the solver, and endgame garbage entries do not affect heuristic search.
- The hand-checked 12-empty positions are part of #93's benchmark scope; noted
  there rather than duplicated here.
- GREEN will document `depth = 0` on `SearchResult` as the exact-solve
  convention.

## Round 2

- `solver_interior_is_heuristic` now searches to depth 3 at 8 empties with
  threshold 7, so children cross the threshold but leaves stay heuristic; it
  selects a fixture where the shallow heuristic score differs from the exact
  score.
- `heuristic_ignores_endgame_entries` uses the same non-terminal-reaching
  depth, so the garbage endgame entries are the only possible difference.
- `solve_sample_deep` uses the release-only `cfg_attr` pattern. If the full
  1,000-position run proves too slow for a default release run, GREEN will
  report that and keep an explicit ignored invocation.

## Round 3

- `solver_interior_is_heuristic` now uses one `limits = depth(3)` value for the
  fixture selection, the thresholded search, and the threshold-0 comparison,
  so the assertions cannot drift to a terminal-reaching depth.
