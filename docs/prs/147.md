# 147: ProbCut v2 engine check behind the switch

Epic #144; design `docs/design/probcut2.md` revision 3 (approved in #145).

## RED

### API the tests fix (GREEN implements it)

In `othello::search`:

- `pub struct ProbCut { t: u32, s0: i32, s1: i32, s2: i32, a_milli: i32,
  b: i32, shallow: u32, d_min: u32, d_max: u32, e_min: u32, e_max: u32 }`,
  `Copy`, `Debug`, all fields public. `shallow` selects the shallow rule:
  0 is `2·⌊d/4⌋ + (d mod 2)` (from `d = 3`), `k > 0` is `d − k` (needs
  `d > k`). This field is a small addition to the design, which has the fit
  choose among exactly these rules; the engine must accept each so the
  tuning tools can inject them.
- `ProbCut::sigma(&self, d, e) -> i64`:
  `clamp(ceil((s0 + s1·e + s2·d) / 100), 1, 2·EVAL_BOUND)`.
- `shallow_depth(&ProbCut, d) -> Option<u32>`: the rule's `s`, or `None`
  where `1 ≤ s < d` fails.
- `probcut_bounds(&ProbCut, d, e, alpha, beta) -> (i64, i64)`: the
  thresholds `H = ceil((β + m − b)·1000 / a)` and
  `L = floor((α − m − b)·1000 / a)`, with `m = ceil(min(t, 400)·σ / 100)`,
  `a = clamp(a_milli, 500, 1500)`, `b` clamped to `±EVAL_BOUND`.
- `probcut(board, d, alpha, beta, ctx) -> Option<Option<i32>>`: the check
  `negamax` calls after the TT probe; outer `None` on cancellation, inner
  the cut bound (`β` high, `α` low) or no cut. The rectangle and shallow
  rule are checked before any coefficient arithmetic or node.
- `SearchConfig::probcut: Option<ProbCut>`, `None` in `standard()`.
- `Ctx`: `pub probcut_tries: u64`, `pub probcut_cuts: [u64; 2]` (high,
  low) and `set_node_limit(&mut self, u64)`.

No `ProbCut::FITTED` here: it arrives with the fit (#146). The `pc:<t>`
agents need a model, so they move to the tuning issue.

### Tests written

`tests/probcut.rs` (new). Constructed checks use a model with σ = 1,
`t = 0`, slope 1, intercept 0, so the thresholds are the window itself,
and a rectangle at depth 6 only, so that neither the probe's nodes (depth
≤ 2) nor the node's children (depth 5) check: the probe's verdict is then
the full-width depth-2 value `v`'s.

- `cut_high`: window `(v − 1, v)` cuts high at `v`; one try, one high cut.
- `cut_low`: window `(v, v + 1)` cuts low at `v` (the high query's valid
  opposite return), and `(v − 1, v)` cuts high at `v` (the low query's
  valid opposite return); counters per direction.
- `no_cut`: window `(v − 10, v + 10)`: one try, no cut.
- `margin_rounds_up`: σ = 10, `t = 1.00`: `(v − 11, v − 10)` cuts,
  `(v − 10, v − 9)` does not.
- `outside_rectangle`: each of the four bounds, and an empty rectangle:
  no cut, zero nodes, zero tries.
- `unreachable_thresholds`: infinite window, and windows at
  `±EVAL_BOUND`: no probe, zero nodes.
- `shallow_rules`: rules 0, 4, 6 at depths 0–40; a depth without a valid
  shallow depth runs no check and no node.
- `cancelled_probe`: node limit 1 inside the probe returns `None`.
- `threshold_limits`: `probcut_bounds` and `sigma` against an exact i128
  reference over every combination of coefficients, slope and intercept
  at the `i32` limits and around the clamps, `t` up to `u32::MAX`, depth
  and empties 0 and 64, and windows including `±INF` and small negative
  numerators.
- `empty_rectangle_is_off`: a model with an empty rectangle gives
  identical results (values, moves, nodes) to `None`.
- `standard_is_off`.
- `cleared_table_is_full_width`: a table used with ProbCut on, then
  cleared, gives exactly the fresh full-width result.
- `selective_search_cuts`: with a permissive model, depth-8 searches use
  fewer nodes and return legal moves.
- `legal_under_limits`: ProbCut on with node limits 1 and 500 and times
  0 and 20 ms: legal moves.
- `exact_unaffected`: identical results and nodes with ProbCut on at 5–12
  empties (corpus) and at 18 (two moves from the corpus position with 20).

`tools/tests/baselines.rs`: `frozen_off` (both frozen baselines are
`probcut: None`).

`gui/src/main.rs`: `setting_change_clears_table` (a new
`App::engine_config` builds the search configuration and clears the
table when it differs from the one the table served; an unchanged setting
keeps an entry, a changed threshold drops it).

## Review response: RED review of `c5be916`

1. **Boundary expectations corrected** (`unreachable_thresholds`): the
   two narrow edge windows now assert the valid opposite cuts
   (`(EVAL_BOUND, EVAL_BOUND + 1)` cuts low at `EVAL_BOUND`;
   `(−EVAL_BOUND − 1, −EVAL_BOUND)` cuts high at `−EVAL_BOUND`), and each
   side's skip is tested on its own with `(−INF, EVAL_BOUND + 1)` and
   `(−EVAL_BOUND − 1, INF)`: no cut and no node. No engine bypass.
2. **Recursive probes** (`nested_probes`, new): constant evaluation, the
   start position, depths 3–12, zero margin; the depth-12 check probes
   depth 6, whose node checks and probes depth 2: exactly 2 tries and 2
   high cuts, top-level result 0. Suppressing ProbCut inside probes gives
   one try and fails it.
3. **Exact mode** (`exact_unaffected`): the model now uses the gap-1 rule,
   eligible at the solver's nominal depth 2; the test first shows it tries
   in heuristic mode at depth 2, then that the public `solve` makes zero
   tries with an unchanged value, and that `search_tt` results and nodes
   are identical. Fixtures: corpus at 5–12 empties plus 18 and 14 played
   from the corpus position with 20. Mutation check on the GREEN draft:
   removing the `!exact` guard makes this test fail.
4. **Cancellation through the caller** (`cancelled_parent`, new):
   `negamax` with a table and a node limit of 3 stops inside its node's
   probe, returns `None`, has made one try, and stores nothing for the
   node. **Root contract** (`root_contract`, new): with ProbCut on, a node
   budget one past iteration 5's total returns iteration 5's move, score
   and depth as `Partial`; a budget of 1 returns `Fallback`.
   `cut_high` now also asserts the probe's nodes are counted in the
   context.
5. **Independent fields** (`independent_fields`, new): ten models with
   each coefficient alone, mixed signs, fractional σ, and slope and
   intercept varied apart, against the exact reference for σ and both
   thresholds; two pinned values that a swapped depth/empties coefficient
   (281 against 22) or a swapped slope/intercept (−1125 against −700)
   would change. `threshold_limits` now compares `sigma` with the
   reference value. `outside_rectangle` adds the inclusive edge
   (`e_min = e_max =` the node's empties cuts) and depths 13, 1000 and
   `u32::MAX` outside the rectangle with extreme coefficients: no
   arithmetic, no node.

Also: full-width oracles and off fixtures use an explicit
`probcut: None` (`off()`); names shortened to two underscores or fewer
(`empty_rectangle_off`, `cleared_table_full`, GUI `setting_clears_table`);
the design's step 3 now records σ rounded up, which the #146 fitter
already uses.

The revised tests were validated against an uncommitted GREEN draft in a
separate worktree: 19 of 19 pass in release and debug. On this branch
they still fail to compile on the missing API (expected for RED).

## GREEN (`f848581`)

### What changed

- `src/search.rs`: `ProbCut` (fields as in RED, documented), `ceil_div`,
  `ProbCut::sigma` (depth and empties capped at 64 before the i64
  products), `shallow_depth`, `probcut_bounds`, and `probcut`. The check
  returns before any arithmetic or node when ProbCut is off, the shallow
  rule has no valid depth, or the node is outside the rectangle; then it
  counts a try, computes both thresholds and probes each only when it lies
  within `±EVAL_BOUND` (so the `i32` conversion is exact), high first.
  Probes are ordinary `negamax` calls (recursive, option B) sharing the
  context's node count, limits and table. `negamax` calls it after the TT
  probe, in heuristic mode only (`!exact`); a cut returns its bound without
  storing. `SearchConfig::probcut` (`None` in `standard()`); `Ctx` counters
  and `set_node_limit`; the two internal `Ctx` literals now use struct
  update from `Ctx::new`.
- `gui/src/main.rs`: `App::engine_config` builds the configuration and
  clears the table when the threshold the table served (`served`) differs;
  `start_engine` calls it on the engine-launch path.
- `probcut: None` added to every full `SearchConfig` literal:
  `tests/agents.rs`, `tests/ordering.rs`, `tests/search.rs` (3),
  `tools/src/baselines.rs` (both frozen baselines),
  `tools/examples/search_rate.rs`, `trainer/examples/occurrence.rs`.
- `tests/probcut.rs`: `cancelled_parent` holds the context in a block
  instead of `drop(ctx)` (clippy `drop_non_drop`); the assertions are
  unchanged.
