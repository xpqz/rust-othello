# Issue 116: Resumable job journal and parallel match runner

## RED

Read the PLAN interruptible-jobs requirements, the optional-parallel-match
rules, and the ProbCut fitting/enablement sections.

New `tools/tests/journal.rs` covers:

- `Journal` header creation/verification, append/flush, completed IDs, and a
  truncated trailing line being discarded and redone;
- SIGKILL and identical-command resume producing the same `report` bytes as
  an uninterrupted run (6 pairs, `--jobs 2`, fixed nodes);
- header mismatch rejection;
- identical sorted game lines and reports for `--jobs 1` vs `--jobs 3`;
- `--pair-range` chunks combining to the full report, with duplicate,
  mixed-configuration and missing-pair rejection;
- load voiding only for time-controlled pairings (node pairings never void),
  and replay after a voided journal is resumed;
- bad `--jobs`, `--pair-range`, and empty `report` invocations.

Expected failure:

```text
error[E0432]: unresolved import `othello_tools::journal`
```

## Intended design

- `Journal::open(path, header)` owns a line-atomic, flushed append log; existing
  headers must match, completed unit IDs are returned, and a torn final line is
  truncated.
- Match units are pairs. Both game lines carry run/pair/game seeds, score,
  points for agent A, job count and sampled load.
- With `--out`, complete non-void pairs resume; a pair with one game or a void
  record is replayed. `--jobs N` uses scoped workers; pair results are sorted
  before reporting.
- `report` requires matching headers, rejects duplicate pairs across journals,
  excludes void time pairs, and fails with the missing pair list.
- Without `--out`, stdout output remains the existing summary plus game logs.

## Budget

Tools is 639/1,000 before this issue; the new journal and runner are expected
to fit comfortably. Final counts recorded in GREEN.

## RED review responses

- Added `--max-load X` (default job count, recorded in the header). All
  match tests pass `--max-load 1000`; the forced-void fixtures write load
  1001 so replay is machine-load independent.
- Kill test now asserts `SIGKILL` via `ExitStatusExt::signal() == Some(9)`
  and fewer than 12 game lines before resume; it uses a larger node budget to
  make the kill window reliable.
- Added a match-level half-pair test: one complete game plus a torn line is
  discarded, the pair is replayed, and the final journal has each pair's two
  games exactly once.
- Header mismatch now also covers different nodes, agent and opening file.
- A short run asserts progress text on stderr.

## RED review round 2 responses

- Kill test no longer replays a different node budget into the reference
  journal; the 20,000-node reference has its own run and `replace_arg` is used.
- Header mismatch now asserts the `header` error for nodes, agent and opening
  content. The opening test runs once with a copied file, swaps two whole
  legal opening lines in place, and re-runs the identical command/path.
