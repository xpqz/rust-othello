Issue: #83 — Implement cancellation contract, fallback, and status.

Tests added in `tests/search.rs`:

- `deadline_zero_falls_back`: `time_ms = 0` on the start position returns
  `Fallback`, depth 0, `solved = false`, the static evaluation, and a legal
  best move.
- `node_limit_partial`: a node budget large enough for depth 1 but not depth 2
  returns `Partial`, the depth-1 score, a completed depth of 1, and
  `solved = false`.
- `node_limit_fallback`: a one-node budget returns `Fallback`, depth 0, the
  static evaluation, and a legal best move.

Expected failure:

```text
error[E0432]: unresolved import `othello::search::search_limited`
error[E0560]: struct `SearchLimits` has no field named `max_nodes`
```

The failure is intended: cancellation and the full limits do not exist yet.

## Intended behaviour

- `SearchLimits { max_depth, time_ms, max_nodes }`; `time_ms = 0` is already
  expired, `max_nodes = 0` means no node limit, and positive limits cancel at
  the next node or iteration check.
- `search_limited` preselects the lowest legal fallback and static score
  before searching. If no iteration completes it returns `Fallback` with that
  fallback and the static score; if one or more complete before cancellation it
  returns the last completed iteration with `Partial`; otherwise `Complete`.
- `negamax` returns `None` on cancellation and propagates it immediately.
  `Ctx` carries the node counter, node limit, and deadline; `Ctx::new` remains
  the unlimited constructor used by the existing search tests.
- The existing unlimited `search` and `search_iterative` keep their behaviour.
- The endgame WDL/exact solver branch, `solved = true`, and threshold
  early-stop are Phase 6, not #83.

## Review responses

- Added `complete_status`: depth 3 with `NO_DEADLINE` and `max_nodes = 0`
  returns `Complete`, depth 3, the direct depth-3 score, `solved = false`, and
  a legal best move.
- Defined an explicit `NO_DEADLINE` sentinel (`u64::MAX`) in the intended
  API; the node-limit tests no longer use wall-clock time. `time_ms = 0`
  remains expired.
- Node-limit semantics are inclusive: a search that visits exactly
  `max_nodes` nodes completes, and the attempt to visit node `max_nodes + 1`
  aborts. Added `node_limit_boundary` with `max_nodes = depth_one.nodes`.
- `node_limit_partial` now also asserts `best == search_iterative(board, 1)`.
- GREEN will add `SearchLimits::depth(d)` and update the two
  `SearchLimits { max_depth }` literals in `tests/agents.rs` and the two
  agent constructors in `tools/src/main.rs`; `search_agent` switches to
  `search_limited`.
