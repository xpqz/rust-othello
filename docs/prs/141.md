## Step 0: tooling and baseline (no engine change, no test stage)

- `tools/examples/exact_bench.rs` (new example; not counted in the
  tools budget). From each game of
  `docs/tuning/speed_135_match.journal` it takes the first position
  with exactly N empties and a legal move, by replaying the recorded
  moves and passes: all 200 games for N = 14, every second game (100)
  for N = 16. Each is solved once per round through `search_tt` with
  `endgame_threshold` set to N, full-size table cleared before each
  solve and the clearing not timed. One untimed warm-up pass over the
  14-empties positions, then five rounds per workload. Output: every
  position's board, move and score in round 0, each round's nodes and
  time, and per workload the node total, minimum, median, maximum and
  spread. It asserts that every solve reports `solved` and that node
  totals do not vary between rounds.
  Two deviations from the issue text, both for run time: the 16-empties
  workload uses every second game (a full run is then about a minute,
  not two), and there is a warm-up pass because the first round was
  otherwise 6 to 17% slower than the rest.
- `docs/tuning/exact_profile_141.log`: the evidence behind the epic,
  committed. The sampled profile of 16-empties solves, the counters by
  number of empties, and mean solve times from 10 to 18 empties, each
  with how it was taken. These came from scratch copies with
  instrumentation; they are evidence for choosing the steps, not gate
  measurements.
- `docs/tuning/exact_141_bench_baseline.log`: one run of the tracked
  tool on the unchanged engine, tools release profile. 14 empties:
  31,419,132 nodes, minimum 2,471.2 ms (spread 4.0%); 16 empties:
  96,631,319 nodes, minimum 7,614.9 ms (spread 14.1%). The machine was
  not quiet and neither spread is inside 3%; this run fixes the node
  totals and the positions' scores. Timing baselines are taken
  alongside each step's after-runs, alternating.

## Step 1 RED: the last empty square

Intended behaviour: an exact node whose position has one empty square
returns the exact result directly: the mover plays the square if that
flips anything; otherwise the opponent does if that flips anything;
otherwise the game is over and the score is the final one with the
empty square awarded to the winner. No child call, no move generation,
no table probe or store. The value returned is the exact value
whatever window was passed, which satisfies the fail-soft contract.

Node accounting changes with it: the node that meets the last square
is counted, and nothing below it is. Today the same position costs 2
nodes when the mover can play, 3 when the mover passes and the opponent
plays, and 1 when nobody can. So `SearchResult::nodes` and `max_nodes`
count fewer nodes for the same exact search; results are unchanged.
