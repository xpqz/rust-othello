## Step 1 RED: the last empty square

Intended behaviour: an exact node whose position has one empty square
returns the exact result directly: the mover plays the square if that
flips anything; otherwise the opponent does if that flips anything;
otherwise the game is over and the score is the final one with the
empty square awarded to the winner. No child call, no move generation,
no table probe or store. The value returned is the exact value
whatever window was passed, which satisfies the fail-soft contract.

Node accounting changes with it: the node that meets the last square
is counted, and nothing below it is. Today the same position costs 2
nodes when the mover can play, 3 when the mover passes and the opponent
plays, and 1 when nobody can. So `SearchResult::nodes` and `max_nodes`
count fewer nodes for the same exact search; results are unchanged.

### The actual experiment: hints only from the full-score pass

How the writing pass is told apart, without inferring it from the
bound: `Ctx` gets a flag that `wdl_root` sets for the duration of the
win/draw/loss pass and clears afterwards. Every endgame entry stored by
`negamax` and by `root` records that flag in its `depth` field, which
endgame entries otherwise leave at 0 and which `endgame_cutoff` does
not read: 0 for the win/draw/loss pass, 1 for the full-score pass
(and for a direct `solve`). In exact search the ordering hint is the
entry's move only when the entry is an endgame entry with `depth == 1`.
Values are reused exactly as before, from either pass. The hint can
therefore come only from an earlier visit in the full-score pass
itself: a transposition, or the null-window probe that precedes a
re-search.

It is a scratch build, on top of the step 4 ordering candidate so that
the comparison isolates the hint; the exact diff is committed as
`docs/tuning/exact_141_step4_hint_full_pass.patch` (no inlining
attributes; 21 changed lines). Nothing of it is in the engine. In that
scratch copy `solver_reuses_endgame_bounds` passes; one other test
fails, `solver_endgame_domain`, because it asserts that endgame entries
