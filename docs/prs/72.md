# Issue 72: Implement minimal evaluation in centidiscs

## RED

Issue: #72 — Implement minimal evaluation in centidiscs.

Tests added in `tests/eval.rs`:

- `start_is_zero`: the start position has equal table sums and equal disc
  counts, so it evaluates to 0.
- `single_disc_values`: eight squares with one disc and no opponent pin the
  table orientation and values: a1 200 (corner 100 + 100 for the disc), b1 80,
  b2 50, c1 110, d1 105, c2 98, d2 98, c3 99.
- `mixed_table_sum`: `me = a1 | h8`, `opp = b1 | g8` gives `240`, since the
  positional difference is `240` and the disc difference is `0`.
- `antisymmetry_and_bounds`: over 100 seeded playouts, `evaluate(b) ==
  -evaluate(b.pass())` and every value is inside `[-EVAL_BOUND, EVAL_BOUND]`.
- `overflow_asserts` (debug): a full-board input whose raw sum is `6512`
  trips the `"out of bounds"` assertion.
- `overflow_clamps` (release): the same input returns `EVAL_BOUND`.

Expected failure:

```text
error[E0432]: unresolved import `othello::eval::evaluate`
```

The failure is intended: `src/eval.rs` is empty.

## Intended behaviour

- `evaluate(board)` is the positional table sum over own discs minus the
  opponent's, plus `SCORE_SCALE` per disc of difference, all in centidiscs.
- The table is the Phase 2 table from `DESIGN.md`: corners `100`, X/C squares
  negative, inner squares `-1` to `-2`. It is symmetric under board reflection,
  so rank/file orientation cannot change a value.
- The raw sum is asserted inside `EVAL_BOUND` in debug builds and clamped in
  release builds. The accepted tradeoff is that a heuristic `+6400` can
  outrank a small proven win; `score` documents this.
- The function is antisymmetric under `pass`, with no side-to-move term.
- `SearchConfig` wiring lands in #73; this issue exposes the plain
  `fn(Board) -> i32` the config will store.
- Phase 2 deliberately keeps the design table's static X/C values. Dynamic
  corner risk is a Phase 7 feature (#96); this function is the frozen Phase 2
  baseline that Phase 7 must beat.
- `evaluate` is for non-terminal positions; terminals use
  `terminal_score`. The bounds test skips terminal boards, while the explicit
  overflow tests pin the debug assertion and the release clamp.
