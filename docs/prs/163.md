## Pre-registration (binding)

- **Pinned worktree** at the `main` commit that merges this setup. The
  release build, `cd tools && cargo build --release`, records its binary
  SHA-256 in the run logs before any game. Both runs use that binary, and
  builds use the worktree's own target directory.
- **Pilot**, run first, about 45 min:

  ```sh
  env -u OTHELLO_TOOLS_ELAPSED_MS -u OTHELLO_TOOLS_LOAD \
  othello-tools match --a pc:80:3000 --b pc:80:3000 \
    --openings bench/openings_tune.txt --pairs 50 --seed 1630 \
    --jobs 4 --max-load 6 --out docs/tuning/clock_pilot.journal
  ```

  - **C** is `clock_time`'s `C_ms` on the completed pilot journal: the
    mean of the `black_ms` and `white_ms` fields over all 200
    side-games, rounded down to a whole second.
  - The pilot journal, log and C are committed to this issue's notes
    before any gate game. C is never recomputed from gate data.
- **Gate**, one look, about 6 h:

  ```sh
  env -u OTHELLO_TOOLS_ELAPSED_MS -u OTHELLO_TOOLS_LOAD \
  othello-tools match --a pc:80:c<C> --b pc:80:3000 \
    --openings bench/openings_time.txt --pairs 400 --seed 163 \
    --jobs 4 --max-load 6 --out docs/tuning/clock_gate.journal
  ```

  - The book is off on both sides.
  - The same command resumes after an interruption. Void pairs above load
    6.000 are replayed by the tool, with their events logged to stderr,
    which the run log keeps.
- **Rule:** enable the clock allocator for play only if both hold:
  - the lower end of the 95% pair-bootstrap interval of a's score, from
    `othello-tools report` (10,000 resamples, run seed), is above 0.500,
    under the degeneracy policy;
  - equal-time holds: `clock_time` reports a's mean charged ms per game
    at most 1.05 × b's, over all accepted pairs, expired moves and flagged
    games included.

  If only the score passes, the result is reported as a comparison at
  these controls, with no equal-time claim, and the allocator stays off.
  Otherwise it stays off and the result is recorded. No other constants,
  clocks or openings are tried on this set.
- **Reported, not gated:**
  - both realized means and maxima;
  - the paired difference and its interval, `clock_time --seed 163`;
  - flags per agent and colour;
  - void events counted from the run log, as observed log events.
- **If enabled:** CLI play and the GUI move from a flat 3 s per move to a
  clock of C per game, in a follow-up issue.

## Setup review response

- **One validated pair set (major).** `clock_time` is restructured
  around a pure `analyse(header, records, a, b, pairs)`. It refuses:
  - a header whose `a`, `b` or `pairs` differ from the registered values
    given as `--a --b --pairs`;
  - a control other than `time` or `clock`;
  - a record outside the declared range, or a duplicate id;
  - anything short of games 0 and 1 of every pair;
  - a record whose saved load is above the header's `max_load`, the
    report's rule; both are stored to three decimals.

  Every statistic, including totals, maxima, flags, the paired
  difference and C, comes from that one validated set. The pilot
  therefore needs exactly 50 complete pairs, and the gate 400.
- **Inclusive 5% (major):** per-pair totals are summed in `u128`, and
  equal-time is `20·a ≤ 21·b` on the integer totals. Floating point is
  used only for display and the bootstrap.
- **Unit tests in the example**, run by `cargo test` through
  `[[example]] test = true` in `tools/Cargo.toml` (4 passed):
  - `sums_by_agent`: per-agent attribution across colours, maxima and
    flags;
  - `refuses_bad_sets`: duplicate, incomplete (3 of 4 games),
    overloaded (6.001 > 6.000, with 6.000 accepted), out of range, wrong
    agent, wrong pair count and depth control;
  - `equal_time_inclusive`: totals 44,100,378 against 42,000,360 hold,
    and one ms more fails;
  - `pilot_rounds_down`: a side mean of 52,249.75 ms gives C = 52,000.
- **Run provenance:** both registered commands start with
  `env -u OTHELLO_TOOLS_ELAPSED_MS -u OTHELLO_TOOLS_LOAD`.
- **Checkpoint commands:**
  - pilot: `clock_time docs/tuning/clock_pilot.journal --a pc:80:3000
    --b pc:80:3000 --pairs 50`;
  - gate: `clock_time docs/tuning/clock_gate.journal --a pc:80:c<C>
    --b pc:80:3000 --pairs 400 --seed 163`.
- **Checks:** `scripts/check.sh` exit 0, 455 passed, 0 failed, 15
  ignored.
- **Open (user, Nov 18):** the user pointed out that the allocation
  constants are untested guesses and the gate gets one look per opening
  set. A pre-registered tuning stage before the gate is proposed to them;
  their answer may amend this registration.

  the saved header's openings path and hash, seed, control, engine commit

## Registration amendment 2: early stopping required, non-inferiority gate

Committed before the night run starts (scheduled for 22:00 Nov 18), so
before any tuning or gate game. It changes no command. It amends the pick
and the gate rule (`docs/design/time.md` amendment 2).

  enables `pc:80:c<C>v<pick>` for play if the lower end of the 95%

    controls.
