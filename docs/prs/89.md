# Issue 89: Add corpus and TT/ordering tests

## RED

Issue: #89 — Add corpus and TT/ordering tests.

Corpus:

- `bench/corpus.txt` holds 23 positions: 12 midgame, 8 endgame (<=12 empties),
  one pass root, and two terminals. Each line is `me opp expected` in hex
  bitboards and centidiscs.
- Provenance is in the header: normal positions use the cold depth-4 score
  with the Phase 5 evaluator; pass roots store the negated depth-4 score of
  `pass(board)`; terminals use `terminal_score(final_score(board))`.

Tests added in `tests/search.rs`:

- `corpus_frozen`: parses at least 20 positions, covers midgame, endgame,
  pass, and terminal, and recomputes every expected score.
- `corpus_tt`: every non-terminal corpus position matches its expected score
  through `search_tt` at depth 4.
- `corpus_preload`: preloading shallow (depth 1-3) exact entries does not
  change the depth-4 score, proving deeper entries only order.
- `corpus_ordering_nodes`: ordered search uses at most 60% of unordered nodes
  across the corpus at depth 4.

Expected failure:

```text
error[E0560]: struct `SearchConfig` has no field named `ordering`
```

The failure is intended: ordering is always on until this issue adds the
benchmark switch.

## Intended behaviour

- Add `ordering: bool` to `SearchConfig`; `standard()` sets it true. With it
  false, root and interior nodes use natural square order.
- The TT tests use the existing strict equal-depth contract; preloaded
  shallower entries cannot cut.
- The corpus is deterministic data; provenance notes when it must be
  regenerated (Phase 7 evaluator changes).

## Issue updates

## Review responses

- `corpus_preload` now preloads each root child (interior) with garbage
  `Exact ±6400` entries at depths 1-2, where a depth-4 search uses depth 3, so
  only ordering may touch them; the score must be unchanged.
- Regenerated the corpus sparsely across distinct playouts: 12 midgames with
  at least 20 discs, 8 endgames with <=12 empties, one pass root, two
  terminals. `corpus_frozen` classifies on discs, so the 4-disc opening cannot
  count as midgame.
- Added `corpus_tt_nodes` (TT <= 80% of cold nodes as an initial target) and
  `corpus_abort_store` (abort at 20 nodes, then a full depth-4 search on the
  same table must match cold).
- The ordering switch is exposed as `tools match --no-ordering`; the tools run
  line will record `ordering false`. Added the RED tools test for it.
- The corpus header now says the expected values are regression snapshots, not
  an independent oracle, and that Phase 6 may give endgame lines exact
  test-side values.
