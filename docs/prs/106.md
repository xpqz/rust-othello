# Issue 106: Make play use the search engine

## RED

`tests/cli.rs::play_opponent_is_search` feeds one Black move and asserts the
White response took at least 500 ms and the game reached the next prompt. The
current greedy opponent answers almost instantly, so the test fails.

Expected failure:

```text
White responded too quickly to be the search agent
```

## Intended behaviour

- `play` constructs
  `search_agent(SearchConfig::standard(), SearchLimits::new(64, 1000, 0))`.
- Human move validation, board printing, passes, and final score stay
  unchanged.
- The old full-game test simulated the greedy White opponent and is obsolete;
  the manual demo will exercise a complete search-agent game.
- README/demo score updated after the new game.

## Budget

The play-agent line is replaced one-for-one; engine stays at 999/999.

## Review responses

- `play_opponent_is_search` now requires at least two `Black to move` status
  lines (or `Game over`), so the initial board alone cannot satisfy it.
- Added `play_complete_game`, release-ignored: it drives the CLI interactively,
  reads each Black `legal:` list, answers with the first legal square or
  `pass`, and checks a readable `Game over` with at most 64 total discs.
- `scripted_game` will be removed in GREEN, not updated: its move list encodes
  greedy replies and cannot match a time-dependent search opponent.

## GREEN

- `play` now uses
  `search_agent(SearchConfig::standard(), SearchLimits::new(64, 1000, 0))`,
  so human play uses the tuned evaluator, 64 MiB TT, and endgame solver at the
  1 s default. The replacement is one line; engine remains 999/999.
- Removed `scripted_game`: its scripted inputs encoded greedy replies.
- Added `play_opponent_is_search` (structural + timing) and the release-ignored
  `play_complete_game`, which drives the CLI interactively from its legal-move
  lists and checks a readable final score.
- README now states the search opponent; both scripted and PTY demos finish
  `Game over. Black 0, White 51.`
