# Issue 93: Benchmark and integrate endgame timing

## RED

Issue: #93 — Benchmark and integrate endgame timing.

Tests added:

- `tests/cli.rs::bench_board_position`: `bench --board
  785c68e1f14f0d11:0223171e0e3070a0 --endgame-threshold 12` must report
  depth 0, score -2200, solved 1, status Complete.
- `tests/cli.rs::bench_board_timeout`: the same position with `--time-ms 0`
  must report depth 0, solved 0, and status Fallback or Partial.
- `tests/cli.rs::bench_board_invalid`: malformed/overlapping/empty boards and
  a malformed threshold fail.
- `tests/search.rs::endgame_bench` (release-only `#[ignore]`): times seeded
  12- and 14-empty positions with a 1000 ms root limit, records completion,
  median, p90, p99 and nodes/s, and requires the 12-empty median < 1 s.
- `tests/search.rs::solver_full_game` (release-only `#[ignore]`): plays a full
  game at a 50 ms per-move limit, asserts each move is legal, and records the
  total and slowest move.

Expected failure: the new CLI tests fail because `bench` rejects `--board`
and does not report `solved`/`status`.

The benchmark and full-game tests are measurement/integration coverage and
have no RED failure against the library.

## Intended behaviour

- `bench` accepts `--board <me>:<opp>` (16-digit hex), validates disjoint
  non-empty bitboards with a legal root move, accepts
  `--endgame-threshold`, and reports `solved` and `status`.
- The release-only benchmarks are run with `--ignored`; results are recorded
  in the issue/docs.
- The timeout path returns `Fallback` or `Partial` with `solved = false`.
