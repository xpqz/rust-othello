"Cold" is `search_limited`; "TT" uses a fresh 1M-entry table per position and
reuses it only within that search. The TT lowers nodes but slightly lowers
measured nps, which is the condition the scope asks to record rather than
trade blindly. The shipped engine now uses the TT in agents and `bench`; the
cold rows remain diagnostic.

## TT integration

`SearchAgent` now owns a `Table::new(MAX_ENTRIES)` (64 MiB), calls `search_tt`
for every move, and clears it on `reset`. `cli::bench` also allocates the
capped table and calls `search_tt`. The endgame and full-game benchmarks use
the same table path. After integration, the search-dependent gates are the
numbers in the table above; all still pass. The #100 strength ladder predates
TT integration and was not re-run for this issue, as the review allowed; that
is noted in #100's record.

## TT cap

`Entry` is 16 bytes; `MAX_ENTRIES = 1 << 22` (4,194,304 entries) is exactly
64 MiB, and `Table::new` clamps requested capacity. `tests/tt.rs` pins the
arithmetic and the `MAX_ENTRIES + 1` clamp. Production changes are the TT cap and its agent/bench call sites; engine is
999/999, `tt.rs` 114/114, `agents.rs` 48/48, CLI 182/183.
