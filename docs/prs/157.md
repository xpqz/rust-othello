# Issue 157: Book extension rounds (builder)

## Design amendment (for review before RED)

`docs/design/book.md`, new section "Extension rounds (amendment 3)", the
extension test list under "Builder", and the amendment 3 table under
"Review response".

- **Motivation (#154 evidence):** 1,843 of 3,771 stored records choose a
  drop-out move; 187 of the 214 gate roots with one reachable record choose
  one at the root.
- **User decision, 17 Nov 2026:** "yes, draft the A+B amendment. It must be
  interruptible."
- **Registered:** R = 3 rounds; D = 19 and the policy unchanged; phase A
  adds the departure children, phase B the position after the best reply
  at each of them; count-0 extension nodes; journal scores of reclassified
  squares ignored, with backup through the new child and no rescoring.
- **Interruptibility:** one journal per phase, headers bound to the base
  journal's SHA-256 and the round and phase, key sets recomputed
  deterministically on re-run. The same command resumes after SIGKILL.
- **Estimated cost:** about 4 h per round on 5 threads, about 12 h for
  R = 3; about 9,300 records after three rounds against a 16,325-record
  room. These are estimates, not bounds.
- **Budget:** trainer at 2,035 of 2,100; an estimated 60–120 lines, so the
  guard is raised under the user's standing permission. The engine is
  untouched.

Issues: #157 (builder, RED/GREEN), #158 (run, reviewed as an artifact).

## Design review response (review of `4fae9b8`)

Revision 2 of the amendment resolves all four major findings and the
non-blocking notes; the "Review of amendment 3" table in
`docs/design/book.md` maps each finding to its change.

- **Phase contexts:** each phase has a sorted unit set plus an immutable
  context snapshot (`M_{r−1} ∪ A_r`, then `M ∪ B_r`), fixed before any unit
  runs, with peer edges as book moves. Departures come from the untruncated
  walk.
- **Phase B:** the child of each A unit's backed-up best move in the
  post-A backup, book or drop-out; a book move adds no unit.
- **Decoder:** the #154 token vector is decoded against its original
  context (terminal children consume no token, forced-pass children +t,
  others −t), with an exact token count, the score domain and `best`
  cross-checked. Every reclassified square is removed before `x(p)` is
  recomputed.
- **Identity:** each phase header binds the base, prior-phase, root, unit
  and context digests (canonical sorted records), R, round, phase and the
  extender commit. The policy and `eval.bin` are checked against the base
  before work. Empty phases, early stop and partial rounds are defined,
  and the manifest states requested and completed rounds.
- The test list is expanded to the review's fixtures. The trainer guard
  raise is planned in #157, not done.

## RED

Design approved at `8b3424d` (re-review of revision 2), with three minor

### API (stubs in `trainer/src/book.rs`, each `unimplemented!("#157")`)

- `decode(key, context, line) -> Result<Vec<(u8, i32)>, String>`: parent
  values per drop-out square under the record's scoring context.
- `remaining(key, values, nodes) -> Option<(i32, u8)>`: `x(p)` over decoded
  squares that are still drop-outs.
- `departures(roots, entries) -> Vec<Key>`; `phase_a(departures, entries)`
  and `phase_b(units, entries) -> Vec<Key>`, sorted and distinct.
- `score_in(units, context, params, jobs, path, header)`: `score` with an
  explicit partition context.
- `Extension { dir, rounds }`; `extend(nodes, base, identity, roots,
  extension, params, jobs) -> Result<String, String>` (the per-round log);
  `build_extended(nodes, base, identity, roots, mandatory, room,
  extension)`.
- CLI: `book extend <wthor dir> <base journal> --extension <dir> --rounds R
  --roots <file> [--min --plies --depth --table --jobs]`, and `book build`
  gains `--extension <dir> --rounds R` (both or neither).

### Tests (`trainer/tests/book_extend.rs`, 30)

- **Decoder:** `decode_terminal_children` and `decode_pass_children`
  (special children interspersed; missing, extra, non-integer and
  out-of-range tokens, a wrong `best` value or square, and `none` with
  drop-outs all refused); `decode_uses_context` (a book square takes no
  token; the record is refused under another context);
  `decode_matches_search` (every scorer record decodes to the
  independently searched parent values).
- **Reclassification:** `remaining_promotes_squares` (old best promoted to
  the runner-up, with the lower-square tie; all promoted gives none);
  `remaining_transposed_squares` (four start squares to one child);
  `reclassified_backup_through_child` (backup through the new child when it
  wins, and the runner-up otherwise).
- **Departures and phases:** `departures_from_walk` (engine first and
  second, given roots only, key order); `departures_after_pass`;
  `phase_a_units`; `phase_a_transposition_and_terminal` (two departures to
  one child give one unit; a terminal child none); `phase_a_after_pass`;
  `phase_b_selection` (a book move beating the drop-out gives no unit; a
  better drop-out gives its child; a tie goes to the lower square; all
  moves book gives none); `phase_b_pass_and_terminal` (normalized child,
  terminal skipped, sorted whatever the input order).
- **Peer edges:** `score_in_peer_edges`: a real same-phase peer edge is a
  book move, not searched; identical sorted records under reversed units

- **Rounds:** `extend_rounds_follow_the_phases` (every phase journal's units

- **Build:** `build_rounds_zero_is_legacy` (R = 0 equals `build` bytes and

  absent one both build the round-1 asset, with `# partial round 2 phase b

- **Identity:** `extend_refuses_changed_inputs` (other roots, other R);
  `extend_refuses_changed_record`, `…_foreign_unit`, `…_duplicate_unit`,
  `…_changed_header` (each refused by `extend` and `build_extended`, with
  no journal touched); `extend_refuses_other_policy` (a base with another
  threshold, or another depth requested: refused before any phase file).
- **Interruption (CLI):** `extend_resume_after_kill`: SIGKILL inside A

## RED review response (review of `740de47`)

Correction to the RED notes above: that suite had 30 tests, 28 stub panics
plus the two CLI failures.

- **Policy refusals isolated:** `refuses_other_policy` builds a fresh, valid
  base for every case and changes exactly one input: a control that must
  succeed; the base header's threshold; the base header's `eval.bin` hash
  (a well-formed different hash); the requested depth; the requested
  table. Each refusal must happen before `r1a.journal` exists, and the
  control must create it.
- **Content binding:** `extend_binds_inputs` compares every phase header of
  a two-round run, byte for byte, with one assembled by the test: the base
  header, then `extend R 2 round r phase a|b`, then `base`, `prior`,
  `roots`, `units` and `context` as `{count}:{sha256}`, then
  `extender {git rev-parse HEAD}`. The digests are computed in the test
  from sorted logical records: the base and each phase as `id<TAB>line`
  lines joined by newlines; `prior` as each earlier phase in order as
  `r{r}{p}\n{records}\n`, counted in records; `roots` as the existing
  `id:engine` list joined by spaces; units and context as sorted IDs
  joined by newlines, the context taken from the test's own node-set
  reconstruction. `refuses_changed_score` and `refuses_changed_base` make
  a valid change: one token moved by one, chosen so that the record still
  decodes with the same `best` under its context. They run with all later
  phase journals present, and both the resumed run and the build must
  refuse with every file unchanged. Foreign, duplicate and changed-header
  cases use the same harness, and the changed-roots and changed-R cases
  stay in `refuses_changed_inputs`.
- **Interruption:** `extend_resume_kill` makes two live SIGKILLs at the
  adaptively chosen depth. The first lands inside round 1 A, after at least
  one A record and with A incomplete against an uninterrupted run. The
  second lands inside round 1 B, after at least one B record, with B
  incomplete and round 2 not started. A depth is accepted only when both
  land, and each run is resumed with 3 jobs. Two replay fixtures are kept
  and labelled as simulated, not live: the boundary after A (later
  journals removed) and a torn round 1 B record. All four directories must
  equal the uninterrupted run's sorted records and its built asset and
  manifest bytes.
- **Empty B with a non-empty A:** `extend_empty_b` uses a synthetic,
  decodable base in which one departure's child has every move inside the
  base node set. A has that one unit. B must be written as an empty
  journal whose header carries `units 0:`. The round counts as complete,
  and a resume changes nothing.
- **Names:** every function has at most two underscores
  (`backup_through_child`, `phase_a_transpositions`, `phase_a_passes`,
  `phase_b_passes`, `score_in_peers`, `extend_follows_phases`,
  `build_zero_rounds`, `refuses_*`, `overflow_extension_first`,
  `extend_resume_kill`, `extend_cli_options`). The test module comment no
  longer names the issue.

## GREEN

### What changed

- `trainer/src/book.rs`:
  - `header` is now `identity + tail(params)`, so the policy check can
    compare tails. `score` calls the new `score_in` with its own node set,
    and `build` calls the new `emit` (pruning, asset and manifest after the
    given head lines). Legacy output is byte-identical (the 47 existing
    book tests pass, and `build_zero_rounds` compares bytes).
  - `best` (lower square on ties) feeds `decode` (the original-context
    decoder: terminal children take no token, a forced pass +t, others
    −t, exact consumption, `±EVAL_BOUND`, `best` cross-checked) and
    `remaining`.
  - `departures` filters the untruncated walk. `phase_a` gives the
    children of the keys' backed-up moves that are neither nodes nor
    terminal, sorted and distinct. `phase_b` is the same rule applied
    after the post-A backup.
  - `State` (nodes plus decoded values) with `entries` (`remaining`, then
    `backup`) and `add`, which decodes a journal under its context and
    refuses foreign or repeated units.
  - `load` reads the base journal under the node set and checks its header
    against the identity, `provenance` and, for a run, this binary's tail
    with the `engine` word masked. A mismatch in eval, depth, table,
    threshold, ordering, probcut or rules is refused before any directory
    or journal is created.
  - `rounds` drives both run and build. Per phase it computes the units and
    context and assembles the header with the five digests and the
    extender commit. An existing journal must match that header and pass
    `add` on a copy before any scoring. A run then calls `score_in`; a
    build stops at the first absent or partial phase. A build takes R from
    the run's `r1a` header, so a two-round run can be built at one round.
  - `extend` returns one line per round; `build_extended` returns `build`
    for R = 0. Otherwise it writes `# rounds requested R completed k`, any
    `# partial round r phase p k/n` line, and per round `# round r
    departures a b peers into returned records first second`. `first` and
    `second` are the untruncated walk sizes from the mandatory roots.
    `emit` then works over the extended node set, where extension nodes
    have count 0.
- `trainer/src/main.rs`: `book extend <dir> <base journal> --extension
  <dir> --rounds R --roots <file> [--min --plies --depth --table --jobs]`.
  `book build` takes `--extension` and `--rounds`, both or neither. The
  roots file reading is shared by extend and build.
- **Extender commit, a deviation from the RED-review clarification:**
  a compile-time commit needs a `build.rs`, which `tests/budget/rules.rs`
  forbids (`check_scope`: "build.rs is not allowed"). I tried that and
  reverted it. The header uses `git_commit()` (runtime `git rev-parse
  HEAD` in the source checkout), as the base header's `engine` field
  already does. The design note now says so, and #158 relies on the
  pinned, never-moved worktree plus the logged binary SHA-256, as #154
  did.
- **Budget:** the trainer is at 2,457 production lines, against my 60–120
  line estimate for this work. The new code is about 420 counted lines,
  including the refactors and CLI. I raised the guard to 2,500 under the
  user's standing permission, in `trainer/tests/budget.rs`, `AGENTS.md`
  and `docs/PLAN.md`. The engine is unchanged.

## GREEN review response (review of `0c4e442`)

- **Token domain:** `decode` now checks `(-EVAL_BOUND..=EVAL_BOUND)`
  directly on the parsed `i32`, before any negation; nothing calls `abs`.
  `decode_bounds` accepts the endpoints ±6,400 and refuses
  `i32::MIN`, `i32::MAX`, ±6,401 and an unparsable `i64::MAX` in each of
  the four slots, plus the reviewer's all-MIN record. It runs in debug
  (`cargo test --test book_extend decode_bounds`) and in release.
  `refuses_bad_token` puts all-MIN tokens into a completed round 1 A
  record: resume and build both return `Err`, and every file is
  unchanged.
- **Evaluator identity:** `tail` hashes `othello::pattern::WEIGHTS`, the
  model compiled into the engine; the static is now `pub`, and engine
  production lines are unchanged at 1,218. It no longer reads
  `assets/eval.bin` at run time, so a changed or removed disk asset
  cannot change the executable's identity. A base naming another model
  is refused before any phase file (`refuses_other_policy`, eval case),
  and an old matching base is judged against the compiled model, whatever
  the checkout holds. `header_embedded_model` pins the field to the
  embedded bytes. I did not write a test that edits the shared asset in
  the tree, since tests run concurrently.
- **Extender provenance:** the identity is compile-time,
  `option_env!("OTHELLO_COMMIT")` (`unknown` if unset), supplied by the
  recorded build command. No `build.rs` is needed, and runtime Git plays
  no part. A run uses its own identity, so a resume by another scorer
  meets a header mismatch and is refused. A build takes R and the extender
  from the run's `r1a` header and replays them. `build_keeps_provenance`
  relabels all four phases to another commit: the build reproduces the
  original asset and manifest bytes, a resume is refused, and relabelling
  one phase inconsistently makes the build fail. A moved checkout HEAD
  cannot relabel a compiled scorer, because nothing reads HEAD.
  `extend_binds_inputs` now expects the compiled identity. The design
  note is replaced accordingly, and the runtime-HEAD wording is gone.
- **Non-blocking:** the manifest label is now `a-peers` (A-to-A edges
  only). For #158 I will build and keep each completed prefix's manifest
  (`--rounds 1`, `2`, `3`, which replays without searching) as the
  per-round, per-root evidence.

Commands: `cargo test --release --test book_extend` gives 36 passed, the
same with `OTHELLO_COMMIT=$(git rev-parse HEAD)` set, and `decode_bounds`
passes in debug. Clippy `--tests -D warnings` and fmt are clean.
`scripts/check.sh` exits 0 (engine 1,218, tools 1,298, trainer 2,464 of
2,500).

The #158 build command will be `OTHELLO_COMMIT=$(git rev-parse HEAD)
cargo build --release` in the pinned worktree, logged with the binary's
SHA-256.
