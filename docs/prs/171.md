## Run registration (for review with the tooling)

All commands run from the main checkout at the merged commit, with the
release examples built from it. Load is telemetry only: node-controlled
games are deterministic and never voided.

1. **Roots**, frozen before any trace:
   - `book_diag roots bench/openings_book.txt` gives 24 lines:
     `bench/openings_diag_early.txt` is the first 12 (the rule above)
     and `bench/openings_diag_hist.txt` the next 12 (the first 12
     historical roots, in file order);
   - `bench/openings_diag_start.txt` holds `start`, the smoke case.
   - Each file's SHA-256 is recorded before tracing.
2. **Traces,** at `--nodes 250000`, one journal per book and group, in
   `docs/tuning/book_diag/`: `trace_{off,r0,r3}_{early,hist,start}.journal`,
   with `--book off`, `--book docs/tuning/book_diag/book_r0.bin` and
   `--book embedded`. The book-off journal is the reference for the same
   ids. The roots of a group are traced once per book.
3. **Replay:** the first two pairs, by ascending id, that the book side
   lost in `docs/tuning/book_nodes.journal` (book points < 1 over the
   pair). Their openings go into `docs/tuning/book_diag/replay_roots.txt`
   and are traced with `--book embedded --nodes 10000000`. Each game's
   score is compared with the journal's. A mismatch is a finding, to be
   resolved before attributing losses to book choices.
4. **First disagreements:** `book_diag diverge` for r0 and r3 against
   off, per group, concatenated in the order r0 early, r0 hist, r3 early,
   r3 hist, into `disagreements.tsv`.
5. **Audit:** `book_diag audit disagreements.tsv --nodes 500000,2000000`
   writes `audit.tsv`. A reversal between the two node caps is flagged as
   unstable, and exact values take precedence where both children solve.
6. **Report:** in this file:
   - coverage and first-hit ply by root group and version;
   - first disagreements by ply and by source (book hit or search);
   - whether r0 and r3 choose differently;
   - the audit table;
   - the replay check;
   - the observed scores, as descriptive data only.
- **Ceiling:** 30 active minutes across all invocations, including
  repeats and restarts. Each invocation's elapsed time is logged, and no
  invocation starts once the total is spent. Expected about 10 min: about
  150 games at 250,000 nodes, 4 games at 10 M nodes, and 64 child
  searches.
- **Deferred:** the design's optional comparison of the chosen exit's
  original drop-out estimate with the fresh scores. The scoring journals
  hold per-square values only through the trainer's context-dependent
  decoder (#157), so this is not done in this run.

## RED review response

All four majors addressed in `tools/examples/book_diag.rs`; the 10
targeted tests fail against the stubs (`cargo test --release --example
book_diag`: 0 passed, 10 failed). Formatting and clippy with warnings
denied are clean; the stubs carry a file-level `allow(dead_code)`,
removed in GREEN.

1. **Run-time deadline.** The registration's ceiling step is replaced:
   - Every production invocation runs under
     `perl -e 'alarm shift; exec @ARGV' S cmd …`, with `S` the seconds left
     of the 30-minute allowance. Start, end and exit status go to
     `docs/tuning/book_diag/time.log`; elapsed time counts whether or not
     the command finished.
   - Traces run in batches of `--pair-range` four pairs, so an alarm loses
     at most the pairs in progress; the start group is one pair.
   - No automatic retry. A killed invocation is resumed only by rerunning
     the same command by hand, while allowance remains.
   - `audit` now writes a resumable journal (`--out`), one record per
     position, so completed positions survive an interruption. Test
     `audit_resumes`: a truncated journal resumes to the uninterrupted
     records; other node caps are a header mismatch.
   - Before any production trace, a stop and restart demonstration on a
     fixture (two roots at 20,000 nodes, and a two-position audit) kills
     each command with a 1-second alarm, reruns it, and compares the
     result with an uninterrupted run. The result goes in GREEN notes.
   - The SHA-256s of the built `book_trace` and `book_diag` examples are
     recorded with the roots and asset hashes before tracing.
2. **Comparison bound to roots and controls.** `diverge` now reads each
   journal's header through `parse_trace`, which refuses duplicate and
   non-canonical ids. `compare` requires the reference to be book-off,
   the same node cap in both headers, both roots digests equal to the
   digest of the supplied roots file, and exactly ids `p:0` and `p:1` for
   every pair of the roots. Results are in numeric pair and colour order.
   Test `compare_checks` covers numeric order (pair 2 before 10),
   mismatched node caps, mismatched roots, a non-off reference, a missing
   game, a duplicate id and the alias `00:0`.
3. **Symmetric first changes.** The comparison of a game ends at its first
   change. When the two moves are images under a symmetry that fixes the
   board, the change is reported as `equivalent`, the rest of that game is
   not compared, and it takes no audit slot. It is counted in the report
   as equivalent, unresolved beyond that point. Tests:
   `disagreement_equivalent` (d3 against c4 from the start, with later
   differences ignored; c3 against e3 after d3 is not equivalent) and
   `select_rule` (an equivalent entry takes no slot; the same board and
   both moves under symmetry 3 count once, the first kept).
4. **Status through the audit.** `child_value` returns `Value { score,
   reply, status, solved }`: a terminal child is exact with no status;
   otherwise the fresh search's status and solved flag are kept. The audit
   record carries, per node cap and per child, the score, reply, status
   (`complete`, `partial`, `fallback`, or `terminal`) and solved flag. The
   report counts a reversal only between completed or solved values; a
   fallback is reported as such. Tests: `child_terminal`, `child_normal`,
   and `child_forced_pass` (opponent must pass: the value is the passed
   position's search, not negated, and the reply is the mover's).

Registration changes: step 5 becomes `book_diag audit disagreements.tsv
--nodes 500000,2000000 --out docs/tuning/book_diag/audit.journal`; the
ceiling paragraph is superseded by item 1 above.

## RED re-review response

The 11 targeted tests fail against the stubs (`cargo test --release
--example book_diag`: 0 passed, 11 failed). Formatting and clippy with
warnings denied are clean.

1. **Partial results with positive depth.** `Value` now carries `depth`,
   the depth of the completed heuristic iteration: 0 for a terminal child,
   an exact solve, a W/D/L partial or a fallback. New stubs:
   - `eligible(value)`: true if the value is exact or has positive depth.
     A node-capped search normally reports `Partial` at positive depth
     from its last completed iteration, so such values count. The
     depth-zero W/D/L partial and a fallback do not.
   - `reversal(low, high)`: whether the preferred child (book or off)
     flips between the two node caps. It returns `None` unless all four
     values are eligible; a tie at either cap is no reversal.

   Test `reversal_rule` covers partial values at depths 9 and 11, with a
   flip, no flip and a tie, plus an exact and a terminal value. It also
   checks that a W/D/L partial and a fallback each give `None`. The
   child tests now also check `depth`. The audit record carries depth
   with status and solved for each child at each node cap. The report
   lists ineligible values (W/D/L partial, fallback) by kind, apart from
   reversals.
2. **Same engine.** `Trace` keeps the header's `engine` field, and
   `compare` requires the two to be equal. `compare_checks` adds a
   mismatched-engine case. The executable SHA-256s are still recorded
   before the run.

## GREEN implementation

`tools/examples/book_diag.rs`: the stubs are implemented and the RED
`allow(dead_code)` is removed.

- `early_roots`: a depth-first walk in square order records each canonical
  position at its first, least, sequence. It keeps all positions after one
  and two placements, and four after each of three and four placements, by
  a Fisher–Yates shuffle with `Rng::new(171)`. The frozen early roots are:
  `d3`; `d3 c5`, `d3 e3`, `d3 c3`; `d3 e3 f2`, `d3 c5 f6`, `d3 c3 c4`,
  `d3 c5 c6`; `d3 e3 f6 e6`, `d3 e3 f5 c5`, `d3 c5 e6 e3`, `d3 c3 c4 e3`.
- `parse_trace`: requires the exact 13-field `book_trace v1` header and
  keeps book, nodes, roots digest and engine. It refuses non-canonical,
  out-of-range or duplicate ids and malformed records.
- `first_disagreement`: replays both traces from the opening. At the first
  differing move it checks for a board symmetry mapping one move to the
  other (`equivalent`) and stops.
- `compare`: checks a book-off reference, an equal node cap and engine, both
  roots digests against the roots file, and exactly ids `p:0`, `p:1` for
  every root, then reports in numeric order.
- `child_value`: terminal children are exact. Otherwise it runs a fresh
  `Table::new(1 << 20)` search with ProbCut off, of the child, negated, or
  of the passed child, not negated, when the opponent must pass.
- `eligible`, `reversal` and `select`, as specified. Symmetric duplicates
  are keyed by the least transformed (board, book move, off move).
- `audit`: header `book_diag audit v1 nodes A,B found {digest of the
  selection}`. One record per selected position, id
  `version:group:pair:game`, with the line
  `{cap} book {v} off {v} | … | reversal yes|no|ineligible`. Each value is
  `score:reply:status:depth:exact|heur`, with status `c`, `p`, `f`, or `t`
  for terminal. On resume, duplicate and foreign records are discarded and
  redone.
