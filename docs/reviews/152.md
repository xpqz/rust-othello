# Review: Issue #152 — Opening book design

## Summary

**Request changes** on revision 1, submitted at `c751eb0594a6e0285684b822259deae8b0b21e4c`.
The playing/search API separation, explicit scoring policy, drop-out correction,
one-look clock gate and resumable node jobs are good foundations. Before a
builder is implemented or a long scoring run starts, make the graph a total
policy over legal moves, specify deterministic scoring and resource selection,
and reconcile pruning with the gate roots. No production experiment is requested.

## Findings

### Major: a legal move can fall into neither scoring category

Location: `docs/design/book.md:77–94`.

An edge currently requires both endpoints in the node set **and an observed
WTHOR transition**. Drop-out requires the child **not** to be a book node.
A legal transition to an existing node that was reached through another
transposition, but never observed from this parent, satisfies neither rule.
It is omitted from both maxima. Global position frequency does not establish
that every incoming legal edge was observed.

Choose a complete partition: preferably include every legal transition whose
canonical child belongs to the node set; alternatively score every move
without a retained edge as a drop-out, even when its destination occurs
elsewhere in the book. Preserve move labels when several squares reach the
same canonical child, so canonical-square tie-breaking is well defined.
Add a builder test with an unobserved legal edge into an existing transposition
and assert every legal move is represented exactly once.

Also define no-move and terminal nodes in this same partition. `max` over an
empty set is not a terminal value. A pass changes side without placing a disc;
specify whether pass nodes are explicit or contracted, their sign, depth and
colour-parity treatment, and the topological order. Include forced-pass and
double-no-move fixtures. Do not infer absolute colour solely from disc count
when computing the two reachability sets.

### Major: reproducibility needs a fixed within-node search order

Location: `docs/design/book.md:99–119,153–160`.

Clearing once per node makes nodes independent of scheduling, but siblings
share their table. With selective search, the table's previous bounds and
stored moves are part of a search's inputs; a node and configuration alone do
not establish invariance to sibling iteration order. In particular, do not
iterate a hash collection to choose the order of the drop-out searches.

Specify a canonical parent orientation, deterministic transform tie-breaking,
ascending canonical move order (or another fixed order), fixed depth-search
sequence and table lifecycle. Promise scheduling/resume independence while
holding that sequence fixed. Pin these rules in the journal format/policy
version. Test one versus several workers, reordered node jobs and resumed
runs for identical per-node scores and final asset bytes.

The claim that a node with no book children gets **the** full depth-D search
value also needs qualification: separately searching all children with a warm
selective table is not guaranteed to equal `search_tt(parent, depth D)` with
its iterative deepening and root policy. Define the former as the book's
scoring algorithm; do not require equality to the latter without evidence.

The 200-node pilot needs a sampling seed/method over the actual N=10 node
set, actual retained-edge/drop-out definition, projection formula, treatment
of nodes with no drop-outs, and an outcome when even D=18 exceeds 36 hours.
Prefer a fixed uniform sample or a specified weighted/stratified estimator;
first-in-file nodes would not estimate the whole workload. The pilot itself
must journal completed node/depth units and resume if it can exceed ten
minutes. These details must precede that pilot, rather than be chosen from
its times. The existing rough estimates need not be rerun.

### Major: pruning roots and the proposed gate do not currently agree

Location: `docs/design/book.md:131–138,209–225`.

The reachability reduction is valid for play starting at its declared roots,
following this engine's selected moves. The design leaves those roots
implicit, while the gate forcibly starts at 400 different ply-6 positions.
A position excluded by optimal-book reachability from the start can be a
forced gate root. Further lowest-count deletion can remove it or disconnect
its continuations. Even before pruning, only 232 of the proposed 546 roots
meet N=10, so a 400-root draw necessarily includes at least 168 roots outside
the initial node set; later re-entry is possible but is not quantified.

Specify pruning roots explicitly and decide whether the book is optimized
for ordinary start-position play, the forced-root gate, or both. Freeze the
seeded gate roots and final artifact before play; record coverage and
reachable continuation counts on that actual artifact, without outcome-based
root replacements. State the claim the gate supports: uniform eligible
ply-6 starts, rather than a game from the standard start position or a
frequency-weighted human opening distribution. A conditional gate is a
reasonable choice if made explicit.

Overflow also needs deterministic count ties and clear semantics after
removal: whether values/moves remain pre-pruning offline recommendations,
or whether the graph is backed up again with removed edges as drop-outs.
The former can be a deliberate truncation policy, but its stored values no
longer describe the same continuation policy. Make tests enforce the chosen
meaning. Do not describe reachability-only pruning and arbitrary deletion
as the same guarantee. Reporting final size/coverage can settle the asset
budget question without raising the guard now.

### Major: symmetry test contract is impossible on symmetric positions

Location: `docs/design/book.md:166–172,229–232`.

The start board is invariant under a 180-degree rotation, but each legal move
is sent to a different square (19↔44 and 26↔37). Thus a deterministic lookup
of that identical board cannot return the exact rotated move for both
orientations. Several transforms can attain the canonical minimum.

Specify deterministic transform ties. Test exact inverse mapping on an
asymmetric fixture; for symmetric fixtures test legality, value identity and
membership in the stored move's stabilizer orbit. Include the start position.
This preserves deterministic canonical-square choice without demanding
impossible full equivariance.

### Required decision before builder GREEN: counted home and budget

Location: `docs/design/book.md:140–151`; `docs/PLAN.md`, Phase 2 Budget.

The design correctly surfaces the trainer shortfall; this review does not
authorize an exemption or budget increase. The current PLAN explicitly puts
training/fitting pipelines in the counted trainer and assets reproducible
from it; the epic's “tools command” wording differs. Resolve that contract
with the user before builder implementation. Prefer an explicit counted
budget/scope decision over selecting a location merely to avoid counting
250–350 production lines. Any chosen exception needs the corresponding PLAN
and issue wording updated. This is not a reason to delay the design fixes
above or to launch the scoring run first.

## Non-blocking suggestions

- Keep the legal-move check for key-only lookup, but also detect duplicate
  64-bit keys for distinct canonical boards during generation. Preserve a
  reproducible board-bearing audit/manifest: `book.bin` alone cannot prove
  that every stored move is legal, because it contains no positions.
- Expand fixture tests to malformed/truncated asset lengths, out-of-range
  squares before bit shifting, empty books, i16 score bounds, terminal/pass
  bypass and hit/miss integration through the actual CLI/GUI/agent paths.
  Preserve a defined miss fallback and status contract for consumers.
- The sizing replay records boards **before** each supplied move and omits
  the position after an unfinished game's final move. The statement that
  unfinished games count “up to their last move” should clarify this boundary.
  It affects a future builder if terminal prefixes within the 30-ply window
  are intended to count. The log totals faithfully describe the present code.
- Keep actual game-clock settings, load/void rules, timeout treatment and
  diagnostics' meaning in the gate's eventual pre-registration after #151;
  do not infer a game-time gate from today's `bk:...:<ms>` per-move parser.
