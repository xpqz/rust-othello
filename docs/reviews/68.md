# Review: Issue 68 — Implement perft utility for CLI and tests (RED)

Verdict: **request changes** (small)

## Verified

- #67 was merged and closed. This branch is based on the current `main`
  (`fc5d90e`).
- `cargo test --test perft` fails only with the expected E0432.
- The counts for depths 1–10 match Aart Bik's table as quoted in PLAN.md.
- I hand-checked both fixtures:
  - pass: `me = b2`, `opp = a1 | c1`. `me` has no move, because both
    diagonal runs end off the board. `opp` has exactly a3 and c3, so the
    position is not terminal, `perft(1) = 1` (the pass node), and
    `perft(2) = 2`. An implementation where a pass costs no depth (the search
    convention) gives `perft(1) = 2`, so the test separates the two rules.
  - early terminal: rank 1 alternating, 56 empties. Every line from a rank-2
    square runs through rank 1 and off the board, so neither side has a move.
    `perft` is 1 at depths 1 and 5.

## Required

1. **`cargo fmt --check` fails on `tests/perft.rs`.** It fails at line 31,
   where the trailing-comment alignment differs, and again at line 40. Run
   `cargo fmt`. The definition of done needs fmt green at every stage, and
   `scripts/check.sh` stops at the first step.

## Minor

2. **Magic bit literals in the fixtures.** `1 << 9 // b2` and `0x55`/`0xaa`
   depend on comments to be readable. A local `bit(file, rank)` helper (as in
   `movegen.rs`), or `common` gaining one, makes the fixtures self-checking
   and removes the alignment problem behind item 1.

3. **Release timing.** The acceptance includes "release perft(8) < 0.2s". No
   test pins it, and PLAN.md assigns the measurement to #71 (record nodes/s
   on recorded hardware). In the GREEN notes, give the measured release time
   for perft(8), or point to #71 explicitly.

4. **The `#[ignore]` test isn't actually release-only.** `#[ignore]` keeps it
   out of the default run, but `cargo test -- --ignored` in debug runs 24M
   nodes slowly. That is acceptable, but if "release-only" is the intent, add
   `#[cfg_attr(debug_assertions, ignore)]` or note the expected invocation
   (`cargo test --release -- --ignored`).

5. **Scope of the CLI deferral.** The #68 Files list includes `src/cli.rs`,
   but the PR defers the `perft` subcommand to #75. #75's scope does include
   `perft <depth>`, so the split is consistent. Update #68's Files in skis so
   the issue doesn't claim `cli.rs`.

## Housekeeping (outside this PR)

- `.opencode/review-watch-state.json` is untracked in the working tree. Its
  ignore rule was removed in `fc5d90e` ("drop the state file"), but the file
  itself is still on disk. Delete it, so it isn't swept into a commit.
