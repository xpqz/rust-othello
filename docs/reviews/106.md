# Review: Issue 106 — Make play use the search engine (RED)

Verdict: **request changes**

## Verified

- #105 was merged, and all prior issues are closed. This branch is based on
  the current `main`.
- `play_opponent_is_search` fails as intended. The greedy reply is
  near-instant, so the ≥ 500 ms assertion fires.

## Required

1. **The "next prompt" assertion is vacuous.** `play` prints the start board,
   including `Black to move`, **before** reading any input, so
   `text.contains("Black to move") || …` holds even if White never moved.
   Require evidence of a White reply instead: at least **two**
   `Black to move` status lines (the initial one and one after White's
   reply), or a `Game over`. The ≥ 500 ms timing check is a reasonable
   heuristic for a 1 s search, but it can't tell "searched" from "slow", so
   pair it with the structural check.

2. **The acceptance's release-ignored full game is missing.** #106's
   acceptance says "a release-ignored full game completes". The notes
   replace the old `scripted_game` with "the manual demo", but a manual demo
   isn't a test. The old test can't simply be reused, because its scripted
   inputs came from simulating greedy, and the search opponent's replies
   depend on time, so they can't be pre-computed. Drive the game
   **interactively** from the test instead. Spawn `play`, read stdout until
   each status line, parse its `legal:` list, and answer with the first
   legal square, or `pass` when the list is empty. Assert that it reaches
   `Game over. Black N, White M.` with `N + M ≤ 64`, inside a generous
   bound (about 60 moves × 1 s plus slack). Mark it
   `#[cfg_attr(debug_assertions, ignore = "release-only")]`, or
   `#[ignore]`, matching the acceptance wording.

## Minor

3. **Removing `scripted_game`.** Say explicitly in the notes that it is
   removed rather than updated, and why (its expectations encode greedy's
   moves). Item 2 is its replacement, so the CLI's full-game coverage isn't
   lost.
