## Required

1. **Test 11 barely bites.** Each window is `(v-100, v+100)` around the
   full-width depth-8 value, so a root cut needs the shallow probe to clear
   `v + 100 + m` (with m about 30-60). Almost nothing fires, and the
   fraction is near 0 by construction. The design specifies "the wrong side
   of full-width **null-window** bounds".
   - For each midgame, use several null windows at offsets from `v`, for
     example `v ± {10, 25, 50, 100}` as `(x-1, x)`.
   - Compare the selective fail-high or fail-low outcome with the
     full-width one, and count the disagreements.
   - Keep the 15% ceiling. Report the measured fraction and the number of
     decisions in the notes; the notes currently report no figure for
     test 11.
2. **The `pc:off` budget test bypasses the agent.**
   `pc_off_uses_the_full_node_budget` calls `search_limited` with a
   hand-built `SearchLimits::new(64, …, 1000)`. It never exercises the
   `pc:off` parsing or the agent construction it is meant to pin, which was
   the depth-10 cap bug. Drive it through the agent. Use `match` with
   `--nodes`, and assert from the log or JSON output that the per-move nodes
   are close to the budget. Alternatively, call the tools function that
   builds the agent from `"pc:off"`. Do the same check for `pc:150`.
3. **Fingerprint: a fresh table at each depth, as specified.** One
   `Table` is shared across depths 1-6 for each board. With full windows
   the values should still be exact, but the issue says "fresh table each".
   Following it removes any doubt that TT interaction affects the hash. The
   recorded constant may change. If it does, regenerate it once and say so.
