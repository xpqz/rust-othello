# Review: Issue 145 — ProbCut v2 design

## Review of `bf8fa02`, with budget update `70eb618`

### Summary and probe choice

**Request changes.** I favor **option B, recursive selective probes**, as
an experiment behind the off-by-default switch. A single heuristic TT
domain is acceptable when its lifetime is confined to one fixed search
policy. The proposed calibration and runtime contracts do not yet make
that policy safe to evaluate or implement unambiguously.

The fresh 3-second gate, larger sample, no extrapolation in depth, separate
full-width labels and explicit failure/removal policy are good changes.
Recursive probes are a plausible candidate, not an established strength
gain for this engine. Buro's MPC also considers increasing shallow depths;
Edax's analogous implementation limits probe nesting. The proposed single
check with depth-bounded recursion is its own variant and needs its own
validation. References: [Buro's paper](https://skatgame.net/mburo/ps/improve.pdf),
[Edax 4.7 midgame search](https://raw.githubusercontent.com/abulmo/edax-reversi/v4.7/src/midgame.c).

### 1. Major: define the actual decision-replay data and execution path

Locations: Calibration data; option B; held-out decision check.

`v_s` and `v_d` alone do not determine false-high/false-low decisions: the
node's alpha/beta window determines whether a cut fires and whether it is
wrong. The collection schema lists values, empties, game and split, but
not the board, original remaining depth or window. A depth-10 sampler also
does not by itself provide runtime windows from depth-14/16 searches.

Specify a replayable record containing the board, stable source/game ID,
sampled depth and alpha/beta window, plus immutable sampler/input/engine
provenance. State how windows for each supported deep depth are obtained;
if synthetic windows are used, define their distribution and label that
check as a proxy rather than actual runtime decision replay. Record only
completed full-width reference values, with completion depth explicit.

For B, define how `fit` executes the same selective probe code while the
model is still being selected: temporary compiled constants, a model
injection interface, or a tools implementation checked against the engine.
The current issue order puts runtime replay before that runtime exists.
Full-width oracle tables must never satisfy selective probe queries.
Specify independent tables and the selective-side warming/history policy;
a cold isolated replay must not be described as an exact reproduction of
all warm in-game TT decisions.

Existing full-width labels can remain useful. This finding asks for the
missing decision context/protocol, not an unnecessary repeated collection.

### 2. Major: make supported cells and the runtime guard agree

Locations: The check, steps 1–2; sigma model and fit; supported domain.

The design alternates between a per-(depth, stage) evidence rule and 200
fired decisions pooled over depths. Those are different guarantees.
Pooled shallow successes cannot certify a poorly measured depth-16 cell.
Tier 2 has only about **450 held-out positions** before stage partitioning,
so 200 decisions per direction in every deep cell cannot be presumed.

Choose and state one evidence unit and pooling policy. Report per-depth
results even when pooling, and distinguish pooled acceptance from
per-depth validation. Repeated depths from one sampled game are correlated;
do not count them as independent binomial trials when constructing the
upper bounds. Specify the confidence-bound method and how sparse cells
are rejected or the planned sample is resized before the long run.

Then make the compiled supported domain executable: a cell mask or a
fully supported rectangle, not merely the deepest depth seen anywhere.
The runtime guard currently checks only `E_MIN`, despite data ending at
56 empties; add an upper empties bound. Likewise, a single `E_MIN` does
not exclude unsupported interior stage/depth holes. No fitted formula may
silently enable those cells.

Model form, shallow rule and `E_MIN` are selected using the same alleged
held-out split that supplies the acceptance bounds. Use a separate final
audit split after those choices are frozen, or explicitly treat that split
as model-selection data and withdraw unbiased held-out confidence claims.
Deduplicate/group repeated sampled positions across game folds so exact
or symmetry-equivalent positions cannot validate their own fit.

### 3. Major: spell out shared-TT policy ownership and off-switch identity

Locations: Option B; TT policy; configuration/API; tests.

“A cut stores nothing extra” does not keep parent entries full-width.
Under B, ordinary heuristic entries may contain selective values. Today's
`Entry::cutoff` cannot distinguish those from full-width results, and
`search_tt` accepts a caller-owned table. Therefore `probcut: None` is not
bit-identical to today's search if it is given a table previously used
with ProbCut on; changing `t` can also change the meaning of cached bounds.

Explicitly bind each table to the evaluator, threshold, model revision and
`probcut` setting. Clear it or use a separate table on any policy change,
including on/off and changes of `t`; otherwise retain provenance in the
entries. Fresh per-agent tables are a sufficient small design when this
precondition is enforced by every caller and replay tool. Add tests for
oracle isolation, policy transitions and off-switch identity with the
specified lifecycle. Frozen baselines must explicitly stay off rather
than inherit a future enabled `standard()`.

Also distinguish “this node does not run a ProbCut check” from “this
subtree/value is full-width”: unsupported parent depths can contain
selective descendants and consume selective TT entries. Exact solver
scores remain protected by `Domain::Endgame`, but identical in-game exact
node counts/times do not follow when earlier play and table contents differ.

### 4. Major: remove the circular screening/tuning order

Location: Tuning `t`.

The pre-match screen uses the “picked t”, but that t is picked by the four
200-pair matches that the screen is supposed to precede. Define an
executable order: for example screen every preregistered candidate first,
then tune only survivors, with a fixed tie/failure rule. Specify what
happens if no candidate survives.

Resolve the decision-check threshold as well: option B says acceptance is
on the chosen runtime predictor, the fit gates only `t = 1.5`, while the
actual candidates are 0.8/1.2/1.6/2.0. A 10% bound checked at 1.5 does not
bound errors at 0.8. State whether 1.5 is only a model-quality filter and
report the actual candidate decision rates, or define candidate-specific
acceptance. Do not imply that every tuned candidate inherits the 1.5 bound.

### 5. Major: specify the experiment-wide rule for the optional gate look

Location: Gate.

There are two opportunities to enable (400 and 800 pairs). Merely
preregistering the extension does not give the interval selected after
stopping ordinary fixed-sample coverage. Specify the experiment-wide
one-sided error budget and its spending across looks, or use one final
analysis with an interim futility check only. Two pointwise two-sided 95%
intervals could, for example, be explicitly justified as a Bonferroni
one-sided 5% gate; state that interpretation instead of implying one
fixed-sample 95% inference after optional stopping.

Freeze the selected model/t before the fresh gate and use disjoint,
reserved additional pairs for extension, retaining the first 400 exactly
once. State how journal identity/chunk aggregation implements that
extension, and retain the repository's conservative degeneracy policy.
There must be no retuning or replacement candidate after seeing gate data.

### Additional design corrections

- Constrain the chosen shallow formula to **1 <= s < d** throughout its
  supported domain. `d-4` and `d-6` are invalid at the proposed minimum
  depth 3 without an explicit domain restriction or piecewise rule.
- Specify positive fitted `a`, its integer representation and conservative
  signed division, plus bounded generated coefficients/sigma and the
  behavior of direct public `Some(t)` values outside the parser's range.
  Merely choosing `i64` does not prove every coefficient/product safe.
  Include these boundaries in RED coverage.
- Carry forward the correction requested in #143: vectorisation and two
  unsuccessful probes do not establish a practical node-cost floor or
  force every future gain to come from fewer nodes. ProbCut is a chosen
  next experiment, which is sufficient motivation.
- Keep the recorded budget decision synchronized with epic 144's older
  1,150/1,499 wording. Budget permission is not a reason to compress the
  domain, validation or TT invariants out of the design.

### Recommendation

**Request changes** — retain B as the proposed experiment, but resolve the
calibration/replay, supported-domain, TT lifecycle and gate contracts before
engine implementation is approved. These are design revisions; no long run
is required to answer them. The user's recorded permission to begin the
collection-tool work does not establish acceptance of the current data
schema or statistical claims.
