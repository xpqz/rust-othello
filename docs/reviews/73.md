# Review: Issue 73 — Negamax/alpha-beta, terminal-before-cutoff, fail-soft (RED)

Verdict: **request changes**

## Verified

- #72 was merged and closed. This branch is based on the current `main`.
  `cargo fmt --check` passes, and `tests/search.rs` fails only with the
  expected E0432.
- I hand-checked the fixtures:
  - `depth_zero_terminal`: 2–1 with 61 empties gives 62, so 6200. The
    heuristic is 80 − 100 + 100 = 80.
  - `horizon_terminal`: the only move is a1, which flips b1, so the child is
    a 63–1 full board. Its terminal value is −6200 and its heuristic is
    88 − 6200 = −6112, so the test separates exact and heuristic values.
  - `fail_soft`: depth-1 start value 297 (REVIEW-r2). With `alpha = 5000`, a
    fail-hard implementation returns 5000, so the test discriminates.
  - `depth_zero_fallback`: the lowest legal opening square is d3 (19).
- The test-side `minimax` is an independent statement of the contract:
  terminal before cutoff, a pass at the same depth, no pruning.

## Required

1. **The pass fixture isn't a pass position.** `pass_in_tree` and
   `caller_roots` use `me = b1` (`at(1, 0)`), `opp = a1 | c1`. Running
   `legal_moves` on it gives **d1** for `me` (b1 → c1 → d1 empty), and
   nothing for `opp`. So the setup assertions
   `legal_moves(board.me, board.opp) == 0` and `legal_moves(opp, me) != 0`
   will fail in GREEN. In `caller_roots`, `search(pass(pass_root), …)` would
   hit the "requires a legal root move" panic. The verified pass fixture from
   #68 is `me = b2` (`at(1, 1)`), `opp = a1 | c1`. There `me` has no move,
   `opp` has a3 and c3, and the position is not terminal (I re-ran it). Use
   that one in both tests.

## Minor

2. **Pin the terminal-root precondition.** The terminal half of
   `caller_roots` only re-asserts board facts. It never shows that `search`
   refuses such a root. Add
   `#[should_panic(expected = "...")] search(terminal, 1, &config)`. A pass
   root is the same case, because neither has a legal move. That pins
   "requires at least one legal root move".

3. **Check `best` against `score`.** `complete_depth` checks that `best` is
   legal, but not that it achieves `score`. Add
   `-negamax(play(START, best), 2, …) == result.score`. That catches a search
   that returns the right value with the wrong move.

4. **Fail-soft on the high side.** `fail_soft` covers a fail-low only. A
   one-line counterpart with a narrow window below the true value, such as
   `negamax(START, 1, -INF, 0)`, should return 297 (> beta), not 0. It pins
   true fail-soft at beta cutoffs too.

5. **The equivalence sample.** `minimax_equivalence` takes the first 100
   positions, which come from about two playouts, so they are highly
   correlated and mostly from two games' openings. Sample sparsely instead,
   for example every 7th visited position across more playouts, so
   midgame and late positions, including passes, are represented. The cost is
   the same.

Verdict: **approve** (RED). Proceed to GREEN.

- Items 2–5: `terminal_root_panics`, the `best` achieves `score` check, the

- `cargo fmt --check` passes, and the target fails only with E0432.

## Note for GREEN

- `terminal_root_panics` is not gated on `debug_assertions`, so it also runs
  under `cargo test --release`. The "legal root move" check must be
  `assert!`, not `debug_assert!`. Otherwise the release suite fails, or
  worse, `search` silently returns a garbage move on an empty move set.

# Re-review (round 3, GREEN)

Verdict: **approve**

## Verified

- The tests are unchanged since the RED approval. `./scripts/check.sh`
  passes, and `cargo test --release` passes, including
  `terminal_root_panics`, because the precondition is a plain `assert!`. The
  engine is 279 lines.
- `negamax` resolves terminal, then pass (same depth, swapped and negated
  window), before the cutoff. `best` is tracked apart from `alpha`, so it is
  true fail-soft. `?` propagates `None` immediately.
- `search` asserts a legal root, returns the lowest-index fallback with the
  static score at depth 0, and searches the root with a rising alpha.
  `value > score` keeps the lowest square on ties, so the result is
  deterministic.

## Nits (non-blocking, for budget)

- **Budget figure.** The notes cite a 110-line budget for `search.rs`.
  PLAN.md gives `search.rs` **210 lines for the finished file**: root,
  ordering, deepening, cancellation, and solver. Fixed-depth search alone
  already uses 95, about 45%. Correct the figure, and treat the remaining
  ~115 as tight for #83, #88, and #92.
- **One square iterator.** The `trailing_zeros` / `rest &= rest - 1` loop now
  appears in `perft`, `negamax`, and `search`, and ordering will add more. A
  `board::squares(bits) -> impl Iterator<Item = u8>` (about 4 lines) turns
  each loop into `for square in squares(moves)`, and pays for itself by the
  third use.
- **Build the `SearchResult` once.** The two struct literals differ only in
  their values. A small constructor, or computing `(best, score, status)`
  first, saves about 6 lines.
