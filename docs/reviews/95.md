# Review: Issue 95 — Dynamic corner risk without static X/C penalties (RED)

Verdict: **request changes**

## Verified

- #94 was merged and closed. This branch is based on the current `main`.
  fmt is clean. `corner_risk_disappears` fails as intended against the
  static table.
- The expected values are right under the stated rule (neutral −1, minus 49
  for X and 19 for C while the corner is empty):
  - b2 alone: −1 − 49 + 100 = **50**; b1 alone: −1 − 19 + 100 = **80**.
    Both are unchanged from the static table, as they should be.
  - a1 + b2, and a1 + b1: 100 − 1 + 200 = **299**.
  - b2 against an opponent a1: −1 − 100 + 0 = **−101**.

## Required

1. **Existing expectations that will change aren't listed.** Changing
   `evaluate` breaks tests that pin its old values:
   - `tests/eval.rs::mixed_table_sum`
     (`me = a1|h8`, `opp = b1|g8`) expects **240**. Both corners are owned,
     so under the new rule b1 and g8 are −1 each, and the score becomes
     200 − (−2) = **202**.
   - The frozen corpus expectations (`corpus_frozen`, `corpus_tt`,
     `corpus_preload`, and so on) are depth-4 snapshots "with the Phase 5
     evaluate config". Any line whose search reaches X/C squares next to
     occupied corners will move. The corpus header says to "regenerate only
     with a provenance note when the evaluator changes", and this is that
     moment.

   Name these in the RED notes as expected to change, and update them in
   GREEN with the provenance note. Otherwise GREEN looks like it rewrote
   failing tests to pass. The frozen `eval_phase2` in tools is deliberately
   untouched, which is correct.

2. **Only the a1 corner is tested.** Every fixture uses a1 with b1 and b2.
   A wrong mask for the other three corners (b7/a7/b8 against a8, g2/h2/g1
   against h1, g7/h7/g8 against h8) passes. The evaluator should be
   **D4-invariant**: the table is symmetric and corner risk is symmetric.
   Add a property test over seeded playouts that
   `evaluate(transform(b)) == evaluate(b)` for every `Sym` in `Sym::ALL`,
   using the shared `common` transforms (apply to `me` and `opp`). It catches
   any corner or X/C mapping error at once, and it stays valuable through
   #96's phase weights.
