# Review: Issue 82 — Iterative deepening with root-only previous best (RED)

Verdict: **request changes**

## Verified

- #81 was merged and closed. This branch is based on the current `main`.
  `cargo fmt --check` passes, and the target fails only with the expected
  E0432 for `search_iterative`.
- `id_matches_depth` checks the right contract: same score as direct search,
  `Complete`, depth `d`, not solved, and `best` achieves `score`.
  `id_zero_is_fallback` mirrors `search`'s depth-0 fallback.

## Required

1. **The pass fixture will panic, not test.** `id_matches_depth` includes
   `{me: b2, opp: a1|c1}`, the verified pass position, where the side to move
   has **no legal move**. Its first line is `search(board, depth, &config)`,
   which asserts "search requires a legal root move" (#73), so the test
   panics in GREEN no matter what `search_iterative` does. Callers handle pass
   roots. Either drop that board, or use `pass(board)`, which has a3 and c3
   for the mover.

2. **`id_root_ordering` can't pass at the start position.** The four opening
   moves are D4-equivalent, so at every depth they score the same, and
   `search` keeps the lowest square on ties: d3, which is already first in
   natural order. Putting the previous best first therefore doesn't change
   the root order at all. Iterative deepening's total equals the sum of the
   fixed-depth searches exactly, and `iterative.nodes < fixed` fails. The test
   needs positions where the previous best is **not** the lowest-index move.
   Sample positions from seeded `common::playout`s (non-terminal, with at
   least 2 moves), and assert on the **aggregate**: the sum of ID nodes is
   below the sum of independent fixed-depth nodes, and every score matches. A
   single-position strict `<` is fragile even off the start position,
   because a better first move doesn't guarantee fewer nodes in every tree.

## Minor

3. **Pin that iterations are thrown away.** The scope says "return the last
   completed depth's result". Without deadlines (#83) every iteration
   completes, so add only what is checkable now: `iterative.nodes` is at
   least the depth-`d` iteration's own count, so totals accumulate rather
   than reset. Or leave it to #83 and say so.

4. **"Stop deepening once the root is proven exact" isn't covered.** It is in
   the scope, but the PR defers solver early-stop to #83. If #83 owns it, move
   the clause in skis so #82's scope matches what it delivers.

# Re-review (round 2)

Verdict: **approve** (RED). Proceed to GREEN.

- Item 1: the pass fixture is gone from `id_matches_depth`.
- Item 2: `id_root_ordering` aggregates over 30 playout positions with at
  least 2 moves each, checks every score against direct search, and compares
  the summed node totals. Off the symmetric start position, the previous
  best is often not the lowest square, so ordering has something to do.
- Items 3–4: `iterative.nodes >= direct.nodes` pins accumulation, and the
  "proven exact" early stop now sits in #83's scope (checked in skis).
- fmt is clean, and the target fails only with E0432.

## Nit (non-blocking)

- The first 30 qualifying positions are consecutive plies of the first
  playout, mostly one game's opening and early midgame. Sampling sparsely
  (every 5th position across several playouts) gives the aggregate a
  broader base at the same cost.
