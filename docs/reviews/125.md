# Review: issue 125, classic and pattern agents; speed and diagnostics

## RED review round 1

Verdict: **changes requested** (small; tests only).

Good: the golden fingerprint now runs through `classic_config()`, which is
the strongest available proof that the copy is the 1.0.0 evaluator. The
agent description tests pin the evaluator name and threshold.

Required:

1. **`classic_antisymmetry` is weaker than the test it replaces.** The
   original ran 100 playouts; this runs one game of at most 100 plies.
   Restore 100 playouts.
2. **Tie the copy to the original while both exist.** Add a test that
   `eval_classic(board) == othello::eval::evaluate(board)` over the same
   playouts. It is temporary and #126 deletes it with the old evaluator;
   say so in a one-line comment.
3. **Keep the engine's `antisymmetry_and_bounds` until #126.** The old
   evaluator is still the engine's evaluator and still ships in
   `standard()`. The test moves when the code moves.
4. **Equal depth has no mechanism.** `pattern[:time]` and `classic[:time]`
   fix depth at 64, and `ab:depth` uses whatever `standard()` holds. State
   how the equal-depth match is expressed, with a test of the parsed
   depth. The smallest change that does it is fine (for example an
   optional depth on both new agents); do not add a general flag if a
   narrower form is shorter.
5. **The occurrence diagnostic needs the trainer's `counts.bin`**, which
   the tools crate cannot see. Put that diagnostic in a trainer example
   (examples are outside the production count) and name the file in the
   notes. State how positions are sampled from search at 3 s; a
   deterministic sample by node count is acceptable if a timed one needs
   engine hooks.

Process for the measurements:

- Before running anything, append the exact commands to the notes
  (pre-registration, as for #117), each writing a log with commit, date
  and elapsed time.
- The equal-depth and equal-nodes matches and the per-call timing do not
  depend on load and can run at any time.
- Nodes per second and depth at 3 s are timed. They run on a quiet
  machine from a worktree pinned at the approved commit, launched
  detached. Do not start them from inside a busy session; say when they
  are ready and wait.
- If the search rate is below half, stop and report the measurement and
  the proposed indexing change before implementing it. That change
  touches the engine and gets its own RED.
