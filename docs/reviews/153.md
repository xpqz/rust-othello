# Review: Issue #153 — Opening book builder, RED

Reviewed `39dd5af` (tests `248b9f1`), design amendment `39ca3c7`, and budget
change `0b605ce`. **Request changes on RED. Amendment 1 is Approved.**

## Amendment and clarifications

The counted trainer home and 2,000-line guard match the user's decision;
engine/tools/asset budgets remain unchanged. Recording the scoring evaluator
for provenance without requiring a rebuild on every retrain is acceptable.
An old book remains an offline move policy; its score must not be presented
as a fresh evaluation by the retrained model. Keep the exact build inputs
available for reproducing the old artifact, and retain journal mismatch
checks when continuing a scoring job. Serving an old completed book and
resuming a job with different scoring inputs are separate contracts.

I accept placement-only plies, contracted forced passes, and removal of the
unreachable second tie-break. Contraction correctly keeps the same mover
and sign across placement-plus-pass; reachability must likewise retain the
engine/opponent role across that combined edge. Please fold those rules
into `docs/design/book.md`, whose current partition/backup descriptions
still describe explicit pass nodes and unnormalized child keys. PR notes
alone should not supersede those implementation instructions silently.

## Blocking RED findings

### 1. The collection tests do not exercise a pass in collection

Location: `trainer/tests/book.rs:112–137`.

`count_contracts_passes` only calls `normalize`; it never invokes `count`.
`count_plies_are_placements` uses a ten-move game and only checks its first
two placements, where no pass occurs. A collector that never normalizes a
pass, advances its cutoff on passes, or omits the position after the last
recorded move can pass both tests. These are the exact collection rules
being clarified here.

Use a legal move sequence that actually reaches a forced pass. Call `count`
with a cutoff straddling that placement, and independently assert the
normalized board is present at the correct placement count, the unpassed
key is absent, and the next placement enters/exits at the specified cutoff.
Also cover an unfinished prefix's final recorded board inside the limit,
and a terminal final board. Retain the standalone normalization assertions.
Use literal independently replayed expected boards or a separate simple
replay oracle rather than deriving every expected key with `normalize`.

### 2. The promised drop-out boundary and emitted-asset cases are missing

Location: `dropout_order_and_depth`, `value_*`, `reachable_skips_terminal`,
and the `build_with`/asset tests.

The value-helper fixtures are good, but the actual `dropout` test uses an
early board. It does not force that path to encounter either an out-of-book
forced-pass child or a terminal child. A correct helper is not protection
against the caller passing an already-normalized child with the wrong sign,
using the wrong remaining depth, or bypassing the helper. Add those two
actual drop-out fixtures with the refusing recorder; assert sign, preserved
post-placement depth, chosen square and absence of terminal search calls.

Likewise `reachable_skips_terminal` covers the key-set helper only. Build a
small artifact containing a terminal node in the input and assert it has no
record in either binary or manifest. Verify the built binary records against
independent expected keys/squares/values and matching manifest records. The
current end-to-end check compares only manifest line count to binary length;
consistently wrong, empty, or mismatched payloads are not excluded by that
assertion. Include the retained-parent/removed-child artifact case, rather
than just asserting an immutable input map still holds its original move.

### 3. The preregistered bootstrap bound is effectively untested

Location: `trainer/tests/book.rs:582–595`.

The only upper-bound checks are `upper >= mean` and repeatability. Returning
`(mean, mean)` passes; so does returning the maximum, or a different
percentile. This bound chooses the depth for a multi-day run and was an
explicit design-review contract.

Add an independently computed expected percentile on the nonconstant
fixture (or a narrow numerical interval that distinguishes wrong choices),
plus equality-at-limit/highest-depth behavior for the decision rule. With
4 draws per resample using `Rng(150)` and the stated times, an independent
10,000-resample calculation gives an upper projection of **0.4444444444444444
hours**; both neighboring endpoint conventions give that value. The mean
is **0.2222222222222222 hours**. Pin a documented endpoint convention before
the pilot. The sampling fixture should also discriminate the fixed seed/
shuffle rule: repeatability and membership alone allow a roots function
that always returns the first n sorted keys, and the shuffle test permits
any fixed nonidentity permutation. A small independently calculated golden
selection is appropriate for this registered protocol.

### 4. Resume coverage does not establish reuse or the final result contract

Location: `trainer/tests/book.rs:696–754`.

The real SIGKILL and different worker count are useful. However, comparing
only completed sorted journal lines allows a resume implementation to
truncate the file and recompute every node. It does not prove bounded loss
of completed work. It also never builds the resumed journal to compare the
final asset/manifest, never exercises a torn last record, and does not
assert that refusing a changed header leaves the existing journal intact.

Add observable proof that completed IDs are skipped, a deterministic torn-tail
case, mismatch byte-preservation, and build/output equality after resume.
These need not become large or slow experiments. Keep the actual SIGKILL
check, but make its in-progress condition robust: the present polling loop
only sees “at least one line”, and a sufficiently fast release build can
finish before `kill`, failing the signal/partial-length assertions. Establish
an in-progress workload/handshake with bounded runtime and ensure a failed
poll cannot leave a child running. Verify the interruption test in debug and
release once GREEN exists. Do not add sleeps to production scoring merely
to make this test pass.

## Accepted test work

The complete partition and canonical transposition fixtures, positive sign
on contracted passing book edges, both-colour reachability, terminal scoring
with awarded empties, mandatory-root overflow, deterministic count/key
removal order, encoding validation, explicit scoring policy and cross-worker/
reordered-node comparisons are useful contracts. Sorted journal comparison
is appropriate: append order may vary, while record contents and the final
asset/manifest must agree. Thirty named tests were found in the committed
file. No implementation is requested in this RED revision.

## GREEN review — `0d07f2c`, with notes `796ecab` (16 Nov 2026)

**Request changes.** The 37 approved tests pass independently in debug and
release, and the core canonicalization, pass contraction, value signs,
child-first backup, protected-root truncation and encoding follow the design.
The blockers are in production input validation, pilot orchestration and the
long-running-job contract. Do not start #154's official pilot or scoring run

### Major: building does not validate its scoring inputs or records

Location: `trainer/src/book.rs:484–543`; `trainer/src/main.rs`, `build`.

`build` reads an arbitrary header and copies it to the manifest; the current
WTHOR input hash, N/ply definition and node set are never checked against it.
It recomputes a graph from today's CLI settings and combines that graph with
old drop-out results. A drop-out is defined relative to the node set, so
matching some node IDs is insufficient when that set changes. Duplicate
journal IDs silently overwrite, extra records are ignored, and an unvalidated
drop-out square can become an emitted illegal recommendation.

Independent probe: a one-node start-position journal headed **`unrelated
header`**, with payload **`123 0 | `**, builds successfully. Its emitted
square is **0**, which is illegal at the start, and the manifest repeats the
unrelated header. `encode` checks only square range, not move legality.

Validate the journal kind/version, complete unique unit set, node-set identity
and relevant collection inputs before backup/output, and validate each
record's drop-out classification and legal square/value payload. Refuse
incomplete/duplicate/foreign records and mismatched current data/collection
settings without writing outputs. A book built from an old evaluator is
allowed: derive the scoring policy/provenance from the validated journal,
without demanding that it match today's evaluator. Keep that amendment
separate from accepting a different node graph. Add CLI/build regressions,
including the illegal-square example and a changed node-set/input journal.

Related collection issue: `read_games` decodes but does not replay-validate;
`line` silently stops at an illegal move and `count` retains its prefix.
A supplied game `[19,19]` is illegal on move two yet contributes **two nodes**
in the independent probe. The approved design excludes illegal records as a
whole, while retaining valid unfinished games. Implement and test that
precise distinction and report rejected records. No existing WTHOR result is
claimed wrong: this probes the input contract.

### Major: pilot command does not implement the registered protocol

Location: `trainer/src/main.rs:133,193–216`; `trainer/src/book.rs:584–591`.

The shared defaults select **400 nodes, seed 151**, whereas the approved
pilot is **200 nodes, seed 150**. More seriously, the projection divides by
`jobs`; that is the number of workers used for this invocation, not the
registered target of **five threads**. Resuming identical pilot records with
a different `--jobs` changes the chosen depth despite doing no new work.

Separate gate-root defaults from pilot defaults; make the official pilot
select the registered sample, resampling seed and five-thread projection.
Worker count may remain a runtime setting, but must not silently change the
resource assumption of the decision rule. Put any explicitly supported
protocol overrides and projection parameters in validated provenance.

Pilot times are also read in append/completion order. Fixed-seed bootstrap
resampling is not permutation invariant for a finite draw stream. With the
same 20 times `[1,2,...,20]`, node count 18,877, five target threads and seed
150, the independent call to `projection` gives upper hours
**13.580952777777778** in forward order and **13.685825** in reverse order.
The mean is identical. Sort by stable unit ID before resampling; a resumed
or differently scheduled journal must produce the same decision from the
same saved measurements. Validate unique expected (node, depth) IDs and
finite nonnegative timings; a duplicate-ID pilot journal currently returns
both durations. Add a fast no-search regression using reordered saved
records, different resume worker counts and the CLI's registered defaults.

### Major: numeric/command validation must precede journal creation

Location: `trainer/src/main.rs:136–163`; `dropout`, depth subtraction.

The CLI parses `usize` and narrows with `as u32`. On a tiny one-game fixture,
**`--depth 4294967297` exits 0 and records depth 1**. **`--depth 0` creates a
journal and then panics** subtracting one in `dropout`. In release that
subtraction can wrap into an enormous search request. Repeated flags and
inappropriate subcommand options are silently accepted; zero jobs silently
becomes one. Empty/repeated/zero pilot depths can also create empty or
repeated units rather than a valid pilot.

Use checked target-type parsing and explicit sensible bounds for depths,
plies, counts, worker/table settings and finite positive limits. Reject
unknown, repeated, missing-value and command-inappropriate options before
reading/scoring/mutating artifacts. Validate required build outputs before
writing either file. Add cheap CLI rejection tests proving no journal/output
is created or changed; include the two demonstrated depth cases. Keep
library entry points from underflowing on invalid depth too.

### Major: the multi-hour runner has no periodic progress

Location: `trainer/src/book.rs:424–454`; CLI `score`/`pilot`.

`run_units` reports nothing until every unit finishes. The one final summary
cannot meet PLAN's requirement for units done/total, elapsed time and ETA at
least once a minute, including while a slow unit is in progress. The shared
runner is otherwise a useful place for this functionality. Add periodic
progress for both score and pilot, resume-aware counts, and an executable
short-interval test that sees progress before completion. Keep cancellation/
SIGKILL semantics and avoid a reporter that holds up shutdown or journal
writes. The existing SIGKILL, torn-tail and skip-count tests pass.

### Major: required final-artifact audit output is absent

Location: `truncate`, `build`, CLI build output.

The design commits to logging **every truncation** and **per-root coverage on
the final artifact before gate play**. `truncate` returns only the retained
set; the manifest and CLI report only node/record totals. Neither provides
the removal history or the promised root coverage, including the other
colour's first-move hit/miss behavior. Complete that audit path, with a
small fixture checking the actual reported removals and final coverage.
Bind the build's root-set identity and room/truncation policy in its output
provenance as well as the scoring header. Do not substitute game outcomes
or replace frozen roots. No new production measurement is needed to test it.
