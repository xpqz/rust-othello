# Review: Issue 96 — Phase-weighted evaluation and bounds (RED)

Verdict: **request changes**

## Verified

- #95 was merged and closed. This branch is based on the current `main`.
  fmt is clean, and `tests/eval.rs` fails only with E0432 for `phase` and
  `disc_weight`.
- The phase design is pinned before implementation, as PLAN.md asks.
  `phase(e) = (60 − clamp(e, 12, 60)) · 1000 / 48` gives 0, 500, 750, 1000
  at 60, 36, 24, 12, which matches the tests. Disc weight is `phase / 10`,
  so 0 at the opening and 100 at the 12-empty threshold, active exactly where
  the heuristic runs.
- The changes to existing expectations (`single_disc_values`,
  `mixed_table_sum`, and the corpus regenerated with provenance) are
  declared up front.

## Required

1. **The combination itself is untested.** The two new tests pin the
   `phase` and `disc_weight` helpers only. Nothing pins how `evaluate` uses
   them: mobility 500 → 800‰, frontier ×10 → ×4, corner risk 1000 → 700‰,
   table 1000‰, plus the disc term. The existing antisymmetry, D4, and bound
   tests hold for *any* sign-symmetric combination, so a swapped weight, a
   missed term, or an interpolation running the wrong way all pass. The
   acceptance says "phase endpoints/interpolation match expected". Add
   hand-computed `evaluate` values:
   - one **opening-phase** position (≥ 60 empties, where the disc weight is
     0, so the disc term must vanish) and one **endgame-phase** position
     (≤ 12 empties, but called directly, since `evaluate` doesn't care about
     the solver threshold);
   - one **mid-phase** position, where interpolated weights (for example
     mobility at 650‰ when the phase is 500) must show up exactly.

   For each, state the feature values (table, mobility, frontier, corner
   risk, disc difference) in a comment, so the expected number can be
   checked by hand.

## Minor

2. **Rounding order.** With integer per-mille weights, "interpolate then
   multiply" and "multiply then interpolate" round differently. The
   hand-computed tests in item 1 pin whichever order is chosen. State it in
   the phase-design notes, for example
   `w = a + (b − a) · phase / 1000; term = feature · w / 1000`.
