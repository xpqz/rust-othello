# Review of #155 — Opening book engine lookup

## RED review of `955aaa4b`

**Request changes.** The lookup tests cover the asset format, legality,
symmetry, and malformed data. Two integration tests need to distinguish
a book hit from a normal search before GREEN.

### Major — The agent fixture cannot detect a bypassed book

At `tests/book.rs:300` (`agent_reenters`), the first asymmetric record
`00000420160c0800:00003a1f08100000` stores square 24, and the unchanged
depth-3 search also chooses 24. The start record stores 19 and the
depth-3 search chooses 19 there too. The current RED failure comes from
the call to `book_move(...).expect(...)` before the agent is exercised.
Once lookup works, the test's opening hit can pass with
`SearchAgent::choose` still calling `search_tt` directly. The book-off
test uses the same nondiscriminating position.

Use a stored board where depth-3 search and the manifest move differ, and
assert that precondition independently of the lookup implementation.
Check the same board with book on and off. Keep the same-agent miss and
return-to-book sequence and use a distinguishing board for the last hit
as well, so the test detects an agent that stops consulting the book
after a miss.

### Major — Exercise the GUI's playing path

At `gui/src/main.rs:703`, `engine_book_policy` checks the configuration
flag but cannot detect `start_engine` continuing to call `search_tt`.
The approved design calls for a hit and miss through the GUI engine call
as well as the shared agent path.

Keep the shipped default off and avoid adding a public CLI flag or GUI
control for this gate. For the GUI, use a small private boundary in the
existing dispatch path that accepts a `SearchConfig`, then exercise it
with book enabled through the result channel or the normal result
handler. The hit should produce the book result with zero nodes and zero
depth, and the miss should produce the normal search result. Keep the
existing default-policy assertion. For the CLI, testing the shared
`SearchAgent` with a distinguishing fixture and verifying the existing
`play_game` delegation is sufficient here. The CLI has no separate
lookup or dispatch path to exercise with book enabled.

### Verification

Reviewed the SKIS issue and approved design, the committed RED changes,
the play callers, and the frozen configuration plan. An immutable archive

budget tests passed. A temporary test in that archive compared the two
agent hit fixtures against the current depth-3 search. The submitted diff
passed the whitespace check. Full cross-crate tests and clippy were not
repeated at this RED gate.

**Verdict: Request changes (RED).**
