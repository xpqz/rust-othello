# Review of #161 — Engine clock allocation

## RED review of `9c59bc28`

**Request changes.** The allocation examples, range tests and discriminating
`choose` fixture cover the main clock contract. The timeout harness needs
to stop the work it bounds.

### Major — A timed-out test leaves its search running

At `tests/clock.rs:53`, `bounded` discards the thread's join handle.
`recv_timeout` stops waiting and drops the receiver, but the worker only
touches that receiver's channel after `search_limited` returns. The
uncapped 40-empty search therefore keeps running after the test times
out, until the integration-test process exits. In a suite with more work
pending, it can compete with other timing tests. The design approval and
SKIS issue explicitly require the timeout to end the runaway search.

Use a killable child process with kill-and-wait cleanup, or a controlled
cancellation mechanism that stops and joins the worker. Keep the two
deadline assertions independent and retain the test where the current
RED stubs fail on admission. Verify the timeout cleanup on that expected
failure. This is a test harness change.

### Non-blocking suggestions

- Bound the seeded fixture search at `tests/clock.rs:233` or pin the first
  suitable board. Keep the proof that the zero-time fallback move is
  strictly worse than the exact optimum. The current loop has no failure
  bound if future search changes remove the distinguishing fixture.
- Strengthen `clock_book_hit` at `tests/clock.rs:282` with an evaluator
  that fails if called. A move-only assertion on the symmetric start board
  can agree with plain search. The evaluator guard would prove that an
  active clock still permits the book hit to bypass search.
