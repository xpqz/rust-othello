# Review of #162 — Tools clock control

## RED review of `83de116`

**Request changes.** The scripted tests exercise fractional accounting,
strict expiry, both flag colours and reporting. The following cases need
stronger assertions before GREEN.

### Major — The load fixture cannot detect an unrounded live limit

In `tools/tests/clock.rs:318`, the fractional-limit case feeds 6.0004
as both the sample and the limit. Comparing a rounded sample against
the raw limit gives the same acceptance decision as rounding both.
Formatting the header to three places can then satisfy the last
assertion independently. Use a sample such as 6.0004 with a limit
of 5.9996. Both round to 6.000 and the pair must be accepted live,
kept unchanged on resume, and included in standalone reporting.
Keep the rejection at 6.0006. Exercise the shared rule for flat
timed play as well as clocked play, as the approved design specifies.

### Major — The interruption fixture does not establish partial-pair recovery

At `tools/tests/clock.rs:405`, any line count from 3 to 12 before the
kill satisfies the test. A run interrupted between complete pairs
can pass without recovering a half pair. Replaying every completed
pair would also produce the same sorted deterministic payloads.
Keep the SIGKILL equivalence test and add an explicit interrupted
journal fixture with a complete pair and one half pair. Verify by
record ID that the complete pair was kept and that the surviving
half was replayed with its mate. A distinct accepted load on replay
can distinguish retained records from replacements. On a timeout
while waiting for progress, kill and reap the live child before
failing the test.

### Major — Real-time no-flag is unsuitable as the engine wiring assertion

At `tools/tests/clock.rs:434`, a properly wired search can still flag
on a loaded machine. The design charges elapsed time after the
move returns, and the solve fallback can overshoot the allotment.
Use a deterministic assertion that a search kind built from the
clocked name receives and uses the clock, with the time source
injected for charge and flag assertions. A real-time match can
remain an optional smoke test.

### Major — Pin the stopped-board score independently of flag points

The harness flag tests check plies, charges and points, and
`flags_scored` checks the report, but none asserts the score of the
stopped board. An implementation that applies the flagged move
without incrementing plies, or writes the flag outcome into the
score field, can pass. Use a fixture where the discarded move
changes the disc difference and the stopped-board score disagrees
with the forfeit points. Assert both, including the journal score
in its existing units. Add a scripted book-hit charge check and
assert that the pass fixture actually encounters a pass. The
current tests cover the book flag in configuration and the
accounting of generic agent calls.

### Choices beyond the design

- The tools budget change, report format, void stderr format and
  deferral of the paired time interval to #163 are acceptable.
  The ladder journal can use plies and the stopped-board score
  to test move discard without adding a move list to that format.
- The approved clock grammar attaches clocks to search time fields
  and rejects a clock with `--nodes`. The RED suite expands that
  public grammar to `random:c…` and `greedy:c…` and requires a
  clock-plus-nodes exception to drive the restart fixture.
  Keep the approved grammar for this issue or get approval for
  the extension before making it a test contract. Scripted elapsed
  time can force a real clocked search agent to flag on its first
  move, so the result is independent of the move it chose.
- An injected elapsed source is appropriate for CLI tests. If
  `OTHELLO_TOOLS_ELAPSED_MS` is available in production builds,
  include its effective setting in the journal identity when set,
  or confine it to the test path. The setting changes every
  clock debit and can change the result of a game. A resumed journal should not silently mix elapsed sources.

## RED re-review of `567d290`

### Major — The maximum-clock CLI fixture can start a days-long search

At `tools/tests/clock.rs:533`, the positive boundary test plays a pair
with `ab:2:c<MAX_CLOCK_MS>`. A clocked search starts with depth 64 and
an allocation based on the remaining game clock. At that cap the first
midgame deadline is measured in days. `OTHELLO_TOOLS_ELAPSED_MS`
replaces the charge after `choose` returns. It does not advance the
engine timer. The test exits promptly against the RED parser stub
and can stall the suite once the clock is wired.

Exercise the CLI boundary using the existing `--pairs 0` path. Check
that the accepted maximum writes a header with `control clock` and that
the first value above the maximum is refused. At
`tools/tests/clock.rs:374`, lower the no-flag journal fixture's
100,000 ms clock as well. A 200 ms clock covers even 60 scripted
3 ms calls by one player, while keeping the engine's per-move
allocations small.

The earlier findings are addressed. The load fixture now separates raw
and rounded decisions for both controls. The half-pair test distinguishes
retained records from replayed records by ID and load. Clock wiring has
a deterministic test, the real-time smoke is optional, and score, pass
and book charges have direct assertions. The grammar stays within the
approved design, and the elapsed override is part of journal identity.

A small fixture improvement would be to remove
`OTHELLO_TOOLS_ELAPSED_MS` from the child environment in the helper's
`None` case. That makes the override-removal assertion and optional
real-time smoke independent of the caller's environment.

Ran the tools formatting and Clippy checks and the release clock and
budget targets from an archive of the submitted commit. Both budget
checks passed. The clock target reproduced 20 expected RED failures
and one ignored smoke test. The submitted diff passed the whitespace
check.

## GREEN review of `db78d59`

**Request changes (GREEN).** The harness, grammar, load rounding and
restart tests pass. The standalone report can silently change the time
and flag totals it reads from a journal.

### Major — Invalid or missing clock data becomes a valid-looking total

At `tools/src/main.rs:150`, a missing or invalid charged time becomes
zero. At line 155, an unknown flag becomes no flag. In a two-pair
scripted run the correct result was `time a 20 b 10 flags a 4 b 0`.
Replacing one `black_ms 20` with `black_ms broken` changed A's mean to
15. Replacing one `flag black` with `flag unknown` changed A's flag
count to 3. Both reports exited successfully. A timed journal in the
previous format also reports zero times even though it never recorded
them. These totals feed the pilot clock and the gate's time comparison.

Require both times and a valid flag together when a record has clock
data, and require the fields on clock-control records. Preserve the
score report for older timed journals and omit their time summary or
mark it unavailable. Reject a partial or malformed telemetry record,
with its record ID in the diagnostic. Add report tests for malformed
clock records and the older timed format.

### Minor — Accepted elapsed values can overflow the report accumulator

The elapsed override accepts all `u64` milliseconds, while the writer
uses `Duration::as_millis()` and the reader and sum at
`tools/src/main.rs:150` and `:606` use `u64`. In the same two-pair run
with a scripted charge of `u64::MAX` ms, all four of A's charges fit
individually but the release report gave a mean of
4,611,686,018,427,387,903 ms. Its actual mean was
18,446,744,073,709,551,615 ms. Use consistent checked or wider arithmetic,
or reject an elapsed override outside a range the writer and report
both support.

## GREEN re-review of `86877b3`

partial and missing clock data in the tested cases. It preserves the

### Major — Resume can retain a clocked pair the report rejects

At `tools/src/main.rs:505`, the match resume path accepts
`parse_saved`'s `clock: None` without checking the control. The
clock-specific missing-data check at line 643 runs only during reporting.
I ran a two-pair scripted clock match, removed all three clock fields
from record `0:0`, and resumed with the same arguments. Resume returned
success and kept the journal byte for byte. Reporting that journal then
failed with `record 0:0: missing clock data`. The match can thus announce
completion while retaining a pair whose time and flags cannot be reconstructed.

Enforce the same requirement when resume retains a clock-control record.
Extend the missing-data test to resume a complete pair with a stripped
record and verify that the invalid pair cannot survive a successful run.
Keep the legacy timed-report behavior.
