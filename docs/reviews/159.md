# Review: Issue #159 — Rust build artifact routing

## Summary

**Request changes** on
`faf6657cf0e9a34f2a0c0fa49282ebaa7f553994`. The mounted-volume helper and
script substitutions are straightforward, and the configuration-only
workflow is appropriate. The new shell startup block needs to handle
inherited routing state before its isolation and local-fallback claims
are true.

## Findings

### Major: distinguish inherited managed routing from explicit overrides

Location: the submitted external change in `~/.zshenv:26–34`, described in
`docs/prs/159.md`.

The block only assigns CARGO_TARGET_DIR when the current checkout has the
helper and the volume is mounted. It never clears a value inherited from
a routed parent shell. A PWD guard does not remove exported variables.
Consequently, after starting in main and exporting its routed target:

- A child shell in `../othello-book-ext` inherits main's target even though
  that pinned worktree has no helper. A Cargo invocation there can now
  write to main's build directory, contrary to the isolation claim.
- A child shell outside all othello checkouts retains the same target.
- If the helper subsequently returns nothing (e.g. the volume is absent),
  the old external path remains selected, allowing Cargo to recreate it on
  the system disk instead of falling back locally.

Conversely, a fresh shell with an explicitly supplied CARGO_TARGET_DIR is
unconditionally redirected onto Space2. That prevents callers from
selecting a private scratch/build directory and undermines isolation for
review and measurement tools.

Track the exact target this routing mechanism owns, clear/recompute only
that managed value when the checkout or mount changes, and preserve a
caller-selected value. Cover the transitions, rather than testing only
fresh shells with an unset environment: main → pinned, main → another
routed checkout, main → unrelated directory, mounted → absent/same-device,
and an explicit custom target. The pinned worktrees must keep their local
targets when no explicit override was supplied. Put the reproducible
startup logic or exact installation snippet in the committed change so
this external part can be reviewed and reinstalled consistently. Do not
modify unrelated ghost/nars routing.

### Non-blocking layout and reuse precision

The issue describes a target per Cargo project; this submission deliberately
uses one target per checkout. That layout is reasonable provided checkout
isolation is fixed; record it as an explicit layout adjustment in the
issue/notes rather than treating the two layouts as identical. Also soften
“the engine is compiled once for all of them”: reuse depends on matching
profiles/features/flags. The trainer's default release profile and GUI's
dev override already differ from the engine/tools profiles. Sharing the
directory permits reuse; it does not promise exactly one engine build.

## Independent verification

Read #159 with comments, the committed diff, the actual new `.zshenv`
block, the two referenced repository helpers, all affected script paths
and crate profiles. The actual device IDs distinguish Space2 from `/` on
this machine. The helper prints the expected mounted path and nothing for
a nonexistent path or a repo-local same-device directory. All nine
submitted shell scripts pass `sh -n`; the actual `.zshenv` passes `zsh -n`.
Diff whitespace check passed.

An isolated ZDOTDIR under repo scratch contained a byte-for-byte copy of
just the submitted othello startup block. Fresh zsh subprocesses produced:

```text
fresh main:             /Volumes/Space2/othello/othello/target
fresh pinned:           UNSET
inherited pinned:       /Volumes/Space2/othello/othello/target
inherited outside:      /Volumes/Space2/othello/othello/target
inherited volume absent:/Volumes/Space2/othello/othello/target
explicit custom target: /Volumes/Space2/othello/othello/target
```

The last four cases reproduce the finding. No Cargo build was run and no
external-volume output, machine-global scratch, pinned binary or shell
configuration was changed by this review. The implementer's full checks
and two routed smoke-test passes are recorded in the notes; they were not
repeated because these environment-only probes already establish the
blocking behavior. Evidence remains in
`scratch/review-watch/159-routing.log`; the temporary ZDOTDIR is removed.

## Recommendation

**Request changes.** Correct ownership, propagation and fallback of the
managed target and return with transition-probe evidence. No Rust code,
long benchmark, target-directory deletion or unrelated shell setup change
is requested.
