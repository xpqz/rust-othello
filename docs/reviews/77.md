# Review: Issue 77 — Tools harness game loop, openings, and pair scoring (RED)

Verdict: **request changes**

## Verified

- #76 was merged and closed. This branch is based on the current `main`.
- The test target fails with the expected E0432 for `othello_tools::harness`.
- The core properties are well chosen. Identical deterministic factories over
  a colour-swapped pair must give exactly 0.5. Swapping two different
  deterministic factories must give scores that sum to 1. The odd-length
  opening `[c4]` exercises the side-bit toggle. A `None` with legal moves
  available must be an error, not a pass.

## Required

1. **`cargo fmt --check` fails on `tools/tests/harness.rs`.** It fails at
   lines 44 and 53: the long `assert_eq!` calls. `scripts/check.sh` runs fmt
   for tools, so the gate fails.

2. **`identical_pairs_draw` won't compile once `harness` exists.**
   `pair_score(..) + pair_score(..)` adds two `Result<f64, String>`, and
   `Result` has no `Add`. The E0432 hides this today. Unwrap both sides:
   `pair_score(&[26], &make, &chess).unwrap() + pair_score(&[26], &chess,
   &make).unwrap() == 1.0`.

3. **Pass and terminal roots aren't tested.** The scope and acceptance require
   "root with no legal placement: agent returns None, loop passes, score
   backs up correctly; terminal roots end the game". The PR describes
   `play_from` for exactly this, but no test calls it. Add:
   - pass root: `play_from(b2 / a1|c1 fixture, true, …)`, where the agent for
     the side to move panics if `choose` is called. That proves the loop
     passes without asking. Assert `passes >= 1`, and that the score has the
     right sign from black's view.
   - terminal root: `play_from(a1 / h8, …)` returns at once with `plies == 0`
     and the score from `terminal_score(final_score)`, mapped to black.

4. **An on-board illegal square isn't tested.** `OffBoard` returns 64, which
   tests the range check but not the legality check. Add an agent that returns
   `Some(0)` (a1) at the start position, where a1 is empty but illegal. "Reject
   illegal squares" is the release-mode validation the scope asks for, and it
   is the case that `play`'s debug assertion would otherwise mask in debug
   builds.

## Minor

5. **Run the tools tests in release.** The validation must hold "in both
   debug and release". `check.sh` runs the tools tests in debug only. For
   GREEN, add `cargo test --release --manifest-path tools/Cargo.toml --test
   harness` to the notes, or to `check.sh`. Release is where a missing
   explicit check would let an illegal `play` through silently.

6. **The win/draw/loss mapping is only tested symmetrically.** Each pair test
   comes out 0.5 or sums to 1, which a mapping such as `score > 0 → 0.75` would
   also satisfy. Pin one decisive game, for example a fixture game whose
   black score is known positive, so `pair_score` gives exactly 1.0 or 0.0
   for that pair, or unit-test the mapping (`+, 0, −` → `1, 0.5, 0`).

7. **Where the frozen openings come from.** The scope says "one frozen opening
   source in bench/". These tests pass inline openings. That is fine if the
   loader belongs to #80 (`positions.rs`), but say so in the notes so the
   scope item isn't silently dropped.
