### Non-blocking correction to the setup note

Remove the claim that competing load **can only** overstate the run and can
never choose a larger D. Contention can increase measured times, but this is
not a proven monotonic relationship or a bound on future runtime. A bootstrap
upper endpoint is an estimate from a finite sample, and the pilot excludes
table allocation/clearing and other builder overhead. Consequently its upper
endpoint is not a guaranteed upper bound on end-to-end build duration.

Keep the recorded load context; describe these as search-time sizing
estimates under the observed load. Apply the already registered arithmetic
D rule unchanged when the complete pilot arrives. This wording correction
needs no discarded observations, replacement sample, new run or change to
the fixed protocol.

For the results submission, retain the complete pilot journal/log and the
chosen-D calculation, then the complete scoring journal/log and final
asset/manifest including removal and per-root coverage audit. Check all
identities against this pinned setup. Book use remains behind the later
artifact review and clock-based gate.
