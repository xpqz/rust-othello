# Review: Issue #134 — choose the release profile by measurement

## Summary

Reviewed configuration and measurement submission `d8e3f12`. The evidence
supports retaining the engine's existing release profile and applying it
to tools. No blocking findings. This is a justified build-consistency
change; the notes correctly avoid counting its roughly 4% improvement as
a speed step passing the 5% gate.

## Findings

- Independently audited every raw round in the 18 profile-comparison logs
  and eight old/new tools logs. Node totals are unchanged throughout.
  Rotations 2 and 3 qualify on both workloads for every setting; the three
  rejected rotation-1 runs and rejected paired runs are retained. The
  qualifying off/16 versus fat/1 ratios are 1.03992 and 1.03919. Paired
  tools comparisons 3 and 4 reproduce 1.04236 and 1.03152.
- All six CLI logs contain the same 12 score/node results, totalling
  26,450,469 nodes. Independently summed elapsed times reproduce the
  table and its roughly 4% comparison. There is adequate agreement to
  support using tools with the same profile for subsequent measurements.
- The manifest matches the root release profile. The worker-builder
  overrides apply the same profile to both engine versions, including
  older commits lacking a tools profile. Independent builds against
  `c73af9f` and `039d59a` confirm one codegen unit, link-time bitcode for
  dependencies and fat LTO for the worker executable. Engine sources,
  assets, tests and the root manifest are unchanged.
- Independently built both tools profiles and confirmed the reported
  symbol distinction: separate `features` and `legal_moves` functions in
  the off build, absent from the fat build. Disassembly also shows the
  off build's call from evaluation to `features`. This supports the
  proposed explanation, with the notes' appropriate limitation that the
  entire timing difference has not been attributed to these changes.
- The plan documents the profile boundary and need to remeasure both
  sides of future comparisons. Previous same-profile ratios remain
  evidence; old and new absolute timings cannot be mixed.

### Minor, non-blocking: CLI timer starts after table allocation

`src/cli.rs` allocates `Table::new` before `Instant::now()`. The notes'
statement that each printed elapsed time includes table setup is
therefore incorrect. First-use evaluation initialisation and cold search
remain inside the timer, but table allocation does not. Correct this
description; it does not change the paired comparison or conclusion.

### Minor, non-blocking: round the small differences less tightly

In qualifying rotation 3, fat/16 versus fat/1 differs by about 0.75%,
rather than being within 0.5% in every comparison. Rotation 2's default
versus fat/1 exact minima differ by about 0.59%. Describing these as
“within about 1%” would match the logs. These small differences do not
challenge the choice or approach the 5% threshold.
