# Review: Issue 83 — Cancellation contract, fallback, and status (RED)

Verdict: **request changes** (small)

## Verified

- #82 was merged and closed. This branch is based on the current `main`.
  `cargo fmt --check` passes, and `tests/search.rs` fails with the expected
  E0432 and E0560.
- The three tests cover the cancellation outcomes. `time_ms = 0` gives
  `Fallback` with the static score. A budget that fits depth 1 but not
  depth 2 gives `Partial` with the depth-1 score, which shows the aborted
  depth-2 iteration is discarded. A one-node budget gives `Fallback`.
- The deferral to Phase 6 (solver, `solved = true`, threshold early stop) is
  recorded in #83's scope.

## Required

1. **`Complete` isn't tested.** The scope says "Complete when max_depth is
   reached", and it is the third status. No test runs `search_limited` with
   limits that don't bind. Add: `max_depth: 3`, generous time, and
   `max_nodes: 0` (unlimited) give `Complete`, `depth == 3`, and
   `score == search(board, 3).score`, with `best` legal. That also pins the
   "`max_nodes = 0` means no limit" rule, which is currently only in the
   notes.

2. **The "no deadline" value is undefined.** `time_ms = 0` means expired, so
   the tests pass `1_000` as a stand-in for unlimited. That makes them depend
   on wall clock: a slow CI machine running a debug build could, in
   principle, cross 1 s. Define and document an explicit "no deadline"
   (`u64::MAX` or `Option<u64>`), and use it in the node-limit tests, so they
   are purely node-driven and deterministic. PLAN.md says fixed-node runs are
   byte-identical.

## Minor

3. **Callers you'll break.** Adding `time_ms` and `max_nodes` breaks every
   `SearchLimits { max_depth }` literal: `tests/agents.rs` and
   `tools/src/main.rs` (two sites). Those aren't in the expected-failure
   list. List them, and in GREEN either update the literals or add a
   `SearchLimits::depth(d)` constructor, so callers stay one-liners.
   `search_agent` should probably move to `search_limited` here or in #84.
   Say which.

4. **Pin the node-limit boundary.** `max_nodes = depth_one.nodes + 1` avoids
   the edge. State whether the limit is inclusive (`nodes <= max_nodes`
   completes) and add the exact-boundary case
   (`max_nodes = depth_one.nodes`), so an off-by-one in the check is caught.

5. **Check `best` on `Partial`.** `node_limit_partial` checks score and depth
   but not that `best` is legal and comes from the completed iteration.
   Assert `best == search_iterative(board, 1).best`, or that it achieves the
   depth-1 score.

# Re-review (round 3, GREEN)

Verdict: **request changes** (two small fixes)

## Verified

- I re-ran `./scripts/check.sh` and it exits 0. The full release engine and
  tools suites pass. `NO_DEADLINE` is imported, so the round-2 condition is
  met.
- `negamax` increments, then checks, then returns `None`, and `root`
  propagates with `?`. The limit is inclusive (`nodes > max_nodes` stops).
  `search_limited` returns `Fallback` (depth 0), `Partial` (the last completed
  depth, below `max_depth`), or `Complete`, exactly as the scope says, and
  aborted iterations never replace `result`. `SearchLimits::depth`, the
  caller updates, and `search_agent` → `search_limited` all landed as
  planned.

## Required

1. **The deadline starts after the fallback is selected.** The scope says
   the clock "starts at search entry and includes fallback selection and
   ordering". `search_limited` calls `root_setup` (legal moves, fallback, and
   the static `eval`) first and only then computes
   `deadline = Instant::now() + …`. Compute the deadline as the first
   statement.

2. **A large `time_ms` panics.** `Instant::now() + Duration::from_millis(t)`
   panics on overflow for any `t` near `u64::MAX` that isn't exactly
   `NO_DEADLINE`, for example `u64::MAX - 1`, or a huge value from #84's CLI
   flag. The acceptance says "no panic". Use
   `Instant::now().checked_add(Duration::from_millis(t))`, and treat `None`
   as no deadline. That also lets `NO_DEADLINE` fall out naturally: map
   `u64::MAX` to `None`, or drop the special case and rely on `checked_add`.

## Nits (non-blocking, budget)

- **`search.rs` grew from 110 to 170 of its final 210.** Move ordering
  (Phase 5) and the root solver branch (Phase 6) still have to fit in about
  40 lines. Cheap trims now:
  - set `result.status = SearchStatus::Partial` in place (the fields are
    `pub`) instead of rebuilding the struct, which saves about 6 lines;
  - drop `Ctx::limited`'s four-argument constructor and build the struct
    inline in `search_limited`, keeping `Ctx::new` for tests.
- **The clock is read at every node.** `Instant::now()` in every `negamax`
  call costs real time once #84 sets wall-clock limits. Check the deadline
  every 1,024 nodes (`ctx.nodes & 1023 == 0`). The node limit can stay
  exact.
- `tests/agents.rs::search_legal` still compares the agent with
  `search(board, 2).best`, but the agent now uses iterative deepening, which
  breaks ties toward the previous best. Compare with
  `search_limited(board, SearchLimits::depth(2), &cfg).best`, so the test
  pins the code path the agent actually runs.
