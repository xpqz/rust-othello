# Review: Issue 101 — Harden performance with corpus and hardware context

Verdict: **request changes**: the TT is never used outside tests

## Verified

- #100 was merged and closed. This branch is based on the current `main`.
  I re-ran `./scripts/check.sh` and it exits 0.
- I reproduced the headline numbers on the release build:
  `perft 10` → 24,571,284 in 0.86 s wall time, and `bench --depth 9` →
  39,101 nodes, 4.4 M nodes/s, 8.9 ms. Every gate in the table passes on
  the recorded hardware (perft(8) 0.08 s, perft(10) 0.80 s, ≥ 1 M nodes/s,
  12-empty median 14.6 ms). Completion and p90/p99 are recorded, and the
  environment and corpus hash are given.
- The corpus depth 7–9 table records cold vs TT nodes and nodes/s, showing
  that the TT cuts nodes (0.72–0.82) at a small nodes/s cost. That is
  exactly the "record, don't trade blindly" condition the scope asks for.
- `MAX_ENTRIES = 1 << 22` × 16 B = 64 MiB, and `Table::new` clamps to it.

## Required

1. **No production path uses the transposition table.**
   `grep -rn "search_tt\|Table::new" src tools/src` finds nothing outside
   `search.rs`'s own definitions. `SearchAgent::choose` and `cli::bench`
   both call `search_limited` (no table), and `tools match` builds its search
   agents through `search_agent`. So:
   - the Phase 5 TT and Phase 6's endgame-bound reuse never run in a real
     game, in `bench`, or in any tools match;
   - every strength-ladder number in #100 and every tuning run in #99
     measured the engine **without** a TT;
   - the 64 MB cap this issue "checks" guards a table nothing allocates.

   #88's scope said "size the table at the 64MB cap at the call site", and
   no call site was ever added. Wire it in. `SearchAgent` owns a `Table`
   sized at `MAX_ENTRIES`, `choose` calls `search_tt`, and `reset` calls
   `table.clear()`. That is exactly PLAN.md's "clear between tools harness
   games; never share across agents" contract, and it is a handful of lines.
   Give `bench` a TT too (or a `--tt` flag), so the recorded nodes/s and
   time-to-depth reflect the engine as it actually plays. Then re-run the
   gate numbers that depend on search (bench nodes/s, time-to-depth, full
   game). Note in #100's record that its ladder predates TT integration.
   The ladder doesn't need re-running for this PR, but say so explicitly in
   the notes or open a follow-up.

## Nit (non-blocking)

- `memory_cap_is_64_mb` pins the constant's arithmetic, not the clamp
  (`entries.min(MAX_ENTRIES)`). A `Table::len()` accessor plus
  `Table::new(MAX_ENTRIES + 1).len() == MAX_ENTRIES` would test the
  behaviour.
