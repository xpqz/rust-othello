# Review: Issue 91 — WDL narrow window and exact widening (RED)

Verdict: **request changes** (small)

## Verified

- #90 was merged and closed. This branch is based on the current `main`.
  fmt is clean, and the target fails only with E0432 for `solve_wdl`.
- The tests cover sign agreement with the exact score (20 seeded positions,
  with a draw as exactly 0), WDL TT semantics (`Lower` for a win, `Upper` for
  a loss, `Exact 0` for a draw, all `Endgame` / depth 0), cancellation to
  `Fallback`, and widening through the trigger matching exact with
  `Complete` / depth 0 / `solved`.
- `wdl_stores_bounds` needs a draw among the first 100 seeded 6–8-empty
  positions. I replicated the sampler and solved them: **56 wins, 37 losses,
  7 draws**, so the `unwrap`s are safe.
- The widening windows are sound. Terminal scores are multiples of 100, so a
  WDL win means exact ≥ 100 inside `(0, INF)`, a loss means ≤ −100 inside
  `(−INF, 0)`, and a draw is exactly 0 inside `(−1, 1)`.

## Required

1. **A completed WDL-only solve isn't tested.** The status contract from
   #83 and PLAN.md Phase 6 both say "a completed WDL-only solve is
   `Partial`": the WDL pass finishes, the widening is cancelled, and the
   result is usable (correct sign) but not `solved`. No test reaches that
   state. Add one: on a decisive position, first measure the WDL pass's node
   count (`solve_wdl` with a fresh `Ctx`), then run `search_limited` with
   `max_nodes` just above that count, so widening aborts. Assert `Partial`,
   `solved == false`, `depth == 0`, and `score.signum() == exact.signum()`.
   Pick a position where widening needs more nodes than WDL, which a decisive
   6–8-empty position will.

## Minor

2. **`Ctx::set_table` is test-only.** It exists "so the tests can attach a
   table when calling the solver directly". A public method used only by
   tests is a test hook in `src`, which earlier acceptances ruled out. Either
   use it internally too (`search_inner` could build its `Ctx` through it), or
   test the WDL entries another way.

3. **Say what non-draw WDL values look like.** "Returns the sign" is in the
   notes. Pin it in `wdl_sign_matches_exact` (`wdl ∈ {−1, 0, 1}`), or state
   that the fail-soft bound value is returned instead. The caller only uses
   the sign, but the API should be unambiguous.

# Re-review (round 2)

Verdict: **approve** (RED). Proceed to GREEN.

- Item 1: `wdl_only_partial` measures the standalone WDL node count on a
  decisive seeded position, then runs `search_limited` with
  `max_nodes = wdl_nodes + 1`, so the widening aborts. It asserts `Partial`,
  `solved == false`, depth 0, and the exact sign.
- Item 2: `set_table` is committed to production use in the trigger. I'll
  check that in GREEN.
- Item 3: `wdl == wdl.signum()` pins the {−1, 0, 1} contract.
- fmt is clean, and the target fails only with E0432.

## Note for GREEN

- `wdl_only_partial` only works if the root trigger's WDL pass spends
  **exactly** the nodes standalone `solve_wdl` does. If the trigger runs WDL
  through `root` with different ordering, or counts the root node
  differently, its WDL pass may need more than `wdl_nodes + 1` and abort
  into `Fallback`. Make the trigger call `solve_wdl` itself, or have both
  share one code path, so the count transfers exactly.
