# Review: Issue 79 — Frozen baseline configurations and agent naming (RED)

Verdict: **request changes**

## Verified

- #78 was merged and closed. This branch is based on the current `main`.
  fmt is clean, and the target fails only with the expected E0432 and the
  missing `CARGO_BIN_EXE_othello-tools`.
- The `eval_pins` values match the #72-verified table (including d2 98 and
  c3 99), and the 6512 full board clamps to 6400.
- The agent names match PLAN.md (`random`, `greedy`, `ab:<depth>`,
  `phase2`). `phase2` is depth 4, and time control is deferred to #84.

## Required

1. **Random agents need seeds per pair and per game.** PLAN.md says "Agent
   and bootstrap RNG streams are derived separately from stable
   run/pair/game IDs and logged". The notes say factories build fresh agents
   for each game, and until #80 every pair starts from the start position. If
   a `random` factory reseeds with the same `--seed` every game, every pair is
   identical. The pair scores then have zero variance, the interval is always
   `Uninformative`, and `--pairs N` measures nothing. Add tests:
   - `random` vs `greedy`, about 10 pairs, `--seed 1`, run twice, gives
     **identical stdout** (reproducibility, the Phase 3 gate);
   - the same run does **not** have all pair scores equal, or `--seed 1`
     and `--seed 2` give different output. That proves streams are derived
     per pair and per game, not reused.

   Define the derivation, for example `seed ^ (pair << 1 | game)` mixed
   through the `Rng`, and log it.

2. **The configuration isn't checked in the output.** The acceptance says
   "the full configuration is recorded in runs", and the scope says
   comparisons are labelled evaluator-only unless a versioned engine artifact
   exists. `match_smoke` only checks `pairs` and `mean`. Assert that the
   output records the run configuration: both agent names and their resolved
   configs (for example `phase2 = eval_phase2, depth 4, threshold 12`), the
   `--seed`, the resample count, and the `evaluator-only` label where it
   applies.

## Minor

3. **Test `ab:<depth>` parsing.** Add `ab:2` as selectable, and `ab:x` and
   `ab:` as rejected with a clear error, next to `unknown_agent_rejected`.

4. **"Does not track evaluate" is only shown by value pins.** The pins prove
   today's values, not independence. A one-line source check in
   `tools/tests/baselines.rs`, asserting that `baselines.rs` doesn't contain
   `evaluate`, makes the freeze explicit. It is optional, since code review
   covers it too.

5. **The Phase 3 gate depends on #80.** Until frozen openings land, `phase2`
   vs `greedy` is deterministic from the start position, so all pairs are
   identical and the gate's "valid interval" can't be informative. Say in the
   notes that the gate run (`--pairs 200`) is checked after #80.

# Re-review (round 2, RED fixes + GREEN)

- `eval_phase2` is self-contained (its own table, `* 100`, clamp) and

## Required

1. **The match output makes a strength claim the policy withholds.** The
   report line doesn't say whether the interval is informative, and it prints
   an Elo range for degenerate intervals. Running `match --a greedy --b greedy
   --pairs 10 --seed 1` prints:

   ```
   pairs 10 … mean 0.5000 interval [0.0705, 0.9295] elo [-447.94, 447.94]
   ```

   That is the zero-variance Hoeffding fallback, which PLAN.md item 10 says
   "withholds a strength claim", presented exactly like a bootstrap interval,
   with Elo. Print the interval kind (`bootstrap` or `uninformative` /
   `insufficient`), and print Elo only when `summary.interval.informative()`.
   Add a test: greedy vs greedy, 10 pairs, output contains `uninformative`
   and `elo none`.

## Nits (non-blocking)

- **Streams can collide across seeds.** In
  `seed ^ (pair << 3) ^ (game << 2) ^ side`, the XOR is linear, so for
  example seed 1, pair 1 gives exactly the same stream as seed 9, pair 0. Two
  "independent" runs with nearby seeds then share games, shifted by a pair.
  Mix the seed first, for example
  `Rng::new(Rng::new(seed).next_u64() ^ id)`, or put `id` through a
  multiply, so different run seeds give unrelated streams.
- `--pairs 0` prints `mean NaN interval [0, 1]`. Reject 0 with an error, or
  print `insufficient`, which falls out of the fix for item 1.
- **Tools budget.** 348 of 600 is used, and `positions.rs` (120) plus
  `sym.rs` and the tune/positions commands are still to come. `main.rs` at
  110 is the largest unbudgeted file. Keep new commands lean.

Verdict: **approve**

- Item 1 is fixed. The same command now prints
  `interval [0.0705, 0.9295] uninformative elo none`. `degenerate_output`
  pins that, and that `--pairs 0` gives `insufficient`.

  352 of 600.

## Nit (non-blocking)

- The "Elo only when informative" rule lives in `main.rs`, while
  `Report.elo` is still filled in for uninformative intervals. Any later
  caller (`tune`, Phase 8 reporting) has to remember the gate. Moving it into
  `stats::report_with` (`elo: interval.informative().then(..)`) makes the
  policy impossible to bypass. `Interval::elo_range` can stay as the raw
  mapping that #78's test exercises.

Clear to merge.
