# Review: #112 RED (round 1)

Verdict: **changes requested.** The skeleton is right, but several tests are
vacuous, depend on accidents, or are missing. Issue tests 7, 9(c) and 9(d)
are absent.

## Required

1. **Restrict the supported depths to exactly the tested `d`** (issue:
   "the depths range limited to exactly the tested d"). The shared
   `probcut()` uses `(3, 12)`, so every interior node at depths 3-5 also
   runs the check.
   - `unsuccessful_probes_match_full_width` asserts `tries == [1, 1]` and
     equality with full-width. Both become false once GREEN lands, because
     children try and may cut.
   - Tests 3 and 4 pass only because the root happens to cut first.

   Give `probcut()` a depth parameter and use `(6, 6)` in tests 3-5.
2. **Test 2 is vacuous.** `exact_mode_ignores_probcut` solves a position
   with 6 or fewer empties under a domain of empties `(18, 52)`, so the
   check would never fire even in heuristic mode. `ProbCut::new` accepts
   empties `(0, 64)`, so use a domain that covers the solved positions.
   Then a zero try count shows the exact mode is bypassed, not the domain.
   Per the issue, cover several corpus endgames and some 13-14-empty
   positions, not one board.
3. **Test 6 lacks "depth outside the range".** Add a case whose depths
   range lies wholly above the search depth, for example depths `(8, 10)`
   with a depth-6 search, so that no node is in range and tries stay 0.
4. **Test 7 (cancellation inside a probe) is missing.** Choose `max_nodes`
   so the budget expires inside a probe. Find it by counting the nodes
   before the first probe, or by bisecting. Then assert:
   - the node returns `None`;
   - `search_limited` reports the documented `Partial` or `Fallback`;
   - `ctx.probing` is false afterwards;
   - no TT entry exists for the aborted node's key, using a fresh table.
5. **Test 9(b) is vacuous.** The planted `Selective` entry has `depth: 0`,
   which could never satisfy a depth-5 cutoff, so it is ignored whatever
   the domain. Plant it with sufficient depth (for example 64) and a wrong
   `Exact` value. Assert full-width ignores it: warm equals cold. Also show
   the planted entry *would* be used if it were `Heuristic`, so that the
   test is known to bite.
6. **Test 9(a) is half done and fragile.**
   - It checks one root child for `Selective`. If that child is cut by
     ProbCut, its only entry is the probe's `Heuristic` one, so the result
     depends on the position.
   - It never checks that probes write only `Heuristic`.

   Use a controlled setup, where the domain is exactly `d` at the root and
   the window gives unsuccessful probes. Assert two things:
   - the root's own stored entry is `Selective`;
   - an entry at depth `d' - 1` is `Heuristic` for a child of the probe,
     which only the probe searched.

   `probcut_off_writes_no_selective_entries` likewise checks only root
   children. Also check the root key.
7. **Add 9(c) and 9(d).**
   - (c) A planted `Heuristic` entry, at sufficient depth with a
     distinctive value, is used by a selective search. Its value must show
     up in the result, or the node count must drop.
   - (d) A heuristic-mode selective search neither reads nor writes
     `Endgame` entries. Plant a wrong `Endgame` entry and check that it is
     ignored and survives unchanged.
8. **Test 10 is thin.** The issue asks for the existing time and node-limit
   status tests to be re-run with the switch on, and for the move to come
   from the last completed iteration.
   - Add a `selective()` variant of the `Partial` and `Fallback` node-limit
     tests (lines ~313-399).
   - Add one time-limited run.
   - Assert that, under `Partial`, the move equals that of the completed
     shallower iteration.

## Notes

- The shared `probcut()` uses t = 1.5 and σ = 100, not the minimum `t` and
  σ the issue names. With a = 1 and b = 0 the thresholds are exact
  (`H = β + 150`), and test 3's boundary `H = v'` pins the rounding.
  Keeping them is acceptable, but say so in the notes.
- The files listed in the issue include `tests/tt.rs` (Entry stays 16
  bytes, which is already pinned) and `tools/src/baselines.rs` (the
  `probcut: None` literal). Those are GREEN, so mark them as planned in the
  notes.

## Required

# Review: RED (round 3)

right. `limit(1)` lets the root through (`nodes > max_nodes` is false at 1),
and the probe's first node stops. The `probcut_tries[0] == 1` assertion
proves the stop happened inside the probe.

## Required

1. **9(d)'s "planted entry survives" will fail at GREEN for the wrong
   reason.** `Table::store` always replaces. The high probe calls
   `negamax(board, d', H-1, H)` on the *same position*, so a correct
   implementation stores a full-width `Heuristic` entry at
   `zobrist(board)`, overwriting the planted `Endgame` entry.
   `table.probe(zobrist(board)) == Some(&planted)` then fails even though
   the provenance policy holds.

   Assert the actual requirement instead:
   - **No read:** keep `Some(beta)` equal to the cold run, and add
     `probcut_tries[0] == 1`, which shows the TT did not cut first.
   - **No write:** every `Endgame` entry in `table.entries()` equals
     `planted`. The planted entry may itself have been replaced.

Then RED is approved, and GREEN can start.

# Review: GREEN (round 1)

Verdict: **changes requested (size and notes).** The behaviour is correct,
and `check.sh` passes (engine 1,210, tools 1,148).

## Verified

- The check sits after the TT cutoff and before ordering, and runs only
  when `!exact && !probing && probcut.is_some() && supports(d, e)`.
- `probing` is reset before the `?` on each probe, so a cancelled probe
  cannot leave it set.
- Reads: selective nodes accept `Heuristic` or `Selective` entries, and
  probe nodes accept only `Heuristic`. Hints may come from either domain.
  Exact mode reads only `Endgame`.
- Writes: selective-mode nodes write `Selective`, including those outside
  the supported domain, whose subtrees may contain cuts, which is correct.
  Probes and ProbCut-off searches write `Heuristic`. `root()` stores only
  exact results.
- `standard()` stays `None`. Explicit `probcut: None` literals are added,
  and `Entry` is still 16 bytes.

## Required

1. **Keep the engine contained.** The engine grew by 75 lines against a
   20-30 estimate. Engine lines are what the Phase 2 budget is protecting.
   - The high and low probe blocks are near-duplicates, differing only in
     window, comparison, counter index and return value. Fold them into
     one small helper, for example `fn probe(board, d, lo, hi, ctx) ->
     Option<i32>`, which sets and clears `probing` around the call, or
     into a two-iteration loop.
   - `empty_count(board)` is computed twice. Bind it once.
   - The 13-line `Entry { … domain: if selective … }` literal duplicates
     `Entry::heuristic`, which production code no longer uses; only tests
     call it. Give the constructor the domain as an argument, or rename it
     (for example `Entry::search(key, value, depth, flag, mv, domain)`).
     Then use it at the store site and in tests.
   - `probing` and the two counters are initialised in three `Ctx`
     constructors (lines ~111, 402, 444). If those constructors can share
     a base (`..Ctx::new(config)` or a `Default` for the counters), do so.

   Aim for about 40-50 net lines. Record the before and after counts.
2. **An approved test changed silently.** At GREEN,
   `selective_search_writes_selective_and_probes_heuristic` swapped its
   probe-provenance assertion. RED checked for a depth-`d'-1` `Heuristic`
   entry. GREEN checks the root-key entry after a high cut, at depth `d'`
   with `Heuristic`. The new form is sound, arguably stronger, because no
   selective store follows the cut. But changes to approved tests go in
   the notes with the reason (AGENTS.md: notes are evidence). Add that
   note.
