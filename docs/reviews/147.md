# Review: Issue 147 — ProbCut engine RED

## Tests-first review — `c5be916`

### Summary

**Request changes before GREEN.** The suite has useful independent
full-width oracles, parameter injection, off-switch checks and a broad
arithmetic reference. One test contradicts the approved check, and some
central properties of recursive probes and exact-mode isolation are not
actually protected by the current fixtures.

### 1. Major: evaluation-boundary expectations are incorrect

Location: `tests/probcut.rs`, `unreachable_thresholds`.

With the injected `t=0`, the margin is zero. At window
`(EVAL_BOUND, EVAL_BOUND+1)`, the high threshold is outside range and skips,
but the low threshold is exactly `EVAL_BOUND` and remains valid. Its probe
fails low, so the designed check returns `Some(Some(alpha))`, not no cut.
At `(-EVAL_BOUND-1, -EVAL_BOUND)`, the high probe is valid and cuts at beta.

Independently exercised the existing depth-2 oracle on the first midgame:
full value 439; the upper-edge low probe returns 3,695 <= 6,400, and the
lower-edge high probe returns -361 >= -6,400. Thus the specified check
would return bounds +6,400 and -6,400 in these two cases. These are valid
opposite-side decisions, not unreachable probes.

Test each skip without forbidding the other direction: for example use
`(-INF, EVAL_BOUND+1)` and `(-EVAL_BOUND-1, INF)` with this zero margin,
or assert the valid opposite-direction cuts in the narrow edge windows.
Do not add an unexplained engine bypass just to satisfy these assertions.

### 2. Major: bind option B with a deterministic nested-probe test

Most branch tests deliberately support depth 6 only, so their depth-2
probes cannot run ProbCut. That is good isolation of individual branches,
but it does not test recursive probes. `selective_search_cuts` requires
only fewer nodes; a full-width-probe implementation could satisfy that
property too.

Add a deterministic case in which a probe itself makes a ProbCut decision
and assert the top-level result plus nested try/cut evidence. A constant
nonterminal evaluator, an early board, supported depths 3–12, zero margin
and an outer depth-12 check is one small construction (12 probes to 6,
then 6 to 2). The test must fail if ProbCut is suppressed inside probes;
it need not pin incidental node totals.

### 3. Major: the exact-mode fixture can pass without an exact-mode guard

Location: `exact_unaffected`; current solver's `EXACT_ORDER_DEPTH = 2`.

The exact solver carries nominal depth 2 through its recursion. The test's
model uses shallow rule 0, which is invalid at depth 2. Consequently the
check can skip solely because of its shallow-depth rule, even if the
explicit exact-mode guard is missing. Result/node equality under that
model does not establish that exact mode disables the mechanism.

Inject a model whose check would be eligible at depth 2 in heuristic mode
(for example the public gap-1 rule), and verify zero tries/cuts through the
public exact-search context as well as unchanged results/work. Include an
actual 14-empty fixture: the corpus cases used here have 5–12 empties,
plus the constructed 18-empty case, despite the comment claiming 14/18.

### 4. Major: test cancellation through the caller and table store path

`cancelled_probe` establishes the public check's direct return, but not
that `negamax` propagates it, shares the node budget with probe work and
avoids storing the interrupted node. `legal_under_limits` asserts only a
legal square, which a stale/static result also satisfies.

Add a deterministic integration case aborting inside a probe called by
`negamax`, with the parent table entry absent afterwards. Also cover the
root's Partial/Fallback/last-completed-depth contract with ProbCut on,
using a bounded node control that actually reaches a probe. Keep probe
nodes in the same budget/accounting; do not merely check move legality.

### 5. Arithmetic/domain coverage needs independent field values

Location: `threshold_limits` and domain tests.

The matrix sets `s0 = s1 = s2` and `a_milli = b`. It cannot catch swapped
depth/empties coefficients or reading one of the slope/intercept fields
in place of the other. Add a few independent basis and mixed-sign cases,
with independently varied slope/intercept; a huge Cartesian product is
unnecessary. Compare `ProbCut::sigma` with the reference value, not just
its clamp range, including fractional positive inputs.

Include a malformed/out-of-domain large-depth case with extreme
coefficients that must return before arithmetic, and positive boundary
cases where `e_min = e_max = actual empties`. These protect the stated
short-circuit and inclusive-rectangle contracts rather than only ordinary
small coefficients and interior empties.

### Accepted refinements and GREEN contract

- Injectable `shallow` is a reasonable way to represent the approved rule
  choices. Defer fitted constants and named `pc:` agents as stated.
- Rounding sigma upward is a conservative refinement, but it must be
  recorded consistently in the design/fitter: issue 146's emitted-model
  validation must use this exact integer rule too.
- Existing goldens, explicitly-off frozen baselines and node counts remain
  binding. Use explicit `probcut: None` in full-width oracle/off fixtures
  so a later enabled `standard()` cannot silently change their meaning.
- The GUI helper test is useful. GREEN review must also verify that the
  actual engine-launch path calls that helper; testing an unused helper
  alone would not establish policy-safe GUI play.
- Record off-switch overhead against the parent as promised. No fitted
  model, tuning run or enablement is approved by this RED gate.
- Shorten the new names exceeding two underscores, including
  `empty_rectangle_is_off`, `cleared_table_is_full_width` and the GUI's
  `setting_change_clears_table`, to follow the working agreement.

### Independent verification

- `cargo test --test probcut --no-run` on an immutable submitted-source
  snapshot fails on the intended missing API/configuration/counters.
- Independently ran the existing full-width engine for the edge-window
  reproduction above. No ProbCut implementation was written or run.
- Root, tools and GUI formatting pass. The corpus empties and solver's
  fixed nominal depth were checked directly against source/data.
- No full suite was run for a RED tree lacking the proposed API. Reviewer
  probe sources and build output were removed; verification logs remain
  under repo-local scratch.

### Recommendation

**Request changes** — correct the boundary assertions and add binding
recursive, exact-mode, cancellation and independent-field coverage, then
resubmit the RED tests. Keep implementation paused at this gate.
