# Review: issue 121, WTHOR reader, replay and check

## RED round 1 (commit 710fa2c)

Verdict: **request changes**. The shape is right; several tests cannot
fail for the mistakes they are meant to catch.

Good:

- The fixture has four forced passes and ends with an empty square, so it
  exercises pass insertion and the empties-to-winner rule.
- `Reject::Illegal { ply }` and `Reject::Incomplete` as separate reasons.
- The SHA-256 of `abc` is the right constant.

Required:

1. **Move decoding is only tested on symmetric squares.** Bytes 11 and 88
   decode to 0 and 63 whether rows and columns are read the right way round
   or swapped. Add the asymmetric cases: 18 (h1) is square 7, 81 (a8) is
   square 56, and 56 (f5, the first move of every game in the format
   document) is square 37.
2. **The known game cannot catch a swapped reading either.** It was encoded
   by the same convention that decodes it. Requirement 1 covers this; say
   so in the notes so nobody takes `known_game` for an orientation test.
3. **An invalid move byte.** A record with a byte that is not a square (19,
   or 99) must be a per-game rejection, counted in the summary, not an
   error that abandons the file. Add the test and decide the reason
   (`Illegal` at that ply is fine).
4. **Header rejections.** P1 = 10 (a 10x10 file) and P2 = 1 (a solitaires
   file) must be refused by `read`. Add both.
5. **The summary is only tested on agreement.** A stub that returns the
   replayed count for `real_agree` and `theoretical_equal` passes. Add a
   complete game whose real score is wrong (`record(&GAME, 9, 8)`) and one
   whose theoretical score differs (`record(&GAME, 8, 20)`), and assert
   both counters.
6. **Manifest.** `verify_file` on one file is tested; the manifest is not.
   Add a test over a two-line manifest in `shasum -a 256` format with one
   good and one bad entry, and one for a file named in the manifest that is
   missing. State what `check` does with a `.wtb` file that the manifest
   does not list (refuse is the safe choice).

For GREEN, not tests:

7. The 99% real-score agreement can hide a wrong convention if it only
   bites on a minority of games. In `docs/tuning/wthor_check.log`, report
   agreement separately for games that fill the board and games that end
   with empty squares, and within the second group separately for black
   wins and black losses. If one group disagrees systematically, the
   reading of the real score is wrong for that group: stop and report.
8. The files are already in `data/wthor/` (49 files, 137,548 games by
   their headers, all with P3 = 24). Generate the manifest from them.

Note for issue 123, no action now: labels need to know which colour is to
move at each position, and that depends on the passes. `Replay` knows it;
keeping it there will be cheaper than deriving it again.
