### Major: Add the promised corpus score and optimal-move checks at depths 1–8

Location: `tests/search.rs:151–209`, `tools/tests/golden.rs:379–414`;
SKIS #135, first RED test requirement.

The issue calls for the corpus to retain its scores at every depth from
1 through 8, with changed best moves accepted only when their child value
proves them equally good. That test is absent. `window_equivalence` uses
the synthetic `noise` evaluator, one selected depth per position, and
checks only the TT result's chosen move. The existing standard-evaluator
golden remains a depth-8 snapshot; `fewer_nodes` checks only node totals.
Existing depth-4 corpus tests do not fill the missing depths either.

Before changing the search, record the original engine's corpus scores
for all eight depths and add executable comparisons against that fixed
reference. Cover the search entry points being changed and validate the
chosen move's value, so legitimate ties can pass without blindly
re-recording a changed best move. Preserve the pass-root and terminal
conventions and the exact-solve cases. When checking a chosen child,
preserve the original root's heuristic/exact domain: calling a top-level
search on that child can otherwise activate the endgame threshold one
move earlier than the original search.

The reference scores must remain fixed when the node columns are updated
in GREEN. A release-only placement for the expensive coverage is fine;
this does not need to make every debug test run slow.

### Major: Reject out-of-range move indices before shifting

Location: `tools/tests/golden.rs:597–603`, `agrees`.

The new corpus check runs in release mode, where shifting by an invalid
move index can wrap. Its legality test computes `1 << result.0` without
first requiring `result.0 < 64`, and `play` also uses that index. A result
containing the no-move sentinel 64 can consequently be treated as square
0 and pass both the legality and independent-child-value checks.

Reproduced against the unmodified helper in a scratch copy of the test
file. For `GOLDEN_V2[3]`, depth 8, the reference is move 0, score 2527.
Calling `agrees` with result `(64, 2527)` and expected `(0, 2527)` returns
normally in the optimized build. A `#[should_panic]` probe therefore fails
with "test did not panic as expected". The guard currently accepts an
illegal move as an equally good alternative.

Check the index range explicitly before any shift or child construction,
then check legality. Add a regression exercised by the release golden
suite that rejects sentinel 64 on this known corner-0 position. Keep the
existing checks for legitimate tied moves.

### Implementation assessment

The first child receives the full window. Later children receive the correct
negated unit window; a strictly interior result triggers a full re-search
before alpha is updated. Unit-width callers avoid a redundant probe. Child
boards are reused, cancellation propagates through both searches, and TT
flags remain classified against the actual call's original bounds. This
applies to heuristic and exact search without introducing selective pruning.

The golden diff changes only the 20 nontrivial `GOLDEN_V2` node counts;
recorded moves and scores, `GOLDEN_V1`, `DEPTH_SCORES`, and the original

to 17,151,669 midgame and from 7,811,100 to 6,583,100 exact. These are node
reductions, not a substitute for the pending timing gate. The reported cutoff
