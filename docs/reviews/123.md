Required:

   side-relative, so a pass swaps `me` and `opp`; the test uses one board
   value twice with different colour flags. And a position where the mover
   must pass never appears in `Replay.positions`. What the test checks is
   that an anchor value is converted to the other colour. Keep it, rename

     rise after a white move and must not fall after a black move, and the
     chain ends at the final result (+48 for black). A wrong colour across
     a pass breaks this. State in the notes at which plies the four passes
     fall; if none is inside the last 10 empties, widen the range until
     one is.
2. **The theoretical band is only tested with black to move.** Add a

3. **Band boundaries.** Positions with exactly 24, 23, 15 and 14 empties:

4. **The journal line is never read back.** The fit will depend on it.

   game (skipping it without a line is fine) and test it with one such

7. **`--jobs` and `--games`.** Run the resumed leg with `--jobs 2`, and

## RED round 2 (commit ebe0068)

Verdict: **request changes**, one test, and the fault is in my round 1
wording.

Points 2 to 7 are done as asked. I rechecked the six expected values in
`label_bands` by hand; they are right.

Required:

1. **`pass_chain` asserts the inequality the wrong way round, because I
   stated it the wrong way round.** Taking values from black's side:
   - Black picks the move. The exact value before the move is the best
     black can reach, so after black's actual move the value is the same
     or lower. It must **not rise after a black move**.
   - White's best move gives the lowest value for black, so after white's
     actual move the value is the same or higher. It must **not fall after
     a white move**.

   The test has `next >= value` after black and `next <= value` after
   white. Swap them, and fix the two messages. As written the test would
   fail on a correct implementation whenever a player misses the best
   move.
2. **The chain should end with the final result as one more link, not as
   an equality on the last label.** The last label is the exact value of
   the last position where someone moved. It equals +48 only if that last
   move was the best one. Append `(_, 48)` to the chain so the same
   inequality covers the final step, and drop
   `assert_eq!(chain.last().unwrap().1, 48)`.

Nothing else changes.
