   - Black picks the move. The exact value before the move is the best

## GREEN round 1 (commits 61ce3c2, 15a5552)

Verdict: **request changes**. One wrong-result bug, then size.

### 1. Sign bug: white-to-move positions at 14 or fewer empties

For a position that is not the anchor, `labels` puts `solve(board) / 100`
into `black_value`. That value is for the player to move, not for black.
The last line then negates it for white, so every white-to-move position
below the anchor gets the opposite sign.

I labelled the known game and compared each late label with a direct solve
of the same board:

```text
empties 14 black true  label 62 direct  62
empties 13 black false label 62 direct -62
empties 12 black true  label 62 direct  62
empties 11 black false label 42 direct -42
empties 10 black true  label 50 direct  50
empties  9 black false label 30 direct -30
empties  8 black true  label 48 direct  48
empties  7 black false label 26 direct -26
```

Four of four white-to-move labels are wrong. In the archive that is close
to half of all exact labels. The pilot journal contains them, so the pilot
figures stand as timing only.

Why the tests missed it, both my doing:

- `pass_chain` cannot see this in a lopsided game. With black far ahead, a
  negated white value is a large negative number between two large positive
  ones, which satisfies "not up after black, not down after white".
- `label_bands` has no white-to-move position in the own-value band other
  than the anchor.

Required:

- Fix the rule. In the own-value band the label is simply
  `solve(board) / 100`; no colour is involved.
- Add `exact_labels`: for every position of the known game with 14 or
  fewer empties, the label equals a direct `search::solve` of that board
  divided by 100. This is the test that would have caught it.
- Add a white-to-move position at 10 empties to `label_bands`.
- Keep `pass_chain`; it still guards the colour flags.
- Rerun the pilot and replace the log.

### 2. Size: 513 lines, `scripts/check.sh` fails the budget test

The labelling code is 263 lines. Much of it is plumbing that the crate
already has or that a dependency does better. Reduce it; I expect about
half.

- **`labels`** carries `anchor` and `anchor_value` as two options and
  matches on the pair twice. Compute one optional black-side anchor value
  up front. With the fix above the loop body is three short branches.
- **`run`** hand-rolls a thread pool with five atomics and an error list.
  The trainer may use `rayon`: a parallel iterator over the tasks with
  `try_for_each` does this in a fraction of the lines, and the summary
  counts can come from what it returns.
- **`inputs`** lists `.wtb` files and reads P3 from the header bytes.
  `check.rs` already has `wtb_files` and `wthor::read` already returns P3.
  Share them.
- **`header`** re-implements FNV mixing by hand. `sha2` is in the crate:
  hash the file names and contents with it in a few lines.
- **`tasks`** and `inputs` can be one pass.
- **`label_command`** spends 40 lines on two flags and two positionals.

Report the count after this. The budget itself is still the user's call;
I will put the measured number to them.

### Budget decision from the user (11 November)

The user's ruling: drift in the trainer's size is tolerated, provided the
code is disciplined and as compact as it can be without tricks. The
reviewer vouches for that at every issue.

What this means in practice:

- The trainer's guard moves from 450 to **650** lines. Change
  `trainer/tests/budget.rs`, `docs/PLAN.md`, `AGENTS.md`, the size note in
  `src/lib.rs` and the budgets table in `docs/design/pattern-eval.md`, in
  this issue.
- 650 is a tripwire, not an allowance. It exists so that growth beyond it
  is discussed with the user first.
- Compactness is now judged in review, not by the number. Every item in
  section 2 above still stands and is still required. Expect the same
  scrutiny on each later issue: shared helpers instead of copies, a
  dependency where it replaces plumbing, no parallel structures.
- The rules against tricks are unchanged: no cryptic names, no squeezed
  formatting, no moving code out of `src` to dodge the count.
- The engine is not affected. Its ceiling and the evaluator's 230 lines
  stay hard.
