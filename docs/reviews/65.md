# Review: Issue 65 — Add LOC and test-separation guards plus check script

Verdict: **request changes**

## Verified

- #64 was merged with a recorded approve, and #64 is closed. This branch is
  based on the current `main`.
- `./scripts/check.sh` exits 0. It is executable and uses `set -euo pipefail`.
- The engine scope is `src/`, and `build.rs`, `rustfmt.toml`, and
  `.rustfmt.toml` are rejected. `tools/target/` is covered by the existing
  `target/` ignore rule.
- The PR reports manual negative checks for the line limit and `#[cfg(test)]`.

## Required

1. **The counter can be made to skip real code.** I extracted `code_lines` and
   ran it on fixtures:
   - `let s = "/*";` followed by two code lines counts **1**, not 3. A `/*`
     inside a string starts a "block comment", and everything up to a later
     `*/` disappears from the count. That is exactly the kind of loophole the
     guard exists to close.
   - Nested `/* a /* b */ c */` over-counts. That direction is harmless, but
     it shows the parser doesn't model Rust.

   The simplest sound fix uses the project's own comment rule: **reject `/*`
   in production source** (comments must be `//`, `///`, or `//!`), and count
   non-blank lines that don't start with `//` after trimming. The block-comment
   state machine goes away, and so does the loophole. If you keep block
   comments instead, the scanner has to understand string and char literals,
   which costs more code.

2. **The counts are not reported.** The acceptance says "report actual
   counts". The `println!` output is captured by the test harness, so
   `check.sh` prints no count (I checked by running it). Run the budget step
   as `cargo test --test budget -- --nocapture`, and the same for tools. That
   also gives the separate invocations a purpose. Today they only repeat what
   `cargo test` already ran.

3. **The counter has no tests.** `code_lines` is the whole guard, and it is
   checked only by hand. Add a fixture test: `//`, `///`, `//!`, blank, a code
   line with a trailing comment (counted), and, if item 1 keeps them, block
   comments and `"/*"` in a string. With the fix from item 1, also add a test
   that `/*` in `src` is rejected.

4. **The guard is copied in full.** `tools/tests/budget.rs` repeats all 80
   lines of the engine guard, differing only in names and the limit. Two
   parsers will drift, and a fix like item 1 has to be made twice. Share one
   copy, for example with `tools/tests/budget.rs` pulling it in via
   `#[path = "../../tests/budget/rules.rs"] mod rules;`. The `#[path]` ban
   applies only to production source. Alternatively, let the engine's
   `tests/budget.rs` check both trees with their two limits, and keep
   `tools/tests/budget.rs` as a thin call.

## Minor

5. **The scope check misses near variants.** `include_str!` and
   `include_bytes!` aren't caught (the substring `include!` doesn't match
   them), and neither are `#[test]`, `cfg(all(test, …))`, or `cfg_attr(test,
   …)`. Match `include_` / `include!`, `cfg(test`, `test,` inside
   `cfg(`/`cfg_attr(`, and `#[test]`, or simply reject the substrings
   `include` + `!` and `test` inside any `cfg`. Data hidden in `include_bytes!`
   would be another way around the budget. Note that plain substring checks
   will also fire on doc text that mentions these. That is acceptable, but say
   so in the doc comment.

6. **The tests rely on the working directory.** `Path::new("src")` works
   because cargo runs integration tests from the package root. Using
   `Path::new(env!("CARGO_MANIFEST_DIR")).join("src")` makes that explicit
   and doesn't break if someone runs the binary directly.

7. **`tools/Cargo.toml` doesn't depend on `othello`.** PLAN.md says the tools
   crate path-depends on `othello`. Add `othello = { path = ".." }` now, while
   the lock file is trivial, so later issues don't each re-touch the manifest.

8. **"Formatted" lines.** The count assumes rustfmt has run. `check.sh` runs
   `fmt --check` first, so that holds in the gate. The doc comment should say
   the count is only meaningful on formatted source.

# Re-review (round 2)

Verdict: **approve**

## Verified

- `./scripts/check.sh` exits 0 and now prints both counts: engine 40,
  tools 0.
- Item 1: the state machine is gone, `/*` is rejected in production, and the
  counter is non-blank lines not starting with `//`. A string containing `"/*"`
  now trips the scope check instead of hiding lines, so the loophole is
  closed. Lines inside multi-line string literals are counted, which is the
  safe direction.
- Item 3: the fixture test covers the comment forms, a trailing comment, and
  the main rejections.
- Item 4: there is one copy of the rules in `tests/budget/rules.rs`, used by
  both crates through `#[path]` in test code only. `tests/budget/` has no
  `main.rs`, so cargo does not treat it as an extra test target.
- Items 5–8: the scope checks are broadened and the false-positive risk is
  documented. Roots come from `CARGO_MANIFEST_DIR`, `tools` path-depends on
  `othello`, and the formatted-source caveat is documented.

## Nits (non-blocking)

- `budget_guard` calls `check_scope` again, which duplicates the
  `source_scope` test, and the tools test does the same. Drop one of them.
- The fixture test doesn't cover `include_bytes!` or `cfg_attr(test, …)`.
  Two one-line assertions would pin the broadened rules.
- PLAN.md's file layout doesn't list `tests/budget/rules.rs`. Add it, as was
  done for `tests/rng.rs`.
