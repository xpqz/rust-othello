# Review: Issue 71 — Differential, perft, symmetry, and invariant tests (RED)

Verdict: **request changes**

## Verified

- #70 was merged and closed. This branch is based on the current `main`.
  `./scripts/check.sh` passes, and the engine is unchanged at 159 lines.
- Release `movegen` + `invariants` with `--include-ignored` passes
  (14 + 2). The 200k differential takes about 0.59 s, as reported.
- The differential compares the full legal set and the post-move board for
  every legal move at every visited position, through the shared `playout`,
  which now includes terminal positions.
- Perft and symmetry coverage already exist from #68 and #69. #71's scope was
  updated accordingly.

## Required

1. **`invariants.rs` doesn't use the shared `playout`.** The PR says "Random
   playouts drive both the differential and invariant checks through the
   shared `common::playout`", but `random_invariants` has its own copy of the
   loop: pick, play, pass, break. That is the duplication #69 and #70 moved
   into `common` to remove. Every check fits in a `playout` visitor:
   - `me & opp == 0`, and every legal move flips at least one disc and adds
     exactly one disc;
   - if there are no moves and the board is not terminal, then
     `pass(board)` has moves. That is the "two consecutive passes means
     terminal" invariant, stated on the visited board.

   Either switch to `playout` or correct the PR text. Switching is preferred.

2. **Show the differential can fail.** As in #69, this issue has no RED
   failure, so nothing yet shows the 10k differential catches a real
   move-generation bug. Record one or two mutations in `docs/prs/71.md`, then
   revert them. For example, drop `NOT_A` from `Dir::E`, which the hand
   fixtures also catch, so note which tests fail, or stop `flips` one step
   early. The useful information is that `differential_10k` fails, and on
   which position index.

## Minor

3. **A tautological assertion.** `is_terminal(board) == (moves == 0 &&
   legal_moves(opp, me) == 0)` restates `is_terminal`'s own definition. It
   can only fail if someone rewrites `is_terminal`. Keep it if you like, but
   the pass invariant in item 1 is the real check.

4. **Compare `flips` too.** The differential checks post-move boards, which
   implies flips, but comparing `flips(board, sq)` with `naive.flips(sq)`
   directly is one line. It makes any failure point at the flip routine
   rather than at `play`.

5. **Release-only, consistently.** `differential_200k` uses a bare
   `#[ignore]`, while `perft_start_deep` uses
   `cfg_attr(debug_assertions, ignore = "release-only")`. Use the same
   pattern so `cargo test --release` runs both.

6. **The Phase 1 gate record.** PLAN.md's gate asks to "record cumulative
   formatted LOC". Add the engine count (159) to the measurements, and name
   the hardware (CPU model) behind the 39 M nodes/s figure. "About 0.01 s" is
   also too coarse to give a nodes/s figure. Time perft(10), or repeat
   perft(8), so the rate comes from a measurement of at least 0.1 s.
