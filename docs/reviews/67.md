# Review: Issue 67 — Implement flips, play, pass, terminal, and WTHOR score (RED)

Verdict: **request changes**

## Verified

- #66 was merged with a recorded approve and is closed. This branch is based
  on the current `main`.
- `cargo test --no-run` fails only with the expected E0432 in `movegen` and
  `score`.
- I hand-checked every fixture: the four opening flips (d4, d4, e5, e5), the
  board after `c4` (me = e5; opp = c4 d4 e4 d5), the counts 2/2/60 → 1/4/59,
  the tie (1–1 with 62 empties → 0), the win (2–1 with 61 empties → 62), and
  the wiring (6,200).

## Required

1. **A loss is never scored.** Every `final_score` fixture is a tie or a win
   for `me`. A sign or perspective bug, or "empties to `me`" regardless of who
   wins, passes all of them. Add the loss from the same position:
   `final_score(pass(won)) == -62`. That also pins the side-relative contract.

2. **A full-board terminal is missing.** With no empties, the score must be
   the plain difference. Example: `me = (1 << 33) - 1`, `opp = !me`, giving
   `final_score == 2`. Without it, a bug that always adds or subtracts empties
   the wrong way only shows up when empties exist.

3. **A single pass must not be terminal.** `terminal_board` checks a
   double-no-move position as terminal and the start as non-terminal, but it
   never checks a position where only `me` has no move. Example:
   `Board { me: b1, opp: a1 }`. Here `me` has no move, but `opp` can play c1,
   so `is_terminal` must be false. That is the case an `is_terminal` that
   checks only `me` gets wrong.

4. **`flips` is only tested on single-direction, one-disc captures.** The
   start position never exercises multiple directions, an unanchored run, or
   the per-step edge checks the issue asks for. Add fixtures (hand-computed):
   - multi-direction with an unanchored run: `me = a1 | c3`,
     `opp = b1 | c2 | d1`, move `c1` → flips `b1 | c2`. The `d1` run ends on
     the empty e1 and must not flip.
   - wrap guard: `me = h3 | b2`, `opp = h2 | a2`, move `h1` → flips `h2`
     only. Stepping east from h1 without an edge check reaches a2 then b2 and
     would wrongly flip a2.
   - a long run: `me = a1`, `opp = b1..g1`, move `h1` → flips `b1..g1`.

## Minor

5. **Tied terminal through the wiring.** PLAN.md (test strategy item 5) asks
   for `terminal_score(final_score(b))` to be tested "including a tied
   terminal with empty squares scoring zero". Add that assertion to
   `terminal_wiring`.

6. **Map the acceptance items.** "Every legal move flips >= 1 disc" and "disc
   count rises by exactly one" are tested here only for `c4`. Either loop over
   all four opening moves (cheap), or state in `docs/prs/67.md` that the
   random-playout invariants in #71 cover them.

7. **The `play` precondition.** PLAN.md says `play` debug-asserts that the
   square is legal and flips at least one disc. A
   `#[cfg(debug_assertions)] #[should_panic]` test on an illegal square
   documents and pins that.

8. The intended-behaviour notes should state the square type (`u8`, as the
   tests' `sq` helper implies) and that `final_score` is meaningful only on
   terminal boards.
