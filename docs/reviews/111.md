# Review: Issue 111 — Calibrate the ProbCut error model (RED)

Verdict: **request changes**

## Verified

- The branch is based on the current `main` (`198e80c`, with #116 merged).
  The RED commit adds `tools/examples/fit_probcut.rs`, the `check.sh` line
  and the notes. `check.sh` now runs
  `cargo test --release --manifest-path tools/Cargo.toml --example fit_probcut`.
- The OLS test's tolerances fit the noise. With σ = 100 and n = 4,000, the
  standard error of `b` is about 1.6, so ±5 is safe, and the estimates of `a`
  and σ are much tighter than their bounds.
- The zero-count Clopper-Pearson references are right:
  0/200 gives 1 − 0.05^(1/200) = 0.01487, and 0/75 gives 0.03916.

## Required

1. **`decision_counts_hand_table` asserts a wrong value.** With `t = 1.5`,
   `a = 1.000`, `b = 0` and `σ = 100`, the margin is `m = 150`, so
   `H = β + 150` and `L = α − 150`. Row by row:
   - `(300, 90, 0, 100)`: high fires (300 ≥ 250), and it is a false high
     (90 < 100).
   - `(-300, -90, -100, 0)`: low fires (−300 ≤ −250), and it is a false low
     (−90 > −100).
   - `(300, 110, 0, 100)`: high fires, a true high.
   - `(-300, -110, -100, 0)`: low fires, a true low.
   - `(250, 100, 0, 100)`: high fires at exactly `H = 250`, and since
     `v_d = β` it is a true high. Low does not fire (250 > −150).

   So `low_fired` is **2**, not 3. The table is missing the mirror of row 5.
   Add `(-250, -100, -100, 0)`: low fires at exactly `L`, and `v_d = α` makes
   it a true low. That gives `low_fired == 3` and covers both boundary
   conventions (`≥ H` fires; `v_d = β` and `v_d = α` are not false cuts).
2. **The Clopper-Pearson test pins only k = 0.** At k = 0 the bound has the
   closed form `1 − 0.05^(1/n)`, so an implementation that is wrong for
   every k > 0 passes. Yet k > 0 is the decisive case: the acceptance rule
   compares false-cut rates around 5-12% against a 12% ceiling. Add
   reference values for k > 0 (one-sided 95%, computed by bisecting the
   exact binomial CDF):
   - 10/200 gives **0.08334**. The normal approximation would give about
     0.0754, so a tolerance of 0.001 catches it.
   - 20/200 gives **0.14199**.
   - 5/75 gives **0.13507**.
3. **The interrupt-and-resume test is deferred to GREEN.** The notes say it
   "will be added with the pipeline implementation", but #111 lists it among
   the RED tests, and PLAN § Interruptible long-running jobs item 7 makes it
   part of done. RED is where it belongs: it can fail to compile like the
   others. The test must show that killing the pipeline during the
   measurement stage, then re-running it, gives recorded data and fit output
   identical to an uninterrupted run, that a truncated trailing line is
   redone, and that a header mismatch (a different seed or depth range) is
   rejected. Use a tiny configuration (a few games, few positions,
   `d ≤ 4`). In-process stage functions are fine for the torn-line and
   mismatch cases. The kill case needs a real child process, so either spawn
   the built example binary (resolved from `std::env::current_exe()`'s
   directory) or run the pipeline as a subprocess of the test.
4. **`dedup_rows` deduplicates per-depth rows by key alone, which would
   discard measurements.** `Row` carries `depth` and `value`, so it reads as
   one measurement at one depth. Deduplicating by `key` alone then keeps one
   depth per position and throws the rest away. The design deduplicates
   **positions**, before measuring (§ Fitting, Positions). Make the test's
   unit a sampled position (key, game id, and for variation positions the
   window), and assert that the first game id is kept, which is what fixes
   the position's side of the split. If per-depth rows remain a type,
   deduplicate them by `(key, depth)` and test that.

## Nit

- `assert_eq!(cond, true)` reads better as `assert!(cond)` in
  `split_is_grouped_and_stable`.

Please address these and re-request RED review.

  `low_fired == 3`, and both boundary conventions are now pinned.

- The pipeline test covers SIGKILL during `measure.journal` with the signal

  seed-mismatch "header" error.

## Required

1. **The test may run a stale or missing example binary.** It runs
   `target/release/examples/fit_probcut`, the *non-test* example binary.
   `cargo test --example fit_probcut` builds only the test harness
   (`fit_probcut-<hash>`), not that binary. So in a clean checkout the path
   doesn't exist, and after any earlier `cargo build --example` it is
   whatever version was built last: the kill-and-resume test would then
   exercise old code and could pass against a broken pipeline. Make sure
   the binary under test is the current source. Either:
   - add `cargo build --release --manifest-path tools/Cargo.toml --example fit_probcut`
     to `check.sh` before the test line, and have the test fail with a clear
     message if the binary is older than `fit_probcut.rs`; or
   - have the test run `cargo run --release --example fit_probcut -- …`
     (slower, but always fresh).
2. **The kill window is probably too short.** Eight positions measured to
   depth 4 take a few milliseconds in release, against a 5 ms poll. The test
   will usually see the run finish first, and then either panic ("finished
   before interruption") or, if it races, fail the `signal == 9` assertion.
   Both fail safely, but the test will be flaky or red. Choose a tiny
   configuration whose measurement stage lasts at least a second in release
   (for example 40 positions to depth 7), or add an uncounted
   `--unit-delay-ms` testing flag to the example. Keep the signal and
   partial-journal assertions.

  seed. A second `run` with `--depth 5` against the same directory, asserting

# Review: GREEN, pipeline checkpoint (round 5)

Verdict: **request changes**. The pipeline runs, but its calibration
stage doesn't implement design § Fitting yet, so the smoke log can't show
the long run would answer the question. Don't start the long run.

## Verified

- The staged, journaled pipeline exists: self-play (`game:N` units),
  sampling, per-position measurement (one fresh `Table` per position,
  `endgame_threshold: 0`, full-window `negamax` for `d = 1..=D`) and a fit.
  The RED tests pass.
- `docs/tuning/probcut_fit_smoke.log` is committed: 8 games, 200
  positions, depth 8.
- "supported-domain: none" is the expected outcome at this size and is
  stated plainly.

## Required

1. **The σ models are placeholders, not fits.** All three candidates are set
   to the global σ:
   - `Linear { s0: 120, gap: 0, empty: 0 }`;
   - `EdaxStyle { …, q0_milli: 120000 }` with `a_milli: 1000` and the other
     coefficients 0;
   - `StageTable [(120, 0); 6]`.
   The cell table right above shows σ from 28 to 290 (`d=8 bucket=0` is
   290), so a constant 120 underestimates several cells by more than 2×.
   That is exactly the failure the asymmetric floor exists to catch. Per
   § The σ model and #111:
   - fit each candidate to the per-cell σs, weighted by `n`;
   - report each candidate's 95%-floor check per supported cell;
   - choose by held-out decision error, then constant count;
   - make the decision simulation use the **chosen** model, not `linear`.
2. **The supported domain and the decision rates aren't per cell.** One
   global `(depths, empties)` box comes from min/max empties, and the
   decisions are pooled across all cells. #111 requires, per `(depth, stage)`
   cell and per direction, the fired count, the false count and the
   Clopper-Pearson upper bound. A cell is supported only with at least 200
   fired decisions per direction and both upper bounds ≤ 12% at t = 1.5.
   `ProbCut` can only express a rectangular domain, so derive the largest
   rectangle of supported cells, and log the cells it excludes.
3. **The variation windows don't come from the engine's search.**
   `collect_nodes` is plain alpha-beta from `(−INF, INF)` in square order,
   with no move ordering and no TT. Without ordering, far more nodes keep one
   infinite bound, and with `α = −INF` the low threshold is skipped by the
   guard. That is the likely cause of the 408-against-33 high/low imbalance,
   and the low-side sample is too thin to judge anything. § Fitting asks for
   windows "ProbCut actually meets". At minimum, order moves with the
   engine's public `ordered_moves` (with the depth-based hint), as
   `negamax` does, and iterate from depth 1 so the root windows narrow like
   iterative deepening's. Report the fraction of samples with an infinite
   bound on each side.
4. **The sampler pads with duplicates.** `sample_positions` fills a short
   reservoir by pushing copies until it reaches `--positions`. Duplicates
   inflate `n`, break deduplication, and shrink confidence bounds
   artificially. Never pad: use what was sampled, and log the actual count
   next to the requested one.
5. **The d′ comparison is missing.** #111 acceptance asks for decision error
   and probe cost for `2·⌊d/4⌋ + (d mod 2)`, `d − 2` and `d − 4`. The
   measurements already hold every depth, so this is a re-analysis, not
   new compute.
6. **A ready-to-paste line is printed for an unsupported domain.** The log
   says "supported-domain: none" and then prints
   `PROBCUT_FIT = ProbCut::new(…, (3, 8), (18, 50))`. Print the line only for
   a supported domain. Otherwise print "no PROBCUT_FIT: …" with the reason.
   Someone copying the last line of the log must not get an unsupported
   configuration.
7. **Small cells are reported as perfect fits.** `n=2` cells print
   `sigma=1.00 r2=1.0000` (two points always fit a line). Use a minimum `n`
   for a fitted cell (say 30), and mark smaller cells "insufficient" instead
   of printing a σ clamped to 1, which would also corrupt any σ-model fit
   that includes them.
8. **The real run can't be configured as the design asks, and progress
   isn't time-based.**
   - § Fitting specifies 4,000 positions to `d ≤ 10` and 1,000 positions to
     `d = 11-12`. The pipeline has a single `--positions` and `--depth`.
     Support the two tiers, or state and justify a single tier in the notes
     before the long run.
   - Progress prints only when `written % 100 == 0`. At depth 12 that can be
     more than 5 minutes between lines, and on resume it prints
     "measured 0/…" once for every already-done sample. PLAN item 6 asks
     for at least one line a minute: report on elapsed time.

## Notes

- `let bucket = …; let _ = bucket;` in the global-fit loop is leftover.
- The log header should record the provenance the journals carry (opening
  hash, engine commit), so the committed log stands alone.
- The cells already suggest material per-bucket differences in `a`
  (0.98-1.29). Decide the rule for "differ materially" in the notes before
  the long run, as § Fit says. Don't decide it after seeing the results.

Please address these and commit a new smoke log for the next checkpoint
review.
