# Review: Issue 81 — Tools harness tests and baseline ladder

Verdict: **request changes** (small)

## Verified

- #80 was merged and closed. This branch is based on the current `main`.
  `./scripts/check.sh` passes, and the release harness suite is 17/17,
  including `phase2_gate`.
- `phase2_reproducible` checks byte-identical stdout, including the ordered
  logs. `phase2_gate` runs the PLAN.md gate command and requires a
  `bootstrap` interval over 200 pairs.
- No test-first failure applies: this is test-only coverage of reviewed
  code, and the rescope to the ladder and end-to-end checks is accurate.

## Required

1. **The ladder tests don't check anything about strength.** The acceptance
   says "random vs random passes a statistical sanity check". `ladder_random`
   asserts only that the mean is in `[0, 1]`, which is true of every possible
   output. `ladder_greedy_random` asserts only that it ran. These runs are
   deterministic for a fixed seed, so real assertions can't flake. I ran
   them in release:

   | run | pairs | mean | interval |
   | --- | ---: | ---: | --- |
   | random vs random, seed 3 | 100 | 0.5325 | [0.4600, 0.6025] bootstrap |
   | greedy vs random, seed 4 | 20 | 0.5375 | [0.3875, 0.7000] |
   | greedy vs random, seed 4 | 100 | 0.6275 | [0.5600, 0.6925] bootstrap |

   Make the ladder say something:
   - random vs random (about 100 pairs): the interval **contains 0.5**.
   - greedy vs random (about 100 pairs): the interval's **lower bound is
     above 0.5**. At 20 pairs it doesn't separate, so 20 is too few for a
     ladder rung.

   If 100-pair runs are too slow in debug, make them release-only like
   `phase2_gate`.

## Minor

2. **The gate could check direction.** `phase2_gate` checks that the interval
   kind is `bootstrap`. Also assert that the lower bound is above 0.5 (the
   round-5 run of #80 gave `[0.8725, 0.9275]`). That catches a regression
   where the frozen evaluator, or search, silently breaks and phase2 stops
   beating greedy. It is the last rung of the ladder.
