# Review of #164 — Early exits and clock tuning

## Design review of `5227333`

**Request changes.** The separation between tuning and the untouched
gate is sound. The amendment needs a deterministic pick rule, coverage
of the actual early-exit settings, and a defined policy input domain
before implementation.

### Major — Define the 0.005 selection rule against a single maximum

At `docs/design/time.md:500`, "ties within 0.005" is ambiguous when
several eligible scores are close. For variants 0, 1 and 2 scoring
0.50000, 0.50375 and 0.50750, consecutive comparisons can retain 0 or
select 2. The lowest number within 0.005 of the best score is 1.
Define the rule in that order. Find the maximum among eligible
variants, then pick the lowest number at most 0.005 below that
maximum, inclusive. Retain the variant 0 fallback if none qualifies.
Use integer half-points for the comparison and record a near-tie
example. At 200 pairs, 0.005 is exactly four half-points over 400 games.

### Major — Test the time condition used by every tuned early exit

At `docs/design/time.md:512`, the stable test uses `share = 0`, and
the decided-score test does not specify a time boundary. Every
candidate with exits actually uses 25%. An implementation that ignores
the share could pass the proposed tests and spend a materially different
amount of time in tuning.

Define the cutoff using elapsed time from search entry and specify how
fractional milliseconds are handled. Test a completed, settled iteration
just below the cutoff and at equality using a deterministic time input
or a pure predicate. Also test that a change of move resets the
consecutive streak, and pin the absolute-score boundary for both signs.
Define the forced-move shortcut's scope on exact positions and before
the first clock update. Verify that a multi-move exact search ignores
the settled-exit fields and that flat play keeps its existing behavior.

### Major — Keep the allocation policy arithmetic defined

At `docs/design/time.md:459`, `allot_with` accepts a publicly
constructible policy with unrestricted `u64` fields. A zero weight
denominator divides by zero. A very large weight, reserve or cap can
overflow arithmetic even with the game clock clamped to `2^40`.
A share above 100 also has no defined contract. The registered variants
need only four fixed policies. Make arbitrary policies unconstructible,
or specify and enforce the accepted domains and arithmetic bounds.
Keep the numerical identity of variant 0 covered by the existing allot
examples.

### Registration follow-through

The 750 ms tuning games select a candidate. The separate 3 s gate
establishes the result at play controls. Keep the current C pilot record
under its original binary. Before tuning, register the new binary,
the 750 ms pilot and the four match commands. Before the gate, register
the picked variant and verify that the gate binary's flat baseline
matches the already pinned pilot, as required by the #163 pilot review.
Use the same accepted-pair validation and clear both fixture overrides.
