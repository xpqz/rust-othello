# Review: #114 pre-registration (round 1)

Verdict: **changes requested before any game is played.**

The sweep values, the opponent (`pc:off`), the 200 pairs from
`openings_tune.txt`, the shared seed (common openings and colours across
`t`, which is good for comparison), the selection rule with ties going to
the larger `t`, and the untouched validation and final sets all match the
issue.

## Required

1. **Record the node-budget measurement.** 1,965,089 nodes per move is 3.6
   times the issue's figure of about 540k nodes/s. It may be right, since
   release full-width search at depth 64 is not the earlier bench run, but
   a pre-registered number needs its derivation pinned:
   - the exact command or test that measured it;
   - the commit and build profile;
   - the per-position node counts, or at least min, median and max.

   Otherwise nobody can reproduce or audit it.
2. **Update the compute estimate.** At 3.6 times the nodes, the issue's
   18 CPU-hours becomes roughly 65 CPU-hours, about 13 h of wall-clock time
   at 5 jobs, not "several hours". State the per-pair cost from a short
   timed sample (one or two pairs) and the projected total. The user
   reclaims this machine, so the estimate matters.
3. **Run from a dedicated worktree** (PLAN § Interruptible long-running
   jobs, item 8). The commands write journals to `docs/tuning/` in this
   checkout. The journal header pins the commit, so your next commit here
   breaks resume, which is exactly what happened before. Run in a worktree
   pinned at the approved commit, with `--out` inside that worktree. Copy
   the four `.log` files back when done. The journals need not be committed.
4. **What the logs must contain.** Per the issue, each
   `probcut_tune_<t>.log` holds the full match output: pair-bootstrap
   interval, Elo, seed, node budget, job count, wall-clock time, and the
   commit. Say so in the pre-registration.
5. **Add one line on a negative outcome.** If every `t` scores below
   `pc:off`, the rule still picks the best `t`. #115's validation gate then
   decides, and this issue does not stop the epic. Pre-register that, so a
   negative sweep isn't argued about afterwards.
