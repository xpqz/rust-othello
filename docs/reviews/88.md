# Review: Issue 88 — Integrate TT into negamax (RED)

Verdict: **request changes**

## Verified

- #87 was merged and closed. This branch is based on the current `main`.
  `cargo fmt --check` passes, and the target fails only with E0432 for
  `search_tt`.
- The two tests express the acceptance properties: TT on/off agreement at
  fixed depth, a legal returned move, and a deep-then-shallow warm table.
- #89 owns the corpus sweep, incomplete-store, preloaded-entry, and node-%
  gates, so those are rightly absent here.

## Required

1. **A table that is never used passes every test.** Both tests assert only
   that TT results *equal* the no-TT results. An implementation that carries
   the table but never probes it, or never stores, or whose cutoffs never
   fire, is trivially equivalent and passes. #89's 20% node gate would
   eventually catch that, but #88 is the issue that wires the table, so it
   should prove the wiring is live. Add one cheap smoke test: search a
   position to depth 4 with a fresh table, then search it **again at depth 4
   with the same warm table**. The second search must return the same score
   and use **far fewer nodes** (for example under half). That forces store,
   probe, the equal-depth cutoff, and the domain checks to actually run.

2. **Three positions at depth 3 won't catch TT bugs.** Bound-flag mistakes
   (storing `Lower` for a fail-low, or using the post-search alpha instead of
   the original window), sign or perspective errors, and depth mismatches
   show up through **transpositions**. Those are rare at depth 3 from the
   start or from small fixtures. Add a seeded sample of playout positions
   (about 30, sampled sparsely, as in #82) at depth 4 or 5, asserting cold ==
   TT score for each, and run deep-then-shallow on the same sample with one
   table per position. The start position alone is a weak deep-then-shallow
   case, because of its symmetry.

## Minor

3. **Store the root?** The notes say interior nodes store after completion,
   but don't say whether the root's result is stored (with `mv = best`).
   Storing it gives the next iteration's root a hint for free. If
   intentionally skipped, say so.

4. **The window rule in the notes.** "Upper/Lower/Exact from the original
   window" is the right rule. Make sure `negamax` keeps a copy of the
   incoming `alpha`, because it mutates `alpha` in the loop. Classify with
   `best <= alpha_orig` → `Upper`, `best >= beta` → `Lower`, otherwise
   `Exact`. Item 2's sample is what would catch getting this wrong.

# Re-review (round 2)

Verdict: **approve** (RED). Proceed to GREEN.

- Item 1: `tt_warm_nodes` requires a repeated depth-4 search on a warm
  table to match the score in less than half the nodes. A table that is
  carried around but never used can't pass it.
- Item 2: `tt_sample_equivalence` checks 30 sparsely sampled playout
  positions cold vs TT at depth 4, then deep-5 → warm-4 on the same table.
  Transpositions and bound-flag errors now have room to show up.
- Items 3–4: skipping the root store is intentional and stated, and the
  `alpha_orig` classification rule is recorded.
- fmt is clean, and the target fails only with E0432.

## Nit (non-blocking)

- `tt_sample_equivalence` runs about 90 searches at depth 4–5 in debug. If
  the debug suite gets slow, keep it by reducing the sample to around 15
  rather than making it release-only, since this is the main guard on the TT
  bound rules.

# Re-review (round 3, GREEN)

Verdict: **approve**

## Verified

- The tests are unchanged since the RED approval. I re-ran
  `./scripts/check.sh` and it exits 0. The full release engine and tools
  suites pass. `tt_sample_equivalence` takes 0.6 s in debug, so the
  sample-size nit is moot.
- `negamax` probes only after terminal, pass, and depth-0 are resolved. It
  cuts only through `Entry::cutoff` (heuristic domain, equal depth,
  bound-compatible). The stored or deeper move feeds `ordered_moves` as
  `preferred`. That is safe even on a key alias, because ordering only
  iterates legal moves. The node keeps `alpha_orig` and stores
  `Upper` (`best <= alpha_orig`), `Lower` (`best >= beta`), or `Exact` only
  after the loop completes. The `?` on child results returns before the
  store, so aborted nodes and their unfinished ancestors store nothing.
  `chosen` is always a legal move, because child values are always above
  `-INF`.
- `search_limited` and `search_tt` share `search_inner`, so the no-table
  path is unchanged and `Ctx::new` keeps `table: None`.
- Counts: `search.rs` 260, `tt.rs` 110, engine 775 of 999.

## Nit (non-blocking)

- `zobrist(board)` recomputes the key from the bitboards at every interior
  node. That is the PLAN's stated default ("incremental updates only if
  measurement demands them"), so it is fine. #89's time-to-depth numbers are
  where to check whether it costs anything.

Clear to merge.
