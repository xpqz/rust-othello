# Review: Issue 63 — Record engine conventions in code and docs

Verdict: **request changes**

## Verified

- Doc-only change. Treating it as setup work with no test stage is reasonable.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test`, and `cargo doc --no-deps` all pass with no rustdoc warnings.
- The branch is based on the current `main`.
- Every topic in the #63 scope appears in the doc. The `[`score`]` link
  resolves, and the objective text is not duplicated, as agreed in #62.
- DESIGN.md already carries the "superseded" banner and per-section markers,
  so the Phase 0 gate item "DESIGN.md visibly points to this plan" is met.

## Required

The acceptance line for #63 is "no ambiguity remains". These bullets are
ambiguous or understate PLAN.md:

1. **Start position is misleading.** "black to move on d5/e4, white on d4/e5"
   reads as black *moves* on d5/e4. Write it as: black discs on d5/e4, white
   discs on d4/e5, black to move.

2. **The fallback rule is under-specified.** "First legal move" in what order?
   Move ordering could make the first move almost anything. PLAN.md says the
   first legal move by square index (lowest index). That also needs the square
   mapping, which no convention records yet: square `i` is `a1 + i`,
   row-major, `a1` = bit 0, `h8` = bit 63 (PLAN.md Phase 1). Add both. The
   mapping is a cross-cutting convention that board, CLI, TT, and tests all
   depend on.

3. **The perft pass rule is incomplete.** PLAN.md says a pass "consumes one
   ply *and is a node*", and `perft(b, 0) = 1`. Without "is a node" the rule
   can be read two ways. Also mark the terminal-with-`depth > 0` rule as this
   project's own convention, not part of Aart Bik's table. The issue scope
   names it "the terminal-with-depth>0 project convention".

4. **The size rule understates what is excluded.** "doc comments are
   excluded" suggests that ordinary `//` comments and blank lines count. #65
   and PLAN.md count *formatted* lines and exclude blank and all comment-only
   lines (`//`, `///`, `//!`, block comments). State the rule the guard will
   enforce, or #65 and this doc will disagree.

## Minor

5. **"12-empty threshold" reads as fixed.** PLAN.md makes it a configurable
   root threshold, 12 by default, which Phase 6 may raise to 14-18. Say
   "default 12".

6. **The 1000 ms move budget is in the Endgame bullet.** It is the default time
   control, not an endgame rule. Move it to its own short bullet, or to Search.

7. **Where the conventions are visible.** The acceptance says "visible where
   board/search code lives". Today that is the crate root, which is right
   while `board.rs` and `search.rs` are empty. When Phase 1 and 2 fill those
   modules, add a one-line `//!` pointer to the crate docs in each, or note in
   `docs/prs/63.md` that `lib.rs` is the intended single home.
