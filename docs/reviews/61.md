# Review: Issue 61 — Create Cargo lib+bin scaffold and module map

Verdict: **request changes** (small)

## Verified

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`,
  and `cargo build --release` all pass. `cargo run` exits 0 and prints nothing.
- Edition 2024, no dependencies, `lto = "fat"`, `codegen-units = 1`.
- `#![forbid(unsafe_code)]` is in both `src/lib.rs` and `src/main.rs`.
- The module map matches PLAN.md Phase 0 and the issue scope exactly. No
  `sym`, `baselines`, or `harness` modules.
- `Cargo.lock` is committed, which is right for a binary. `target/` is ignored.
- Treating this as setup work with no test stage is reasonable.

## Required

1. **The AGENTS.md change is on the issue branch and not mentioned in the PR.**
   Commit `9fc5160` ("Document setup exception for test stage") changes the
   working agreement. It is the rule this PR relies on to skip RED, and it would
   reach `main` through the issue 61 merge without being called out. Either land
   it on `main` separately, or say in `docs/prs/61.md` that this branch carries
   it and why. A change to the process should not arrive inside a feature
   merge.

2. **Remove the redundant `[lib]` and `[[bin]]` tables.** With
   `name = "othello"`, Cargo already finds `src/lib.rs` and `src/main.rs` and
   names both targets `othello`. The two tables add eight lines that change
   nothing. This project is strict about size, so the manifest should be minimal
   too.

## Minor / for the record

3. **The "24 lines" figure has no stated method.** It looks like raw `wc -l`
   over `src/`: 11 + 5 + 1, plus 7 single-newline files. That counts blank lines
   and empty files. Nothing defines the budget metric until #65 ("formatted
   non-comment lines"). Either drop the number or state how it was counted
   (about 14 non-blank lines), so later PRs report the same metric.

4. **`cli::run` is an empty stub.** The issue requires `main` to call
   `cli::run`, so this is in scope. PLAN.md Phase 0 also says "No fake stubs for
   later phases". A no-op that exits 0 is acceptable as wiring. Make sure no
   later Phase 0 issue builds on it before the CLI exists.

5. **Optional:** add `rust-version = "1.85"`. Edition 2024 needs at least that
   version, and with the field set an older toolchain fails with a clear error
   instead of a confusing edition error. One line. Leave it out if the manifest
   should stay minimal.

6. `CLAUDE.md` is untracked in the working tree. It is not part of this PR.
   Commit it separately or ignore it, but do not sweep it into the 61 merge.
