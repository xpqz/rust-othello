# Review of #171 — Book diagnostic run and report

## RED and registration review of `f2b136f`

**Request changes.** The two book assets match their recorded
identities. The bounded diagnostic is appropriate, but the current
test and run contracts leave these gaps.

1. **Major — Enforce the 30-minute limit during a run.**
   The registration checks the total before launching each command.
   A slow trace or audit can run past the remaining allowance. Give
   each invocation a deadline tied to the time left, with small
   resumable trace batches and no automatic retry. Retain completed
   audit positions if it is interrupted. Demonstrate the stop and
   restart path with a short fixture before running production
   diagnostics. Record the executable identities alongside the
   opening and asset hashes before tracing.
2. **Major — Bind the comparison to the same roots and controls.**
   `trace_records` drops the header and silently folds duplicate IDs
   into a map. `diverge` compares whichever IDs the book file
   contains and accepts a separately supplied roots file. This can
   turn mismatched or incomplete traces into apparent disagreements.
   Add command-level coverage for mismatched root hashes or node
   caps, duplicates and missing games. Require the full registered
   ID set for each group and verify the roots identity. Order games
   by numeric pair and colour before applying the audit quota.
   String order puts pair 10 ahead of pair 2.
3. **Major — Define how a symmetric move affects the audit.**
   The current fixture labels a symmetry-equivalent first move
   but leaves open whether it consumes one of the four audit slots.
   Keep equivalent square changes separate from the audit of different
   decisions. Specify whether the comparison realigns the traces or
   ends the comparison and counts the game as unresolved beyond that
   point. Cover that behavior with a trace containing an equivalent
   first change. Also test deduplication with the same board and both
   moves transformed by a symmetry. The current fixture only repeats
   identical inputs.
4. **Major — Carry result status into the child audit.**
   `child_value` and its output currently carry only score and reply.
   The report consequently cannot identify exact solves or distinguish
   a fallback from a completed search. Keep the status and solved
   information through audit output, and add a forced-pass child
   fixture to lock down the score sign and who moves next. A
   fallback must stay distinguishable from evidence of a reversal.

The original asset matches the file extracted from `42e5d00` byte for
byte. Both book hashes match the registration. All seven targeted
tests failed against the expected RED stubs. Formatting and whitespace
checks passed. I did not run the full suite, clippy or production
diagnostics.

## RED re-review of `c5ffe82`

**Request changes.** The registration now gives each invocation a
deadline and schedules a trace and audit recovery demonstration
before production. The new fixtures cover root identity, numeric
ordering, symmetry and forced-pass scoring. Two analysis details
remain.

1. **Major — A node-capped heuristic result normally reports
   `Partial`.** The report rule in `docs/prs/171.md` compares only
   completed or solved values. In the targeted RED run, the real
   reference search in `child_normal` returned a score of 456
   with status `Partial`. The engine returns its last completed
   iteration with that status when it stops before maximum depth.
   Carry depth or equivalent result provenance so the report can
   use a completed heuristic iteration while identifying fallback
   and the depth-zero partial W/D/L result separately. Add a test
   of the reversal decision using positive-depth partial values,
   alongside an ineligible value.
2. **Major — Bind the comparison to the same engine.**
   `Trace` stores the book mode, node cap and roots identity but
   drops the journal's engine identity. Two traces produced at
   different engine commits can still pass `compare_checks` and
   produce changes attributed to the book. Retain and compare the
   engine field and add a mismatched-engine case. Continue to
   record the pinned executable hashes before the run.

All 10 targeted release tests failed against the RED stubs.
Formatting and whitespace checks passed. A one-second alarm
survived `exec` and stopped a five-second sleep. The full
trace and audit recovery demonstration remains part of GREEN.
