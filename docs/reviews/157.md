# Review: Issue #157 — Book extension rounds, design amendment 3

## Summary

**Request changes** on `4fae9b8fadae6063d2908ef8ebae67c57a1c23cf`, before RED.
A fixed three-round, resumable A+B experiment is a reasonable response to
#154's coverage evidence. Keeping the engine unchanged, avoiding strength
claims and retaining the later gate are appropriate. The phase membership,
reply selection, legacy-score decoding and resume identities need precise
contracts before tests or long jobs can implement them consistently.

## Findings

### Major: distinguish a phase's scoring context from its units

Location: amendment 3, phase A/B and Validation paragraphs.

“Score each node, then add it” and validation against “base plus all earlier
phases” do not specify whether same-phase peers are book children. Nor can
the phase's expected records equal that context: A/B contain new unit IDs,
whereas the base and earlier nodes must not be rescored. The current scorer
uses one set for both queries and membership; extension needs these roles
separated explicitly.

Specify an immutable membership snapshot and a separate sorted unit set for
each phase. For example, derive all of A first, score exactly A against
N_previous ∪ A, validate exactly those units against that context, and only
then back up the complete post-A graph. Define B similarly. Another fixed
snapshot convention can work, but job completion order must never change
membership or the search sequence. Clarify whether round departures come
from the untruncated graph walk or from the final capacity-pruned records;
keep the full scored node set separate from emitted records.

This matters on the actual frozen data. A short read-only graph probe finds:
**1,843 departures → 1,839 distinct A1 children**, no terminal exits;
**56 A1 nodes** have a legal reply into the base node set, and **4 A1 edges**
lead to another A1 node. Same-phase membership is therefore not merely a
hypothetical corner case. Add a tests-first DAG with such a peer edge and
assert identical labels/builds under reversed unit order and different jobs.

### Major: “best drop-out” is not necessarily the best reply

Location: phase B, `r*(c)`.

An A node can already have a book child. Its best backed-up book move may
beat its best drop-out, or it may have no drop-out at all. The current B rule
can extend a reply the scored book would not select, and is undefined when
no best drop-out exists. This contradicts the description “the position
after the opponent's best reply”. The 56 base-transposition cases above
make the distinction relevant to round 1.

Prefer selecting the actual best move from the **completed post-A backup**,
using the existing value/square tie rule. If its child is already a node or
terminal, no B node is needed there. If instead the intent is deliberately
to explore the best remaining outside move, say that and define the absent
case; it is a different heuristic. Also state the mechanical role rule for
contracted passes: c can belong to the engine, and the next child need not
be the engine's turn. Add fixtures where an existing book move beats a
drop-out, all moves are book moves, values tie, and either edge causes a
pass. Do not promise monotonic coverage growth when backup changes choices.

### Major: define how the existing journal becomes per-move parent values

Location: Values after reclassification and base-journal validation.

The #154 format stores a best parent result plus a positional vector of
**search callback results**, not explicit `(square, parent value)` records
for every drop-out. The callback is skipped for terminal children and sees
the passed board for a forced-pass child. Its returned score therefore
requires the correct sign conversion and the old membership/order context.
The present builder reads only the aggregate best result; retaining that
aggregate when its square becomes a book move loses the next-best drop-out.

Define a deterministic decoder for the immutable base journal using its
original node snapshot and ascending legal-square order. Reconstruct
terminal scores without consuming a callback token; consume/pass/sign the
other tokens correctly; require an exact token count and valid scores.
Then remove **every** reclassified square and recompute x(p) from those
remaining. Specify the new phase record format and validate its square
mapping against its frozen context. No legacy journal rewrite or repeated
search is required.

RED should include promotion of the old best with a different runner-up,
all drop-outs becoming book moves, two squares transposing to the same new
child, terminal/pass children interspersed in the old vector, and missing/
extra/bad score tokens. Test backup through the new child, not just removal
of the old aggregate.

### Major: bind all phase-defining inputs and completed-round state

Location: Interruptible and resumable; Asset.

The proposed header binds the base journal, r/phase/R, but not roots,
phase units or membership snapshot. Changing roots/earlier phases can change
those sets while leaving the proposed header unchanged; shared unit IDs
could then be skipped using results scored under a different partition.
“In a deterministic recomputation” is not a substitute for checking that
the recomputed inputs match the journal being resumed.

Bind the roots, sorted unit set and complete membership snapshot, D/table/
scoring rules and relevant predecessor state. If predecessor results are
hashed, hash a canonical sorted-record representation so parallel append
order does not defeat reproducibility. Validate existing units before doing
new work; reject changed inputs, duplicate/foreign records and torn-tail
misinterpretation. Record the extension executable/source identity in
addition to base provenance, and verify that the actual scorer still uses
the base's evaluator and numeric search policy. Old-book compatibility does
not authorize mixing new-evaluator extension scores into this registered
“unchanged policy” run.

Define the durable empty-phase/early-stop case and what build does when A
is complete but B is absent or partial. Building the last complete round is
reasonable, provided the manifest states requested/completed rounds and
never claims partial work as a complete round. Tests should cover kills
inside A and B, between them, a valid empty B, mismatched inputs and R=0.
Require deterministic logical records and final artifact/manifest; raw
parallel journal append order need not be identical, as in #153.

## Non-blocking precision

- “At most about 1,843 engine records per round” is not an upper bound.
  Later departures can grow, and backup changes can make previously
  unretained base nodes reachable. Keep 9,300 records / 12 hours as sizing
  guesses with their assumptions; retain deterministic overflow and the
  fixed R rule rather than changing rounds after looking at strength.
- Name the overflow tie key explicitly. Existing priority is
  `(count, zobrist(canonical board))`; “key order” elsewhere means the
  canonical bitboard pair. Preserve the stated unchanged rule or register
  a deliberate change before running. Count-zero extensions and protected
  mandatory roots are sound.
- This commit does not actually raise the 2,100-line trainer guard. Call
  that a planned change under the recorded standing permission and keep
  guard/AGENTS/PLAN consistent when a concrete ceiling is chosen. Do not
  claim it is already done. The engine budget remains unchanged.

## RED review — `740de470`

**Request changes.** The 30 tests cover the decoder, reclassification,
phase selection and peer membership well, and the API stubs are an

### Major: isolate policy refusals, including the evaluator

Location: `trainer/tests/book_extend.rs:1057–1090`.

`extend_refuses_other_policy` first changes the base threshold from 18 to
17, then requests a different depth against that **same altered base**.
An implementation checking only threshold passes both assertions while
accepting a wrong depth on an otherwise matching base. Restore/recreate a
valid base before each single-input change, and check that refusal occurs
before creating or modifying phase journals. Include the explicitly
approved evaluator-hash mismatch and table mismatch. These need no retrain
or production search: edit the base header to a different well-formed
hash, or vary the requested parameter independently. Preserve the valid
control case so unrelated input errors cannot satisfy these assertions.

### Major: prove content binding rather than malformed-record rejection

Location: `extend_headers_bind_inputs` (775),
`extend_refuses_changed_record` (1012), and the identity fixtures.

The header test checks field names, not their counts or digest values.
The changed-record test subtracts 10,000 from a score, making it invalid
under the decoder's domain check. The changed-header test inserts text.
All can pass without hashing predecessor content at all. In particular,
a broken implementation that resumes under a changed, still-valid prior
record would escape these tests.

Add a valid-content mutation: change a non-winning token within bounds,
preserve/correct `best` so `decode` succeeds, and leave the unit/context
sets unchanged. With dependent phase journals present, both resume and
build must reject their stale predecessor identity without altering files.
Cover a valid base-record change too. Independently calculate at least the
base/prior/unit/context digest/count expectations on a small fixture,
including phase boundaries; use existing sorted logical records as data,
not the new production header helper as the oracle. Retain the changed
roots/foreign/duplicate cases and worker-order equality. This distinguishes
partition validation from binding the actual scores that determined it.

### Major: complete the interruption and empty-phase evidence

Location: `extend_resume_after_kill` (1227), `extend_empty_rounds` (895).

Only phase A is killed while running. The B and between-phase cases are
constructed by copying/truncating a completed run. Those are useful replay
fixtures, but they do not execute a live phase-B SIGKILL as the approved
RED contract requests. Add an observed kill after at least one B unit is
journalled and before B completes, then resume with another worker count
and compare logical records and artifact/manifest bytes. Retain the torn
record fixture as a separate check. The A kill's adaptive choice should
also verify A is incomplete before accepting that attempt: absence of a
B file alone can describe the boundary after A completed.

The empty-round test supplies no roots, so both A and B are empty. Add a
non-empty A whose post-A selected children are already book nodes, giving
an empty B; verify its durable empty journal, round completion, build and
resume. This exercises the distinct checkpoint where real A work is
complete but B needs zero work. Describe simulated versus live
interruption accurately in the appended notes.

### Major: reject the full out-of-domain integer range without overflow

Location: `trainer/src/book.rs:881`, `decode`'s token filter.

`v.abs() <= EVAL_BOUND` is not a safe range check for `i32::MIN`.
On the start position with context containing only the start, this record:

```text
-2147483648 19 | -2147483648 -2147483648 -2147483648 -2147483648
```

is **accepted in release** as four parent values of −2,147,483,648. In
debug the same call panics with `attempt to negate with overflow`.
Downstream backup may consequently overflow or emit invalid values instead
of returning a journal error. This bypasses the registered ±6,400 domain.

Use a direct inclusive bound check (or checked absolute value) before any
negation. Add regressions for MIN, MAX, both near-bound violations and
valid endpoints in debug and release, including the build/resume error
path. Refusal must return `Err`, preserve the existing journal and launch
no scoring work.

### Major: compare the base evaluator with the executable's actual model

Location: `trainer/src/book.rs:424–430` (`tail`) and 1035 (`load`).

The new policy guard says it checks this binary's evaluator, but `tail`
hashes `assets/eval.bin` from disk. Search uses the bytes embedded in the
engine at compile time. These can disagree after a retrain/file update
without rebuilding an existing executable.

Independent reproduction: compile the original model, change only the
snapshot's disk asset, and use a base header naming that changed model.
The existing executable **accepts and scores the extension**, although its
embedded model still hashes to
`676987110ca656677d18ef1bf54810ed559d417fde7cd0e88c87ba61ff5ea8cb` and
the disk/base model hashes to
`c1b988b1d946f9b9073dcadcdf3393bc37daddc8803f8588c284f32507c3b7eb`.
No production asset was touched; the snapshot was restored after the probe.
The old base-header convention cannot establish this new guard's invariant.

Derive the comparison from the actual embedded model (or an equivalently
sealed executable/build identity), rather than the current source-tree
file. Add a stale-executable regression: after compilation, changing or
removing the disk asset must not change the executable's model identity;
a base naming another model must refuse before a phase file is created.
The reverse case, an old matching base plus a changed checkout asset,
should be evaluated against the compiled model as well. Serving an old
book remains allowed; this finding concerns mixing scoring models.

### Major: separate stored replay provenance from runtime checkout HEAD

Location: `trainer/src/book.rs:1102–1115`, the shared run/build path;
`docs/design/book.md`, the new runtime-identity amendment.

Every reconstructed phase header includes today's `git_commit()`, even
for a read-only build. With an otherwise unchanged completed run, merely
changing the runtime Git response makes `build_extended` fail on the
`extender` field. The probe changed an isolated Git shim from one 40-hex
commit to another; no journal, model, parameter, root or actual repository
HEAD changed. The same executable could no longer reproduce its earlier
asset. Moving the source checkout, building from a later checkout or
losing the original checkout has the same underlying dependency.

For scoring, seal and record the actual executable/source identity once;
for replay/build, validate and preserve the recorded scoring provenance
instead of substituting the current builder checkout's HEAD. Keep all
base/prior/root/unit/context checks and reject inconsistent phase
provenance. Add a test that completes a run, changes only the runtime
checkout identity, and rebuilds identical asset/manifest bytes. Also test
that moving HEAD cannot relabel an already-compiled scorer as a new one.

The detached worktree and binary hash are good operational controls for
#158, but they do not fix this read-only build dependency or prove what an
arbitrary existing executable contains. I do not approve the runtime-HEAD
design amendment as implemented. The assertion that compile-time metadata
requires a forbidden `build.rs` is too strong: a recorded build command
can supply a source identifier through a compile-time environment value.
Choose a straightforward identity mechanism consistent with the guard;
no engine budget increase or uncounted build script is requested.

### Non-blocking reporting precision

The final manifest retains per-root coverage, but per-round `first` and
`second` are sums across mandatory roots rather than per-root rows. Keep
the promised per-root/per-round evidence for #158, for example by building
and retaining each completed prefix's manifest without repeating searches.
The `peers` counter currently measures A-to-A edges only; label that scope

increase is covered by the recorded standing permission. The larger-than-

loophole or code compression is requested to address these findings.
