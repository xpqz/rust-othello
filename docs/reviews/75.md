# Review: Issue 75 — CLI board printer, play, perft, and bench (RED)

Verdict: **request changes** (small)

## Verified

- #74 was merged and closed. This branch is based on the current `main`.
  `tests/cli.rs` fails with the expected E0432, and the binary cases fail
  against the empty `cli::run`.
- The tests cover each acceptance item: `perft 3` → 56, a scripted
  complete game, the printer round-trip, malformed and illegal input, EOF,
  usage, and bench. There is no new dependency.
- `scripted_game` simulates the same human/greedy game and derives the
  expected final line independently. The black/white mapping from the
  side-relative board is correct for both parities.

## Required

1. **No out-of-range squares are tested.** The scope says "validate moves
   and depth bounds *before shifting/indexing*". `zz` fails on the file
   letter, and `a1` is in range but illegal, so neither tests the bound. A
   parser that accepts `a9` computes square 64, and `1u64 << 64` panics in
   debug (or wraps in release). Add `a9`, `a0`, and `i1` to
   `illegal_input`, plus a trailing-garbage case like `d3x`. Each should
   print `Illegal move` and keep the game going.

2. **A `pass` with legal moves available must be rejected.** PLAN.md (tools
   harness, which applies here too) says a `None` or pass when legal moves
   exist must not silently become a pass. Add `pass` at the start position
   to `illegal_input` and expect `Illegal move: pass`, or a dedicated
   message.

## Minor

3. **The parser doesn't reject malformed boards.** `printer_roundtrip` covers
   only good input. Add `parse("") == None` and `parse` of a rendered board
   with one cell replaced by an unknown character `== None`, so the "exact
   parser" isn't accept-anything.

4. **More depth edge cases.** Add `perft` with no argument and `perft -1` to
   `perft_invalid`, and `bench --depth x` to a failure case. These are the
   same validation path, so they cost a few lines.

5. **The engine's pass is never asserted.** The scope says "prints a pass
   when the caller passes". If the simulated game in `scripted_game` contains
   a white pass, assert the CLI output contains the pass message. Otherwise,
   add a fixture that forces one. As written, the pass message could be
   missing and every test would still pass.

## Correction to my #73 review

- In #73 I said the `search.rs` budget was 210 rather than the 110 the notes
  cited. PLAN.md's Phase 2 section budgets `search.rs` at **≤ 110 at this
  stage**, and 210 is the final figure for the finished file. The
  implementer's figure was right. The square-iterator and
  constructor nits still stand, and both have been taken.

# Re-review (round 3, GREEN)

Verdict: **request changes**: over budget

## Verified

- The tests are unchanged since the RED approval. `./scripts/check.sh`
  passes, and `cargo test --release` passes. A manual `play` run prints
  coordinates, the side to move, disc counts, and legal moves.
- The behaviour is right. Input is validated before any shift, a legal
  `pass` is accepted only with no moves, engine passes are printed, EOF exits
  0, and errors exit 2 with a usage or depth message.

## Required

1. **`cli.rs` + `main.rs` is 214 lines against a Phase 2 budget of 130.**
   PLAN.md's Phase 2 budget is `cli.rs + main.rs <= 130`, and the
   finished-file allocation is **160**, so this is already 54 over the final
   allocation. The Phase 2 gate says: "if over projection, scope is cut
   before Phase 3". AGENTS.md says to stop and discuss rather than proceed.
   The PR reports the overrun but doesn't address it. Most of it is
   mechanical, so cut it, or come back with a scope proposal. Candidate
   trims (about 60 lines total):
   - **`parse_move`** (about 12 lines) becomes
     `squares(moves).find(|&s| square_name(s) == text)`. User text is then
     never turned into a shift at all, so bounds validation follows by
     construction, and `a9`/`i1`/`d3x` simply don't match.
   - **One colour mapping.** `render`, `parse`, and `discs` each repeat the
     `if black_to_move { (me, opp) } else { (opp, me) }` swap. One
     `fn colours(board, black) -> (u64, u64)`, which is its own inverse for
     `parse`, removes about 15 lines.
   - **Positional `parse`.** The format is fixed: header, eight rows, status
     line. Index `lines().nth(1..=8)` and drop `parse_row` and the row
     counter. Reject on a wrong line count or a bad cell. That saves about 12
     lines.
   - **Legal-move order.** `squares` already yields ascending square order.
     Drop the `Vec<String>` and `sort`, print in that order, and the tests
     still pass (about 5 lines).
   - **One depth parser.** `fn depth(text) -> Result<u32, String>` with the
     0–10 bound, shared by `perft` and `bench`, folds the bench match arm
     (about 8 lines).
   - **I/O error plumbing.** Treat a `read_line` error as EOF
     (`unwrap_or(0)`) and ignore a flush failure, which is harmless for an
     interactive CLI (about 6 lines).

   Record the new count. If it is still over 130 after these cuts, state the
   proposed reallocation, for example from the unused headroom elsewhere in
   the 999. Don't leave it silently over.

## Nit (non-blocking)

- Each rendered row ends with a trailing space (`"X "` per cell). Joining
  the cells with spaces avoids it, and is no more code if done while
  rewriting `render`.
