# Re-review (round 3, GREEN)

Verdict: **request changes** (one small fix)

## Verified

- `./scripts/check.sh` passes. `reference` is 7/7 and `symmetry` 6/6, and the
  engine is unchanged at 159 counted lines.
- The reference is independent and readable. `line` walks over `-1` cells
  with bounds checks and keeps the run only if it ends on `1`. `legal_moves`
  is "empty and flips something". `play` sets the runs and the square and
  then negates. Nothing calls production move generation.
- `nth_bit` and `playout` are shared, and `symmetry.rs` uses them, which
  closes the #69 commitment.

## Required

1. **`playout` never visits a full-board terminal.** The loop is
   `for _ in 0..60 { visit(board); ... }`. A game without passes makes all 60
   placements, but the board after the 60th placement is never visited. A
   game with passes is cut off before the end. So the shared driver, which
   #71 will use for the 10k differential and the invariants, never sees the
   final position of a full game. Those positions are where full rows, both
   sides passing, and `final_score` with no empties occur. The loop
   terminates on its own: at most 60 placements, and never two consecutive
   passes without hitting the terminal `break`. Make it
   `loop { visit(board); ... }`. The `symmetry` ≥90% guard will still hold,
   because there is one terminal per game against about 60 positions.

## Nits (non-blocking)

- `Naive::play` doesn't check legality. That is fine for a reference whose
  callers pass legal squares, but say so in a one-line doc comment, since
  production `play` debug-asserts.
- `from_bits` silently prefers `me` when the two masks overlap. A
  `debug_assert_eq!(me & opp, 0)` makes a bad input fail loudly in #71.
