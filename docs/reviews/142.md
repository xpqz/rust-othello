### Major: the measurement job cannot resume completed work

`solve_times` runs every position from scratch, writes only stdout, and
has no checkpoint reader, configuration validation, completed-unit skip or
resume test. The recorded twenty-empty run lasts about 35 minutes; even
200 previous searches at 3 seconds already consume ten minutes before
solving. This falls directly under AGENTS.md and `docs/PLAN.md`
§ Interruptible long-running jobs, which explicitly says such a job is not
done without the restart contract.

Add durable per-unit output and same-command resume, complete configuration
and input/build identity checks, torn-tail recovery, bounded lost work and
visible progress at least once a minute. Reuse the existing journal
support where appropriate. Add the required SIGKILL/resume, mismatched
header and torn-line checks with short budgets. Timing samples are
inherently non-deterministic: test that completed records survive unchanged,
IDs are neither repeated nor omitted, and summaries use the saved records;
do not require newly measured wall times to equal a separate run's times.
Document the dedicated pinned worktree command for future long runs as the
plan requires; the submitted notes do not identify such a run checkout.

Independent reproduction with 1 ms budgets: killed after observing game 2,
then reran the identical command. It restarted at game 0 and repeated all
200 positions. Existing completed timing logs can remain evidence; fixing
the tool does not require redoing the 35-minute experiment solely for this
operational correction.

Location: `tools/examples/solve_times.rs`, `main`; missing restart tests
and long-run instructions.

### Major: full-solve overrun does not count arbitrary fallbacks

The notes say one of 200 eighteen-empty games would play an arbitrary move
under the current engine. The tool records combined WDL-plus-full-score
completion time, not the WDL completion time or the result at a 3-second
limit. The inference is unsupported: if WDL completes and only the full
score times out, `search_inner` returns the WDL move with `Partial`, not
the lowest-square fallback.

A targeted cold reproduction of the reported outlier (game 75,
`0064e080c0a2868f:08181c7e3e5c3830`) at 3 seconds returned `Partial`, score
`1`, with 33,974,272 nodes. Its WDL pass completed and established a win.
This is a short diagnostic observation, not a repeat of the recorded warm
condition or a new timing gate.

Withdraw the quantified arbitrary-move claim, or measure and report WDL
failure specifically if retaining such a count. Keep the real distinction
between fallback on WDL failure and a proven-outcome move on score-pass
failure. The planned heuristic fallback remains useful, but this table
does not measure its incidence.

Location: `docs/prs/142.md`, “Step 3 applied to these numbers”, final
paragraph; `src/search.rs::search_inner`.

## Step 2 RED — `7e31d37`

### Summary

**Request changes** to the resource-limit contract and deadline coverage
before implementation. The fallback-quality assertions are useful, and
running a fallback after a timed solve fails is recorded in the amended
issue. The submitted design does not, however, leave node limits unchanged,
and its central fourfold time allowance is not tested.

### Major: an unlimited fallback after node exhaustion bypasses the cap

The design starts a new depth-8 search with no node limit after WDL fails
for either reason, then adds its nodes to the failed solve's. The new test
uses `NO_DEADLINE` and `max_nodes: 1` yet requires a completed depth-8
heuristic result. That explicitly requires substantial search beyond the
requested node limit; only the first solve is capped. Passing the
start-position node-limit tests does not preserve the endgame contract.

This affects deterministic node-budget matches and tuning callers, not just
the wall-clock game policy that the user relaxed. The claim that the node
limit is unchanged therefore cannot stand.

Preserve the node budget across all search work, or scope the emergency
unlimited fallback to the intended time-controlled game path and retain
bounded behavior for node-controlled callers. At this RED gate, specify
the policy explicitly and test it. An expired time limit (`time_ms: 0`,
without a node cap) can deterministically exercise the new timed fallback
without requiring a node-budget escape. Keep a separate endgame
node-cancellation guard; replacing its old assertion with an unlimited
search requirement hides the contract change rather than testing the
wall-clock feature. If a node-cap exemption is desired, that needs an
explicit resource-contract decision, not the “unchanged” description.

Locations: `docs/prs/142.md`, step 2 design and caller semantics;
`tests/search.rs::exact_timeout_plays_heuristic`, replacing
`wdl_cancellation_falls_back`.

### Major: test the fourfold allowance and hard cutoff

The issue explicitly requires a solve that finishes after T but before 4T
to return its solved move. The new deterministic test has no deadline, and
`endgame_bench` only rejects `Fallback`: a fallback implementation without
any deadline extension could satisfy both tests. The factor itself is a
core behavior, not something to leave solely to review.

Add the proposed release-only smoke test, or a controlled timing fixture,
covering completion beyond the nominal budget but inside the allowance.
Also exercise WDL expiry at the hard limit and check the specified
heuristic result/status. Retain the distinct WDL-completed/full-score-
interrupted case. Use the plan's wall-clock tolerances or controlled
callback cost rather than exact elapsed-time equality; no clock framework
is mandated. Ensure the allowance is measured from move entry, including
root setup, rather than resetting its origin after preparatory work.

Location: `docs/prs/142.md`, “What rests on review rather than a test”;
missing deadline tests in `tests/search.rs`.

### Verified tests and remaining design points

- Independently reproduced `exact_timeout_plays_heuristic` failing on
  `Fallback` versus `Partial`. Its reference score and child-value checks
  are appropriately independent of root tie-breaking and worth retaining
  with the corrected cancellation trigger.
- Independently ran the release-only `endgame_bench`. It reports eight
  WDL partials preserving their outcome and two old-style fallbacks, then
  fails the new zero-fallback assertion as intended. This is useful
  fallback coverage, but does not test the fourfold allowance.
- Formatting and targeted search-test clippy pass. No engine or golden
  implementation changed; no full suite or production measurement was run
  at this RED gate.
- The saturating multiplication/checked-add proposal handles unlimited
  controls sensibly. Preserve existing completed-solve values/node counts
  and account for fallback work honestly. Measure the post-timeout search
  cost in GREEN: the pilot's sample maxima are not a universal upper bound
  on depth-8 work, and this is additional latency after the exact deadline.
- Update `docs/PLAN.md`'s search/status/deadline contract in GREEN as well
  as the `SearchLimits` comment; the plan currently specifies the old
  exact-WDL failure behavior. `Partial` with a completed heuristic depth
  is otherwise a reasonable existing status representation.

### Recommendation

**Request changes** — revise the node-cap policy and its tests, and add
actual deadline-allowance coverage before GREEN. Candidate 18 and the step 1
measurements remain accepted; match registration is still a later gate.
