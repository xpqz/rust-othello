# Review of #163 — Clock gate

## Setup and pre-registration review of `6b821e0`

**Request changes before the pilot.** The frozen opening set and stated
decision rule match the design. The time analysis needs to enforce the
same pair selection as the score report and apply the inclusive 5%
threshold exactly.

### Major — Time analysis can use a different set of games than score analysis

At `tools/examples/clock_time.rs:48`, every journal row contributes to
the flag counts and maxima. At line 76, any two rows with the same pair
number count as a complete pair. The analyzer does not check the declared
pair range, require one record for each colour assignment, or compare
the saved load with the journal limit.

In a scratch journal with one accepted pair at 6.000 and one overloaded
pair at 6.001, the standalone score report retained one pair. The time
example counted both pairs, included the overloaded pair's flags, and
reported a time ratio of 25.475 instead of 1.000. In a second fixture,
two copies of `0:0` produced a complete time pair with no `0:1` record.
A journal that ends early can also produce a pilot C from fewer than the
registered 200 side-games.

Require the full expected set of pair IDs with games 0 and 1 once each,
and apply the same saved-load rule as the score report. For this gate,
refusing an incomplete or overloaded journal is sufficient. Compute
every statistic from that same validated set. At the pilot and gate
checkpoints, verify that the headers and counts match their registered
controls and that the pilot contains 50 pairs and the gate 400. Add
small synthetic checks for the duplicate, void and incomplete cases.

### Major — The inclusive 5% decision can fail at exact equality

At `tools/examples/clock_time.rs:93`, the condition compares two
separately rounded floating-point means. On an 800-game fixture with
candidate total 44,100,378 ms and baseline total 42,000,360 ms, the
candidate is exactly 5% higher. The example printed `ratio 1.0500 fails`.
Compare the integer totals with `20 * a <= 21 * b`. Accumulate the
per-pair totals in the same wide type, then convert to floating point
for display and the bootstrap interval. Pin the inclusive boundary with
a fixture.

### Run provenance

Make the registered execution explicitly clear
`OTHELLO_TOOLS_ELAPSED_MS` and `OTHELLO_TOOLS_LOAD` for both runs.
These are useful fixture overrides. An inherited value can otherwise
replace the measured elapsed times or the measured load without changing
the command written in the registration. Keep the pilot journal, log
and fixed C reviewable before the first gate game, as specified.

## Tuning registration review of `5ce1890`

**Request changes before the automated night run.** The pilot and four
tuning commands, fixed seeds, pair counts and half-point pick rule match
the approved amendment. The baseline-pilot approval remains in effect.
The overnight wrapper needs to enforce the inputs it registers.

### Major — The wrapper logs pins without enforcing them

At `docs/tuning/clock_night.sh:14`, the wrapper resolves a mutable build
directory and immediately runs the binary after printing its hash and the
checkout's HEAD. A rebuilt binary or a changed worktree can therefore
play games before any mismatch is noticed. On resume, a rebuild at the
same HEAD can append games to the original journal because its header
contains the engine commit and opening hash, with no binary hash. The
analyzer used to derive `C_t` is also launched without checking its pin.
If the target helper returns an empty path, the script looks in
`/release`.

Check the expected worktree commits, opening input and executable hashes
before the first launch and on every restart. Require a usable target
directory or stop with a clear diagnostic. Compare the hashes against the
registered values rather than merely logging the current values. Keep
the logged values for provenance.

### Major — The tuning pilot checkpoint needs to fail before candidate play

At `docs/tuning/clock_night.sh:24`, the pipeline returns the status of
`awk`, so an analyzer error can leave an empty `C_t` with a successful
assignment. The script writes that value to the log and attempts a
candidate command. Capture the analyzer's output only after a successful
exit, verify that it produced one positive integer `C_ms`, and append the
validated result before admitting any tuning game. The pilot match's
header and the analyzer's 50-pair validation should agree with the
registered command. Preserve the same `C_t` on resume.
