# Review: Issue 74 — Implement fixed-depth search agents (RED)

Verdict: **request changes**

## Verified

- #73 was merged with its nits applied (`board::squares`), and is closed.
  This branch is based on the current `main`. `cargo fmt --check` passes,
  and `tests/agents.rs` fails only with the expected E0432/E0425.
- The greedy fixture arithmetic is right *for the evaluator-based
  definition*. After a1 the child is `me = b2`, `opp = a1 b1 c1 c2`, giving
  −138 − 300 = −438. After a2 it is −(−258). Both moves are legal and they
  are the only two.
- The pass and terminal roots reuse the verified b2 / a1|c1 fixture.

## Required

1. **Greedy is the wrong player.** DESIGN.md defines the baseline as
   "Greedy (maximise discs after the move)". PLAN.md's ladder (greedy vs
   random, `phase2` vs greedy, and the ≥ 95% target vs greedy in Phase 8) is
   built on that disc-greedy player. The PR defines greedy as
   `max -evaluate(play(b, sq))`, which is a 1-ply search with the Phase 2
   evaluator, essentially `ab:1`. That makes "phase2 vs greedy" a
   depth-vs-depth comparison of the same evaluator, and the gates lose their
   meaning. Make greedy maximise `disc_count(me)` after the move (lowest
   square on ties).

   The fixture then needs a position where disc counts separate the moves.
   In the current board, a1 and a2 each flip one disc, so the result would
   be a tie broken by square order. Use, for example, a position where one
   legal move flips two discs and a lower-index move flips one, and assert
   that the higher-index two-flip move wins.

2. **The factory/reset lifecycle is missing.** The scope says "agent
   trait/factory or reset lifecycle (no opaque FnMut state leak across
   paired games)". The proposed design is a blanket `Agent` impl for
   `FnMut(Board) -> Option<u8>`, which is exactly opaque `FnMut` state. A
   harness holding an agent can't reset it, and the constructors return
   unnameable closure types that the tools crate can't store or rebuild per
   game. `fresh_state` only shows that calling `random_agent(42)` twice
   gives equal agents, which is true of any constructor, so it doesn't test
   a lifecycle. Pick one and test it:
   - `trait Agent { fn choose(&mut self, b: Board) -> Option<u8>; fn reset(&mut self); }`
     Test: choose a sequence, `reset()`, then choose the same sequence again.
   - or a factory, `type Factory = Box<dyn Fn() -> Box<dyn Agent>>`. Test:
     two agents from one factory produce identical sequences even after the
     first has been used.

   #64 also deferred the "per-game agent factory/reset helper" in
   `tests/common` to this issue. `agent_game` is a runner, not that helper.
   Deliver whichever one item 2 settles on.

## Minor

3. **Pin the search agent's wiring.** `search_legal` only checks legality.
   Add `search_agent(cfg, {max_depth: 2}).choose(b) ==
   Some(search(b, 2, &cfg).best)` on a couple of positions, so the agent is
   shown to use `limits.max_depth` and to return `best`.

4. **`game_finishes` and passes.** Random-vs-random from the start rarely
   passes, so the runner's pass branch may never run. Either start
   `agent_game` from the b2 / a1|c1 pass fixture (if the runner takes a start
   board), or assert across several seeds that at least one game passed.

# Re-review (round 2, RED fixes + GREEN)

Verdict: **approve**

The review responses and GREEN landed together. AGENTS.md allows this:
step 4 updates RED, then step 5 implements. So I reviewed both.

## Verified

- Item 1: greedy maximises the mover's discs after the move, and
  `max_by_key((count, Reverse(s)))` breaks ties toward the lowest square. In
  the new fixture (`me = c1 g1`, `opp = b1 d1 f1`), a1 flips one disc and e1
  flips two, and these are the only legal moves, so e1 wins on disc count,
  not on square order. The start position still picks d3.
- Item 2: there is a reset lifecycle with named agent types.
  `RandomAgent::reset` reseeds, and `reset_replays` checks that an 8-move
  sequence replays exactly. Stateless agents use the default no-op `reset`.
- Item 3: `search_legal` pins `choose == Some(search(b, 2, &cfg).best)`.
- Item 4: `agent_game` takes a start board, and the pass fixture start goes
  through the pass branch on its first ply. The turn bit toggles on passes as
  well as placements, matching PLAN.md's absolute side-to-move rule.
- `./scripts/check.sh` passes, `cargo test --release` passes, and
  `agents.rs` is 50 lines against PLAN.md's 50-line budget. The engine is 334
  lines.

## Nits (non-blocking)

- `RandomAgent::choose` advances the RNG even when there are no moves, using
  `.max(1)` to dodge the division. It works, and `reset` still replays, but
  a `None` turn shouldn't consume randomness. When the tools harness logs
  agent RNG streams, the draws won't line up with moves. Return `None` before
  drawing.
- `agents.rs` is exactly at its budget. #83 and #84 (time limits,
  equal-node naming) touch agents. Plan those additions as replacements
  rather than additions, or agree a reallocation from another file's slack
  first.
- `agent_game` relies on `play`'s debug assertion to reject an illegal
  square. That is fine for tests. The tools harness must reject illegal
  squares explicitly in release, as PLAN.md requires.
