# Review: Issue 78 — Pair-bootstrap intervals, Elo, and reporting (RED)

Verdict: **request changes**

## Verified

- #77 was merged and closed. This branch is based on the current `main`.
  `cargo fmt --check` passes for tools, and `tools/tests/stats.rs` fails only
  with the expected E0432.
- The Elo anchors are right: 0.5 → 0, and 0.75 → 400·log10 3 ≈ 190.85.
- The Hoeffding fallback is right for a 95% two-sided bound:
  `sqrt(ln(2/0.05) / 2n) = sqrt(ln 40 / 2n)`. For the `elo_range` fixture
  (n = 10, zero variance) that gives about ±0.43, so the bounds are about
  [0.07, 0.93], finite, and the test's `unwrap` holds. For `report_counts`
  (n = 3) the half-width is about 0.78, which clips to [0, 1], so Elo is
  `None` as expected.
- The degeneracy cases match PLAN.md item 10: zero pairs are insufficient,
  one pair is uninformative, and all-equal or zero-variance sets fall back
  without a strength claim.

## Required

1. **W/D/L can't be derived from pair scores.** `report` takes pair scores
   and reports "pair-level W/D/L", and the fixture uses only 1.0, 0.0, and
   0.5. Real pair scores also take 0.75 and 0.25, and a 0.5 pair is either
   W+L or D+D. So W/D/L is either undefined or ambiguous. The scope means game
   W/D/L ("Report pairs, games, W/D/L"). Either:
   - have `report` take per-game points per pair (for example
     `&[(f64, f64)]`), and derive the pair scores and true game W/D/L from
     them (preferred, because #81's harness has the game results anyway), or
   - define pair-level categories explicitly, covering 0.75 and 0.25.

   Add a fixture with 0.75 and 0.25 pairs in either case.

2. **The statistics belong in `stats.rs`, not `harness.rs`.** PLAN.md's tools
   layout has `stats.rs` for "pair bootstrap, degeneracy fallback, Elo", with
   its own budget (`stats.rs <= 120`, `harness.rs <= 180`). The issue's Files
   line says `harness.rs`, but following it would put both budgets in one
   file and drift from the plan. Import from `othello_tools::stats`, and
   update #78's Files in skis.

## Minor

3. **Pin the interval values.** `bootstrap_deterministic` checks that the
   same seed gives the same result and that the interval is ordered. It
   doesn't check that the bootstrap is a percentile bootstrap of the mean.
   Pin the exact `low` and `high` for the fixed seed, or at least check the
   interval is narrower than the Hoeffding bound for those 12 pairs. Then a
   change to the resampling or percentile rule is visible. Also state the
   percentile index rule (for example the 2.5% and 97.5% order statistics of
   sorted resample means).

4. **Default resamples.** The scope fixes `resamples = 10_000`. The tests pass
   1,000, which is fine for speed, but `report` should be called with the
   10,000 default by #81. Record that in the notes, or give `report` the
   default.

# Re-review (round 3, GREEN)

Verdict: **approve**

## Verified

- The tests are unchanged since the RED approval, plus `report_default`,
  which takes the round-2 nit. `./scripts/check.sh` passes, and the release
  tools suite passes. Tools is 206 of 600, and `stats.rs` is 115 of 120.
- `bootstrap_ci` handles every case in PLAN.md item 10. Zero pairs are
  `Insufficient`. Fewer than 10 pairs, zero variance, or zero resamples fall
  back to Hoeffding (`sqrt(ln 40 / 2n)`, clipped). Otherwise it does a
  percentile bootstrap from the engine `Rng` with the stated
  `round((len − 1)·p)` rule. `elo_range` exists only for bounds strictly
  inside (0, 1), so infinity is never reported as an endpoint.
- `report` derives pair means from per-game points, counts game W/D/L, and
  defaults to 10,000 resamples with seed 0.

## Nits (non-blocking)

- **`stats.rs` is 5 lines from its budget.** `Interval`'s three variants
  force the `bounds` and `mean` accessors to repeat the same match.
  `Option<Interval>` with
  `struct Interval { mean, low, high, informative: bool }` removes both
  accessors and `Insufficient` (about 15–20 lines), and leaves room if #81
  adds Wilson diagnostics.
- `report(&[])` sets `mean = NaN`, and with `PartialEq` derived, two empty
  reports compare unequal. That is harmless today. With the `Option`
  refactor above, `mean` can be `Option<f64>` too.
